# SDF-SEP: ソフトウェア開発の社会・倫理・専門職

出典：[CS2023 印字 p.233](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。すべて CS Core。固定されたゲーム内の操作は、実際の法的判断や専門職としての実践能力を証明しない。

| トピック | 対応と不足 |
|---|---|
| 1 プログラム開発者の知的財産権 | 依頼269で２種類の架空の利用条件を比較。権利の発生・帰属や実法域の扱いは未対応 |
| 2 剽窃と学術的誠実性 | 依頼270で出典と貢献の表示を選ぶ固定例。学術的誠実性や実際の引用判断の全体は未対応 |
| 3 開発したコードに関する責任・法的責任 | 依頼360で警報の不具合に関する停止、検査、報告、再検証の固定例。一般の法的責任は未対応 |
| 4 プログラマーの基本的な職業倫理 | 依頼360で不確実性と確認結果の区別、担当者との協力を扱う。体系的な職業倫理は未対応 |

| 例示学習成果 | 対応と不足 |
|---|---|
| 1 プログラムに関する知的財産の問題 | 依頼269の限定した利用条件の比較。一般的な説明は未評価 |
| 2 他者のコードを使用できる場合と適切な明示 | 依頼269・270は架空の条件と出典表示。実際のコードや法的判断は未評価 |
| 3 チームでの成果物を含む開発者の責任 | 依頼360で担当者への報告と有限の検査を操作。実際のチーム運営や責任の説明は未評価 |
| 4 プログラマーに適用される行動規範 | 依頼360で ACM の危害回避、誠実さ、リスク評価の考え方を参考にする。規範全体の説明は未対応 |

依頼360の架空の約束は水位３以上で警報。旧規則は水位３で警報を出さず、新規則は２・３・４の３例で約束と一致する。未確認の懸念は早期に担当者へ伝えられ、確認後の結果も改めて報告する。３例の検査は装置全体の安全性を保証しない。[ACM の倫理綱領](https://www.acm.org/binaries/content/assets/about/acm-code-of-ethics-booklet.pdf) の危害回避、誠実さ、リスクの評価と適切な相手への報告を参考にした。
