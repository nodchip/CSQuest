# 工房から旅立つ冒険：方針

2026-11-06 の対話で選んだ最初の開発区切り。これは設計であり、完成や公開を意味しない。既存の全体設計 `adventure-redesign.md` と異なる範囲・公開方針はこの文書が今回の区切りで優先する。大学水準の CS2023 全分野という長期目標は変更しない。

## 要件

| ID | 要件 | 状態 |
| --- | --- | --- |
| R0 | 人と精霊を助けて世界を巡る冒険を通して、大学水準の CS 全分野を学べる。 | 長期目標 |
| R1 | 一つの冒険として完成・公開後に遊び、その感想を次の改善に反映できる。 | 必須 |
| R2 | 冒険の楽しさを保ち、異なる少数の CS の考え方を依頼で扱う。 | 必須 |
| R3 | 次に作る範囲と公開の区切りが分かる。 | 必須 |
| R4 | 工房周辺で冒険し、別の地域に移動し、その地域の最初の依頼を達成できる。 | 必須 |
| R5 | 旅先で工房との雰囲気の違いを感じ、新しい人物と CS の考え方に出会う。 | 必須 |
| R6 | 最初の依頼後、選んだ２つの依頼を達成すると旅立て、残った依頼にも後から戻れる。 | 必須 |
| R7 | 最初の依頼後に工房周辺で選べる依頼が最低３つあり、出会いや出来事から旅立つ理由と世界全体の目的の手がかりが生まれる。 | 必須 |
| R8 | GitHub Pages の別ページに新しい冒険を公開し、既存トップページを維持する。 | 必須 |

## S: 工房から旅先へ続く体験版

| 部品 | 仕組み | 未確定 |
| --- | --- | --- |
| S1 | 既存体験版のタイトル、世界紹介、人物紹介、最初の依頼を出発点にする。人物の姿や顔、読みやすさ、会話と依頼のつながりを維持する。 | |
| S2 | 最初の依頼の後に、森の薬草を含む少なくとも３件の工房周辺の依頼を少数ずつ選べる。各依頼に必要な情報・目標・ヒントをその場で提示し、操作によって解く。 | 具体的な依頼、配置、CS 内容 |
| S3 | 異なる２件の初回達成で旅立ちを可能にし、ユーザーが移動を選ぶ。未達成の依頼に後から戻れる。工房の出来事から旅の動機を生む。 | 移動の具体表現、旅立ちの出来事 |
| S4 | 旅先の風景、人物、最初の依頼を作る。暮らしを助ける旅の中で、世界全体の目的への手がかりを示す。 | 地域、人物、依頼、長期目的 |
| S5 | 独立した記録で進行と設定を保持し、達成時の中央表示、記録の確認、途中再開、保存失敗時の案内を設ける。 | 古い体験版記録の移行方法 |
| S6 | 少数の異なる CS の考え方を正確に扱い、対応根拠を記録する。コードや数式や文章を入力させる演習は設けない。 | CS2023 上の対応項目と検証範囲 |
| S7 | 完成した冒険を検証して別ページにまとめて公開し、公開先でも確認する。面白さは公開後にプレイヤーが評価する。 | 公開時の既存成果物と競合の解決 |
