# 港の分担と集約：範囲と未完了

[CS2023 印字 225 ページ（PDF 225 ページ目）PDC-Algorithms](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の CS Core 1a はデータ並列と map/reduce の例を挙げる。[Guy Blelloch の並列アルゴリズム解説](https://www.cs.cmu.edu/~guyb/papers/Ble93.pdf)は結合的な演算を使う並列の集約・累積の考え方を扱う。

旧教材の `parallel-scan.js` 等の存在だけでは現行冒険の到達を示さない。現行の港の時間比較は人数と調整時間、共同作業は共有更新や待ち合わせを扱う。今回の３依頼は、４枚の整数札をそれぞれ２倍にする操作、二組の小計と最終合計、二つを組み合わせた固定手順を扱う。同じ値の別札も別々に数える。発展例は全変換完了を待ってから小計を求めるが、すべての並列アルゴリズムがその待機を必要とするという主張ではない。

整数の和の固定例のみであり、演算一般・浮動小数点に結合律を一般化しない。実際の同時実行、MapReduce フレームワーク、任意の入力・故障・分散処理、性能測定、自由なコードや設計能力は検証しない。該当する原典項目と学習成果は部分対応である。

`harbor-parallel-map` と `harbor-parallel-reduce` の２件を終えると `harbor-parallel-pipeline` が開く。港の依頼分類から選び、地図の全達成判定にも含まれる。

実装担当とは別の `review_candidate` が原典、[MapReduce の原論文](https://research.google.com/archive/mapreduce-osdi04.pdf)、固定例の期待値、別々の札と重複操作、依存関係、説明、分類と保存をコード上で確認した。各値は操作に応じて自動生成され、空入力やキー別の一般的なグループ化は扱わない。実言語やフレームワークでの実装や性能を確認したものではない。レビュー担当自身はブラウザを操作していない。

`tests/endgame-parallel-map.test.js` は異なる操作順、依存関係、重複操作の拒否、０と重複値、保存履歴からの再開を検証する。`tests/harbor-quest-groups.test.js` は分類と開放を確認する。`scripts/endgame-parallel-map.playwright.js` は集いと４地域などの達成を用意した検証用記録から、213・390・1200 px 幅で分類からの到達、キーボードによる依頼と回答、誤答の案内、途中復元、段階開放、３依頼の達成と達成後の再開を確認した。新規開始からこの依頼群までの通し操作、実際のスクリーンリーダー音声、利用者による面白さの評価は未確認。
