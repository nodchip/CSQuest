# 項目別評価：NC-Applications の要求分析

2026-11-05 に [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.199、依頼668の実装と試験、公開版の操作を照合した。対象はトピック３と例示学習成果２の２行で、他の行はこの評価に含めない。

## トピック３・例示学習成果２ — いずれも部分対応

原典はネットワークアプリの遅延・帯域・損失耐性などの多様な要求と、具体的なアプリの要求分析を扱う。依頼668は２つの固定された用途について、欠損の許容と期限に対する選択を求める。別の４条件では荷物の大きさ、伝送速度、伝播時間と期限を比べる。一般のアプリの要求を自由に導き出す課題ではないため、両行とも部分対応とする。

TCP の順序付きバイト列と UDP の保証の違いは [RFC 9293 §2.2](https://www.rfc-editor.org/rfc/rfc9293.html#section-2.2) と [RFC 768](https://www.rfc-editor.org/rfc/rfc768.html) に照らした。依頼はメッセージの区切りをアプリ側が扱うと明示している。１本の通信路について全体の送り出し時間と伝播時間を足す計算は模型の仮定の下で成立する。小・大・同着・期限超過の結果はそれぞれ近道 3／広道 4.5、13／7、5／5、13／7刻で、各期限と照合した。

`tests/transport-needs.test.js` と `tests/link-choice.test.js` の７件が成功。390px 幅の公開版で両方の観察、誤答、修正後の再読込と依頼の再選択による復元、４条件、振り返りと達成を確認し、ページ全体の横あふれはなかった。

この評価は選択操作と固定された到着・損失の例に限る。実際の通信、混雑、実測、一般の要求分析、実装能力、自由な説明は評価していない。再送時刻や通信の成功・期限も保証しない。
