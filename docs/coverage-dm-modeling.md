## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | 関係モデルの構成要素を説明 | 部分 | 依頼13・67・101で行・結合・キーの固定例。構成要素の体系的・自由な説明は未評価。 |
| 2 | CS Core | １対１・１対多・多対多を関係モデルで表す | 部分 | 依頼101で多対多の保存方式、102で１対１と１対多の一意性を選択。一般の構築や完全参加の保証は未評価。 |
| 3 | KA Core | ER など関係以外のモデルの構成要素を説明 | 部分 | 依頼101で実体・関係・属性を選択。一般の ER 表記や自由な説明は未評価。 |
| 4 | KA Core | 与えられた環境を概念モデルで表す | 部分 | 依頼101で指定された要件から実体・関係・属性・参加条件を選択。自由な概念モデルの構築は未評価。 |
| 5 | KA Core | 与えられた環境を文書型またはキー値型で表す | 部分 | 依頼189で既に与えられた記録を２種類の箱で検索・更新。要件からモデルを設計する操作は未評価。 |

依頼101・102の制約と３方式は [対応記録](dm-modeling.md) にある通り SQLite と照合した。依頼189の２方式の更新前後と途中記録は `tests/nosql-models.test.js`、表現形式の選択は `tests/data-formats.test.js` が対象。これらの固定例は、原典の各項目全体や実データモデルの自由な設計を証明しない。

依頼101の追加例は、冒険者と依頼の双方について０件を許す多対多の参加と、参加の組に付く受付時刻を選ぶ。[Virginia Tech の ER 関係](https://opendsa.cs.vt.edu/ODSA/Books/Database/html/ERDRelationships.html)を参照。１組の重複は許さず、同じ組での複数回の参加、図記法や自由なモデル作成は扱わない。

依頼189の札の規則では、村と束数の必須・束数の非負整数・備考の必須を個別に切り替える。村と備考は存在すれば文字という固定条件。必須の有無は型の検査とは別であり、備考なしと数値の備考を区別する。[JSON Schema のオブジェクト](https://json-schema.org/understanding-json-schema/reference/object)と[数値](https://json-schema.org/understanding-json-schema/reference/numeric)を参照。これは限られた規則の模型であり、実際の JSON やスキーマの記述・一般の処理は扱わない。

依頼1074は [PostgreSQL の実体化ビュー](https://www.postgresql.org/docs/current/rules-materializedviews.html)を参考に、固定の取引と価格を同時刻または時刻以前の最新価格で結び、半開区間 [0,3)・[3,6) の数量と金額を集計する。遅れた取引の追加前後と保存済み集計の更新を比較する。空の区間は表示上０、読取数は価格の探索・保存・更新費用を含まない模型上の行数。`node scripts/check-timed-ledger.mjs` は SQLite 3.50.4 の相関副問合せと保存済み表で集計を照合する。実体化ビューの実行、差分更新、実測性能や一般の時系列処理は評価しない。

依頼1168は [GraphQL の照会](https://graphql.org/learn/queries/)と[検証](https://www.graphql.org/learn/validation/)を参考に、冒険者と所属先の固定型の項目を選び、入れ子の結果や所属なしの null を比較する。`tests/graphql-selection.test.js` は２人・32種類の項目集合の形と検査、保存・達成を検査。実クエリの記述、通信、一般のスキーマやエラー・権限は未評価。

依頼1170は固定の緯度経度を球面上の領域として扱い、正距円筒・球面メルカトルの座標と見え方を比較する。出典と検査、模型の限界は [GIT-Visualization](coverage-git-visualization.md) を参照。

依頼1228は [Microsoft の参照の説明](https://support.microsoft.com/en-us/excel/switch-between-relative-absolute-and-mixed-references)を参考に、２行の乗算で相対・絶対参照の４設定と２種類の値の変更を比較する。固定された下方向コピーと、コピー済み式の参照先を変更したときの自動再計算を模型化する。[Microsoft の再計算の説明](https://support.microsoft.com/en-us/excel/change-formula-recalculation-iteration-or-precision-in-excel)を参照。既存の途中記録はコピー済み式なしとして復元する。`tests/sheet-lantern.test.js` で全16入力・設定、自動再計算、旧記録の復元と達成を検査し、配信用ビルドで４設定・再開・値の変更と320・390・1280px幅、キーボード操作を確認。一般の関数、混合参照、循環参照、実際の表計算ファイルは未評価。

依頼192は有向ラベル付きの固定グラフで「集める」「使う」の順に２辺を操作し、２症状のすべての経路と重複を除いた薬師を選ぶ。原典 DM-Modeling のグラフデータとリンク走査に対応する固定例として照合し、既存テストと配信用画面で両症状の達成を確認した。一般の経路長・グラフ問合せ言語や実 DB は未評価。
