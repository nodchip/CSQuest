# SPD-Game の対応

原典: CS2023 pp.306–308。依頼94は１次元の点を位置０から10へ動かし、閉区間 [4,6] の壁について、更新後の位置のみと移動区間全体の交差を比べる。速度10では位置だけの判定が壁を見落とし、区間判定は位置４で検出する。速度２なら位置だけの判定でも４に触れる。端の接触を含み、静止壁と点の模型である。

| 3 | ゲーム開発言語、シェーダー、API、道具。870でフラグメント色計算を調整、871で WebGL による固定立方体を描画。実際の言語記述、他の API や道具は未評価 |

例示学習成果 2 は869の描画後半、6 は871の固定立方体、7 は870の色計算の調整、9 は94の接触判定と800の区画による衝突候補の絞込みの固定例に留まり、実装や実時間の最適化は評価しない。他の成果は[項目別台帳](coverage-spd-game.md)を参照。実ゲームの形状、反射や移動体同士の衝突は扱わない。

依頼799は描画の頻度と固定時間刻みの更新を比較する固定例。実時間・処理落ちやゲームループの実装は評価しない。[項目別台帳](coverage-spd-game.md)を参照。

依頼869は２画素をそれぞれ１タイルとみなし、金（両画素・深さ９）、青（両画素・深さ４）、赤（左のみ・深さ１）を遠い順または近い順に不透明で描く。早い深さ判定を仮定すると深さ比較は５回、色計算は遠い順５回・近い順２回。即時の模型では深さを通過するごとに外へ色を書き、タイルの模型では一時棚に保持して最後に各画素を１回ずつ外へ書く。完成色は左が赤、右が青。[Apple のタイルベース描画の説明](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering)を参考にした単純な模型であり、実 GPU では隠面除去、キャッシュ、順序や保存方式が異なる。頂点処理、タイルへの分配、深さの通信、半透明、帯域と実時間は評価しない。

依頼870は固定の光０・0.5・１に、周囲の明るさ０・0.2、光の倍率0.4・0.8・１、０〜１の制限を組み合わせる。周囲0.2・倍率0.8では出力0.2・0.6・１、倍率１では制限前0.2・0.7・1.2、制限後0.2・0.7・１、倍率0.4では0.2・0.4・0.6。全12設定と３要求を比較し、同じ出力になる設定を受け入れる。画面表示は固定 RGB への係数乗算と成分ごとの丸め・範囲制限で、ガンマ変換を含まない。フラグメント処理と [WebGL のシェーダー](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Adding_2D_content_to_a_WebGL_context)、[DirectX の HLSL](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl)に言及する。固定値の模型であり、実シェーダーの記述や API、頂点補間、光源・法線計算、色空間や実性能は評価しない。

依頼871は各面４頂点・２三角形、計24頂点・36索引の固定立方体を独自のシェーダーとバッファで WebGL に描く。一面は先頭６索引、立方体は36索引を `drawElements` で描画し、０・45度の回転と深度判定の有効・無効を選ぶ。手前の面を先に、奥を後に描く固定順序のため、深度無効では奥が上書きする。道具の選択は模型であり、実際の WebGL 準備・転送・描画は描画ボタンを押したときに行う。[MDN の立体描画](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Creating_3D_objects_using_WebGL)を参照。WebGL が利用できない場合は失敗を表示し、達成として記録しない。固定の正投影風の例であり、自由な API・モデル・シェーダー記述、一般の行列や透過、実性能は評価しない。

依頼872は４人組の２組に太陽・月の各４仕事を配置し、組内で異なる分岐を順に実行する模型。混在する２組は合計４命令・待機８枠、種類ごとの２組は２命令・待機０枠だが、並べ替え・通信や実行時間は数えない。[NVIDIA の SIMT 説明](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html)を参照。実際の CUDA のワープは32スレッドで、ハードウェア実装や独立スレッドの扱いもこの固定模型に限定されない。
