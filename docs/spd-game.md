# SPD-Game の対応

原典: CS2023 pp.306–308。依頼94は１次元の点を位置０から10へ動かし、閉区間 [4,6] の壁について、更新後の位置のみと移動区間全体の交差を比べる。速度10では位置だけの判定が壁を見落とし、区間判定は位置４で検出する。速度２なら位置だけの判定でも４に触れる。端の接触を含み、静止壁と点の模型である。

| KA Core トピック | 内容と状態 |
|---:|---|
| 1 | ゲームプラットフォームの歴史、種類、制約、入出力と競技環境。未対応 |
| 2 | 実時間シミュレーションと描画。依頼94で衝突検出、799で描画と固定時間更新、800で描画候補、869で深さ判定と即時・タイル内保存の固定模型。CPU/GPU、実描画の全工程や他のアルゴリズムは未対応 |
| 3 | ゲーム開発言語、シェーダー、API、道具。未対応 |
| 4 | エンジンと開発手法。未対応 |
| 5 | ゲームデザイン、ジャンル、利用者、応用。未対応 |

例示学習成果 2 は869の描画後半の模型、9 は接触判定を比較する固定例に留まり、実装や最適化は評価しない。他の成果は[項目別台帳](coverage-spd-game.md)を参照。実ゲームの形状、反射や移動体同士の衝突は扱わない。

依頼799は描画の頻度と固定時間刻みの更新を比較する固定例。実時間・処理落ちやゲームループの実装は評価しない。[項目別台帳](coverage-spd-game.md)を参照。

依頼869は２画素をそれぞれ１タイルとみなし、金（両画素・深さ９）、青（両画素・深さ４）、赤（左のみ・深さ１）を遠い順または近い順に不透明で描く。早い深さ判定を仮定すると深さ比較は５回、色計算は遠い順５回・近い順２回。即時の模型では深さを通過するごとに外へ色を書き、タイルの模型では一時棚に保持して最後に各画素を１回ずつ外へ書く。完成色は左が赤、右が青。[Apple のタイルベース描画の説明](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering)を参考にした単純な模型であり、実 GPU では隠面除去、キャッシュ、順序や保存方式が異なる。頂点処理、タイルへの分配、深さの通信、半透明、帯域と実時間は評価しない。
