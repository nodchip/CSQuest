# SEC-SEP: セキュリティと社会・倫理

出典：[CS2023 印字 pp.258–259](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。固定された模型は、実際のインシデント調査、法令適合やプライバシー保護の実践を保証しない。

| 区分・トピック | 対応と不足 |
|---|---|
| CS Core 1 プライバシーの原則と実践 | 依頼194・352で架空の情報の収集範囲を比較。一般の原則と実装は未対応 |
| CS Core 2 セキュリティ・プライバシーの破綻が社会に与える影響 | 依頼362で架空の窓口停止と申請予定件数を比較。実際の人・社会への影響は未評価 |
| CS Core 3 セキュリティ・プライバシーの法令・規制 | 1113・1191で GDPR の一部原則と適用を仮定した設計を比較。適用判断や他法域は未評価 |
| CS Core 4 安全な設計・プライバシー維持の職業倫理、倫理的なハッキング | 依頼360で不具合の確認と報告を操作。倫理的な調査や実際の設計は未対応 |
| KA Core 5 設計段階からのセキュリティ | 依頼328で固定された脅威と対策を比較。一般の設計は未対応 |
| KA Core 6 設計段階からのプライバシー、プライバシー工学 | 依頼194・352で架空の収集範囲を比較。一般の設計や実装は未対応 |
| KA Core 7 悪意ある AI・機械学習と偽情報等の安全・プライバシー | 1196で来歴・別経路・文脈を架空の声と画像で比較。実検出器や一般の影響は未評価 |
| KA Core 8 IoT 等の新技術の安全・プライバシーへの社会的影響 | 依頼352で室内情報収集の固定例。IoT 全般や実社会への影響は未対応 |

| 区分・例示学習成果 | 対応と不足 |
|---|---|
| CS Core 1 特定のシステムのセキュリティ破綻の影響を計算 | 依頼362で停止した２窓口の申請予定12＋８＝20件を集計。原因は未確認で、被害人数や実社会の損失ではない |
| CS Core 2 セキュリティ法に適合するシステムを構築 | 未対応 |
| CS Core 3 プライバシー規制を適用してシステムを設計 | 1113で目的別の収集項目を操作。実システムや法令全体の適合は未評価 |
| KA Core 4 法令に適合しないシステムの法的影響を評価 | 未対応 |
| KA Core 5 利用者のプライバシーへの害を避けるシステムを構築 | 依頼194・352は選択式の固定例。実システムの構築は未評価 |

依頼362では三窓口のうち北・東の利用が停止し、南は利用できると定める。影響の20件はあくまで停止窓口の申請予定数であり、原因や情報流出の有無は不明。紙の代替窓口の可用性もこの架空の例での前提である。[NIST のインシデント対応](https://csrc.nist.gov/projects/incident-response) は準備・対応・復旧を含むリスク管理の重要性を説明するが、この模型は実務手順や法的助言ではない。

依頼1319は FDA の対象医療機器に関する一部要件を参考に、架空の部品一覧・更新・継続対応を操作する。実機の安全性や法令適合は検証しない。出典と限界は [SEC-SEP 項目別対応表](coverage-sec-sep.md) を参照。

依頼1320では1319の架空の部品について、版の異なる灯台を巡り、確認・調整・更新・点検を操作する。実際の機器運用・安全性・法令適合の評価ではない。詳細は [SEC-SEP 項目別対応表](coverage-sec-sep.md) を参照。
