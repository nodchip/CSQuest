# NC-Reliability の対応状況

出典: [CS2023, Networking and Communication, NC-Reliability](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 199。原典を要約した作業用一覧。以下は KA Core であり、試作の存在は学習成果の達成を示さない。

## トピック

| 番号 | 要約 | 現状 |
|---:|---|---|
| 1 | 信頼性を保証しない配送 | 試作：データまたは応答が途中で失われる状況。UDP の機能や動作全体は扱わない |
| 2 | 消失・重複・順序の乱れを避ける信頼性の原則 | 依頼10・62で消失と重複排除、422で欠落後に届いた順序外の手紙を破棄する固定例。一般的な順序の乱れや破損は未対応 |
| 3 | 再送や誤り訂正 | 試作：時間切れ後に再送。誤り訂正は未対応 |
| 4 | stop-and-wait やウィンドウに基づくフロー制御 | 依頼10で１件ずつ、422で未確認を最大３件とする Go-Back-N の固定例。798で受信箱の空きに合わせる固定模型。実際の TCP の窓や一般のフロー制御は未対応 |
| 5 | 輻輳制御 | 依頼423で二つの送信量と固定容量の橋を使い、加法増加・乗法減少の固定模型を操作。実ネットワークや他の制御は未対応 |
| 6 | TCP と性能、各種の輻輳制御 | 依頼424で通常の３段階の接続確立を操作。実際の性能、損失回復と各種輻輳制御は未対応 |

## 学習成果

| 番号 | 要約 | 現状と限界 |
|---:|---|---|
| 1 | 信頼性のある配送プロトコルの動作を説明する | 固定シナリオでデータ・応答の消失、再送、重複排除を試作。自由記述の説明は直接評価しない |
| 2 | 信頼性ある配送の性能に影響する要因を挙げる | 依頼423で共有容量を超える場合の混雑と送信量の調整を扱う。遅延、実測や一般的な分析は未対応 |
| 3 | TCP の信頼性に関する設計課題を説明する | 依頼424で接続開始時の双方の番号と状態を扱う。TCP の損失回復や一般的な設計・自由な説明は未対応 |
| 4 | 単純な信頼性プロトコルを設計・実装する | 既定の手順を操作する試作のみ。プロトコルの設計や実装は未対応 |

この題材はデータ１件目の消失、２件目の応答の消失を意図的に発生させる固定シナリオ。遅延、破損、複数の未確認データや現実のネットワークを包括的に再現していない。

依頼422では３通を送った後に確認を受け、２番の消失時は順序外の３番を破棄し、時間切れ後に２・３番を再送する。累積確認は指定番号までの連続した受信を表す。[Cornell の Go-Back-N 講義資料](https://www.cs.cornell.edu/courses/cs519/2003sp/slides/06_udp_reliable.pdf)を参照。返事の送達順・時間切れ・再送成功は固定し、一般の損失、動的な窓や TCP 全体は扱わない。

依頼423は共有容量６の橋を２人が使い、超過したら両者に同時に混雑が通知される模型。通常は各窓を１増加し、通知後は半分にする（端数切捨て・最小１）。[RFC 2914](https://www.rfc-editor.org/rfc/rfc2914) の AIMD の考え方を参照するが、実際の TCP のスロースタート・受信窓・個別の損失や時間挙動は再現しない。

依頼424は [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293) の通常の接続確立を参考に、本文・損失なしの３通と２組の初期番号を操作する。SYN は番号を１つ使い、ACK は次に期待する番号を示す。再送、同時開始、切断や暗号化・本人確認は扱わない。

依頼649では道を巡って塔に到達し、知らせ０の確認応答が失われた後に同じ番号を再送し、重複を配送せず応答を返してから知らせ１を送る。消失・再送の順序は固定した一例で、一般の遅延、再順序、破損、TCP 全体は再現しない。[Cornell: Alternating Bit Protocol](https://harmony.cs.cornell.edu/book.pdf)。

依頼798は受信側の空きを待つ方法と無視する方法を比較する固定例。実際の TCP の窓更新・ゼロウィンドウ探査・輻輳制御は再現しない。[項目別台帳](coverage-nc-reliability.md)を参照。
