# NC-Emerging：新しいネットワークの話題

出典：[CS2023 NC-Emerging](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.201。原典の要約と限定的な対応であり、固定模型の達成は実際のネットワーク設計・運用や自由な説明能力を証明しない。

| トピック | 区分 | 内容と対応状況 |
|---:|---|---|
| 1 | KA Core | ミドルボックス：AI・意図に基づくネットワーク、フィルタ、深いパケット検査、負荷分散、NAT、CDN など。依頼279で通信フィルタ、280で侵入検知、320で NAT、321で負荷分散、322で CDN の写しと鮮度の固定模型。他の方式と一般的な配置・運用は未対応 |
| 2 | KA Core | ネットワーク仮想化、SDN、データセンターネットワーク。依頼319で制御側による規則設定と中継器による転送の固定模型。仮想化と実際の制御器・運用は未対応 |
| 3 | KA Core | 量子ネットワーク、テレポーテーション、安全性、量子インターネット。依頼678は２地点間の量子テレポーテーションと古典通信の固定例。量子ネットワーク全般、安全性、実装は未対応 |
| 4 | KA Core | 衛星、ミリ波、可視光。1161で衛星の伝搬距離と遮蔽・反射の固定例を比較。実機や一般の通信設計は未評価 |

| 例示学習成果 | 区分 | 対応状況 |
|---:|---|---|
| 1 | KA Core | ミドルボックスの進歩の価値を説明。依頼279・280・320〜322は通信フィルタ、侵入検知、NAT、負荷分散と CDN の固定模型。一般的な説明は未対応 |
| 2 | KA Core | SDN の重要性を説明。依頼319で集中した制御側による２中継器の規則設定と転送を比較。一般的な説明と実ネットワークの設計は未対応 |
| 3 | KA Core | 量子ネットワークの付加価値を説明。依頼678は量子状態の転送の固定例。ネットワークの付加価値全般と自由な説明は未対応 |

依頼319では１つの宛先、出発・A・B・村の４地点、既知のリンク状態と単一の指揮塔を仮定する。壊れた道で出発の次の塔を変更する例と、B の規則不足を補うか、通れる A へ切り替える例を操作する。転送は設定済みの規則で行う。実際の SDN には複数の制御器、異なる制御・転送方式、配布順や障害の問題があり、この模型はそれらや実装を保証しない。参考：[ONF: SDN Architecture](https://opennetworking.org/wp-content/uploads/2013/02/TR_SDN_ARCH_1.0_06062014.pdf)。

依頼320は２つの内側アドレスが一つの外側アドレスを共有する固定例で、送信元ポートの割当てと返事の対応付けを操作する。実際の接続管理、相手による制限、期限やセキュリティは未対応。参考：[RFC 7857: Updates to NAT Behavioral Requirements](https://www.rfc-editor.org/rfc/rfc7857.html)。

依頼321は２つの処理先に４件を交互に送る固定模型で、故障と状態確認前後の記録の差を比較する。実際の検査間隔、再試行、全処理先の故障や性能は未対応。参考：[AWS: How Elastic Load Balancing Works](https://docs.aws.amazon.com/elasticloadbalancing/latest/userguide/how-elastic-load-balancing-works.html)。

依頼322は本庫と１中継拠点で、期限内の写し、期限切れと明示的な削除の固定例を操作する。再検証、無効化の伝播、障害時の応答や実際の速度は未対応。参考：[RFC 9111: HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html)。
