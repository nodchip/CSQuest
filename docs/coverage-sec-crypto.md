600〜603の Web Crypto は実験用の固定データまたは一時鍵を使う。602・603の本人と公開鍵の対応、616の確認済み鍵と暗号の正しい動作は模型の仮定であり、実際の本人認証・鍵管理や安全性の証明ではない。既知の試験値、操作・保存の検査と各例の出典・前提は [詳細](sec-crypto.md)に記す。

依頼989は [Stanford の秘匿転送の説明](https://crypto.stanford.edu/pbc/notes/crypto/ot.html) と [Virginia の講義ノート](https://www.cs.virginia.edu/~evans/courses/crypto-notes.pdf) の RSA を用いた導入を参考とする。法55、指数３と27、２つの固定された公開印を使い、選択した値の復元と、秘密を０〜54から一様に選んだ場合の送信側から見た依頼値を比較する。実際の３候補では両選択の依頼値が重ならず、選択が分かる。小さい法は全探索で他方も読める。実装は教育用の模型であり、安全な秘匿転送、実用の乱数、敵対的な参加者、完全な安全性証明は評価しない。`tests/oblivious-transfer.test.js` は両選択と全55通りについて復元、依頼値の分布、総当たり、保存と達成を検査する。

依頼990は989の依頼値について、限定された秘密候補や選択の事前割合が推測に与える影響を比較する。条件付き確率の仮定・検証と限界は [MSF-Probability](coverage-msf-probability.md) を参照。実用の秘匿転送の安全性を証明しない。

依頼991は [UCF の転置暗号の講義](https://www.cs.ucf.edu/~dmarino/ucf/cis3362/lectures/newlecs/Transposition.pdf) を参考に、２行４列の印を列ごとに上から読み、列順を操作する。異なる列では一致する順番は１通り、同じ内容の列を含む固定例では２通りあり、いずれも印の個数は変わらない。短い固定例であり、一般の暗号解析、実装、通信の安全性は評価しない。`tests/transposition-route.test.js` は両巻の全24通りの印の保存、一致する順番、途中記録・達成を検査する。

依頼992は991の列読みを逆にたどり、既知の鍵の順に２印ずつ列へ戻してから行ごとに読む。２行４列の固定例で、同じ内容の列がある場合も、与えられた鍵どおりに置いたかを確認する。[UCF の転置暗号の講義](https://www.cs.ucf.edu/~dmarino/ucf/cis3362/lectures/newlecs/Transposition.pdf) を参照。任意の長さ、鍵を知らない場合の一般的な解析、実用の安全性や実コードの作成は評価しない。`tests/transposition-decipher.test.js` で２巻の全24列順の暗号化・復号、鍵の検査と途中記録・達成を検証する。

依頼1032は法55の教科書的な RSA を用い、３×27 が法40で１、２の３乗が法55で８、８の27乗が法55で２となる例と、公開鍵と受取人の対応確認を関連付ける。[Cambridge の講義](https://www.cl.cam.ac.uk/teaching/2627/Crypto/)と [NIST の鍵管理](https://csrc.nist.gov/projects/key-management/faqs)を参照。小さい鍵、パディングのない模型であり、実際の通信や安全性の証明、本人確認の実施、一般の暗号の数学は評価しない。`tests/crypto-perspectives.test.js` で計算、選択肢、保存と達成を検査する。

依頼1271は [NIST の GCM](https://csrc.nist.gov/pubs/sp/800/38/d/final)と [Web Crypto の暗号化](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt)を参照し、公開された固定鍵・印と１バイトの実験で AES-CTR と AES-GCM の改ざん・再送への反応を比較する。`tests/crypto-mode-compare.test.js` は Node の Web Crypto で実際の復号・拒否・再送を検査する。CTR に別の認証を組み合わせる方式、鍵と印の安全な管理、本人確認、再送防止、一般の安全性は評価しない。
