# AR-Security：安全なプロセッサアーキテクチャの対応状況

出典：[CS2023、AR-Security](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 107–108。以下は原典を要約した作業用の一覧で、既存の依頼との接点は単位全体の達成を意味しない。原典で挙げられたトピックと例示学習成果はすべて KA Core。

## トピック

| 番号 | 内容 | 現状と限界 |
|---|---|---|
| 1a | 安全なハードウェアの原則：リスク分析、資産の保護、脅威モデル | 依頼180で媒体・起動部品・受付に対する固定の脅威と対策を比較。ハードウェアの脅威モデルやリスク分析は未対応 |
| 1b | 暗号処理のハードウェア支援 | 未着手。依頼58・128は暗号の固定模型であり、加速器を扱わない |
| 1c | 仮想化への支援、OS の隔離 | 依頼135は仮想マシンとコンテナのカーネル共有の比較。ハードウェア支援や隔離の安全性は未対応 |
| 2 | ハードウェアの信頼の起点と物理的複製困難関数（PUF） | 依頼257で個体差と読み取りの揺らぎを固定例で比較。依頼180は検証器を信頼できると仮定し、信頼の起点の構築は未対応 |
| 3 | ハードウェア乱数生成器 | 依頼256で決定的な数列と外部の物理的な雑音を比較。実際の雑音源、健全性検査やハードウェアは未対応 |
| 4a | 実行時のポインタ範囲検査とバッファオーバーフロー | 依頼255で４つの固定アクセスをページの許可と範囲付きの読み取り専用の鍵で比較。実機の例外や実際のバッファ操作は未対応 |
| 4b | マイクロアーキテクチャ水準のメモリ保護 | 未着手 |
| 4c | 命令セットアーキテクチャ（ISA）水準のメモリ保護 | 依頼255は CHERI の範囲・許可の考え方を単純化した固定模型。タグ、導出、命令や実装は未対応 |
| 5a | 信頼できる実行環境（TEE）と信頼の基盤（TCB）の保護 | 依頼258で証明の検証器や署名を信頼する固定例。TCB の構成・保護は未対応 |
| 5b | TEE による仮想マシンの保護 | 依頼258で仮想マシンの構成証明と鍵の受け渡しの固定例。メモリ隔離の実装や実機での検証は未対応 |
| 5c | TEE によるコンテナの保護 | 未着手 |
| 5d | TEE と信頼されたソフトウェアモジュール（エンクレーブ） | 未着手 |
| 6 | プライバシーを保つ処理のための準同型暗号 | 依頼259で教材用 RSA の乗算に関する性質と、決定的な暗号の危険を操作。安全な準同型暗号、加算や実用上の費用は未対応 |

## 例示学習成果

| 番号 | 要約 | 現状と限界 |
|---:|---|---|
| 1 | 安全なハードウェアの原則と、リスク分析・資産保護の枠組みを議論 | 依頼180は三つの固定した攻撃経路と対策の比較。ハードウェアを対象にした分析や自由な議論は未対応 |
| 2 | PUF をセキュリティ用途の装置固有識別に使う方法を要約 | 依頼257で登録と再測定の照合、誤拒否・誤受入の固定例を操作。実装や攻撃耐性の評価、自由な要約は未対応 |
| 3 | 専用ハードウェアでエントロピーを得る乱数生成器と、それを備えない生成器を区別 | 依頼256で決定的な規則の再現と、外部の物理的な雑音という情報源を比較。専用ハードウェアを使わない場合も OS の情報源を利用できると説明。実際の生成器の構成や検証は未対応 |
| 4 | ISA 水準のメモリ保護の利点と欠点を列挙 | 依頼255で頁内の範囲外アクセスの検出と、広すぎる範囲・範囲内の誤り・解放後アクセスの限界を提示。互換性とメタデータの費用にも触れるが、自由な列挙や一般的な比較は未対応 |
| 5 | 仮想マシンを支える TEE の重要な設計課題を説明 | 依頼258で署名、起動状態、新しい照会を照合する固定例。検証器への信頼や安全な転送先との結び付け等の限界を提示。自由な説明と TEE 設計全体は未対応 |

ゲーム内の選択操作は、自由な記述による議論や説明そのものを評価しない。今後教材を追加する場合も、実際の製品の安全性を固定模型の結果から推定しない。

依頼255の参考：[Cambridge CHERI FAQ](https://www.cl.cam.ac.uk/research/security/ctsrd/cheri/cheri-faq.html)。CHERI はアドレスに加えて範囲や権限を保持し、その利用を制限する ISA 拡張。依頼の鍵は概念を示す単純化であり、CHERI のタグや権限の導出などの仕組み全体を再現しない。

依頼256の参考：[NIST Random Bit Generation](https://csrc.nist.gov/projects/random-bit-generation)。決定的な生成器とエントロピー源は役割が異なる。教材の漸化式と公開された二つの種は暗号用ではなく、物理的な雑音の観測も生成や評価はしていない。

依頼257の参考：[NIST、ハードウェアの物理的測定](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=934744) §1.6.4。製造時のばらつきによる物理的な特徴を識別に利用する考え方を、既知の正解を持つ４件の架空の照合で表す。測定の揺れと別個体の類似は仮定であり、この例は実機の誤り率や複製困難性を評価しない。

依頼258の参考：[Google Cloud、Confidential VM の構成証明](https://docs.cloud.google.com/confidential-computing/confidential-vm/docs/attestation)。４件の固定報告で署名・期待する起動状態・照会への応答を検査する模型。実際の署名、証明書、nonce、通信、TEE の隔離や脆弱性を実装・検証しない。

依頼259の参考：[Craig Gentry, A Fully Homomorphic Encryption Scheme](https://crypto.stanford.edu/craig/craig-thesis.pdf) 第３章。法55、公開指数３、秘密指数27の教科書的 RSA で、暗号文の積を復号すると平文の積の剰余になる性質を示す。決定的かつ極小のため秘密保持に使えず、安全な準同型暗号を実装したものではない。
