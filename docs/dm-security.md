## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | データの安全とプライバシーの目的の違いを説明 | 依頼194で不要な収集、通信保護、閲覧制限を独立に操作。自由記述による説明は未対応 |
| 2 | CS Core | 異なる保護方法のリスクを特定し軽減 | 依頼194で３場面の固定例。実装の脅威分析は未対応 |
| 3 | CS Core | データの安全とプライバシーの法的・倫理的考慮を説明 | 依頼27・63で架空の範囲や関係者の固定例。法的要件と自由な説明は未対応 |
| 4 | KA Core | リスクを考慮した DB 監査システムを開発 | 依頼195で固定の記録項目と調査の選択を操作。実際の監査システムの開発・運用は未対応 |
| 5 | KA Core | 未知のデータ集合を理解するための探索手法を適用 | 依頼111〜115で可視化と集計の固定例。一般の未知データは未対応 |

依頼194は受取番号と時間で包みを渡せる架空の手順で、不要な診療歴の収集、正しく保護された通信、正しい閲覧権限検査を別々に試す。番号も他の記録と結び付けば個人を識別し得る。実際の法的要件、脅威や運用の安全性は評価しない。

依頼195は同一台帳への４件の架空の要求から、拒否された１件と許可された10件超の１件を選ぶ。後者は調査の手がかりであり不正の証明ではない。記録の正確さと完全性を仮定し、実際の監査ログの保全・解釈や本人特定は扱わない。

依頼196は架空の５人の値で、４人の合計14と３人の合計11から差３を求める。別条件では両方４人の合計14・12と、追加で既知の１人の値１から対象者の値３を推測する。最低人数４の制限は前者の３人集計を拒否するが後者の２集計を許す。一般的な公開制度や保護の保証は評価しない。
