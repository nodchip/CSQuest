# 項目別評価：NC-Routing の転送表と最長一致

2026-11-05 に [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.199–200、依頼48・61の実装と試験、公開版の操作を照合した。対象はトピック２と例示学習成果２。

## 評価 — いずれも部分対応

原典は転送表・照合方法と IP 網での転送の説明を扱う。依頼48は固定した一宛先について各塔の次の塔を選び、１ホップずつ転送し巡回と回数切れを経験する。依頼61は８ビットの架空宛先の一致と、文書用 IPv4 アドレス３例について固定表で最長一致を選ぶ。/26 の行を外すと、192.0.2.193 は /25 を選ぶ。

[RFC 4632 §5.1](https://www.rfc-editor.org/rfc/rfc4632.html#section-5.1) の最長一致と [RFC 5737](https://www.rfc-editor.org/rfc/rfc5737.html) の文書用アドレスを参照。表に行があることは実際の宛先への到達を保証しない。実 IP ヘッダー、実機の転送表、一般のアドレス・経路学習・自由な説明は扱わないため両項目とも部分対応とする。

`tests/forwarding.test.js` と `tests/prefix.test.js` の９件で18通りの転送表、256通りの８ビット宛先、IPv4 の３例・表の変更と旧記録を検査。390px幅の公開版で両依頼を達成し、IPv4 の /26 を外した際の選択と横あふれがないことを確認した。誤答と途中再開は IPv4 例の追加時に確認している。

文書用 198.51.100.3 は固定表の具体的な 192.0.2.x の経路に一致せず /0 を選ぶ。IPv4 の判定は32ビットの先頭を照合し、192.0.2.x と 198.51.100.x の各256宛先で数値範囲の独立判定と比較した。３例以外をゲーム内で任意に入力する操作や実網の設定は扱わない。
