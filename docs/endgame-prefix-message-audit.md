# AR-Memory：接頭符号による伝言（部分対応）

[CS2023 原典](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.104–105 の AR-Memory 9b 圧縮に関する固定例。現行の風車の里では連続する色をまとめる連長符号を扱う。旧依頼110 `huffman.js` は４記号の頻度からハフマン木を構築するため関連・重複があり、新しい達成範囲として二重計上しない。今回は既定の接頭符号表を使う符号化・復号と、異なる頻度でのビット数に焦点を当てる。

可変長は A＝0、B＝10、C＝11、固定長は A＝00、B＝01、C＝10。いずれも表の中の一つの符号が別の符号の先頭にならない。011100 は 0｜11｜10｜0 なので ACBA、ABCA は 010110。AAAAABBC の８記号は固定長16ビット、可変長11ビット。比較は本文のビット数のみで、符号表の伝達・保存や記号数の情報などは含まない。この例の可変長表があらゆる分布で有利とは限らず、ハフマン構築や最適性を証明しない。

参考：[Princeton のハフマン圧縮](https://algs4.cs.princeton.edu/55compression/) の接頭符号・頻度と符号長。任意の符号表・壊れた入力・実際のファイル形式・圧縮性能・自由なプログラム実装は評価しない。

実装担当とは別の `review_candidate` が原典・MIT OCW と接頭条件、固定例の符号化・復号とビット数、画面の前提、誤答・不正履歴、分類と開放、旧記録の既定値を確認した。関連８テストも成功した。任意の符号構築・一般の最適性を検証したものではなく、レビュー担当自身はブラウザを操作していない。

`scripts/endgame-prefix-message.playwright.js` は集いと４地域の達成状態を用意した検証用記録から、213・390・1200 px 幅で分類経由の到達、キーボード操作、誤答案内、途中保存・再開、段階開放と達成後の再開を確認した。新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者による面白さの評価は未確認。
