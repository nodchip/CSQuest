# 文庫の印で巻物を探す依頼：照合記録

[CS2023 印字122–123頁 DM-Unstructured](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) のトピック 2b は Bloom filter を索引の一例に挙げる。[RocksDB の説明](https://rocksdb.org/blog/2014/09/12/new-bloom-filter-format.html)では候補をデータ本体で照合し、不在なら読取りを省ける。旧依頼120の `src/bloom-scroll.js` を現行冒険で再利用する。同じ固定例なので新規の範囲達成を主張しない。

初期６印すべて０、月草は０・２、解毒は１・４、薬草は０・４、炎は３・５。最初の２語を登録すると [1,1,1,0,1,0]。月草は候補で実在、薬草は候補だが原本にはなく誤検知、炎は消えた印により不在。正常に登録、登録と検索で同じ位置を使い、印を消さず破損しない前提。実際の実装、確率・性能、削除、破損や並行更新、一般の設計と自由な説明は未評価。

## 独立レビューと動作確認

実装担当と別の担当が印、候補・確定不在・偽陽性と原本照合、保存・開放・焦点を確認。ブラウザ脚本の全角数字の期待を半角に修正し、再開後の登録ボタン状態も検査。ローカルで集いと４地域の達成状態を用意した記録から、幅 213・390・1200 px で誤答、キーボード、途中保存・再開と達成を確認した。冒険開始からの通し到達は含まない。
