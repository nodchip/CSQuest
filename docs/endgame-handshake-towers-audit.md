# 二つの塔の TCP 接続準備：教材監査

[CS2023 NC-Reliability 印字199頁](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=199) の TCP 接続準備の固定例。旧 `src/tcp-handshake.js` の依頼424を再利用し、現行の空の中継塔へ接続する。現行の配送・再送・HTTP の依頼とは異なり、通信前の双方の初期順序番号を扱う。

青100・赤500の通常接続では青 SYN(seq=100)、赤 SYN+ACK(seq=500,ack=101)、青 ACK(seq=101,ack=501)。青20・赤70では順に SYN(20)、SYN+ACK(70,21)、ACK(21,71)。SYN は順序番号を１つ消費し、ACK は相手から次に期待する番号。各知らせはただちに相手へ到着し、本文はない前提である。

これは固定の通常例であり、消失・再送・同時オープン・番号の巻戻り・任意の TCP 状態・データ送信・実装を評価しない。TCP の接続準備自体は本人認証や暗号化を保証しない。[RFC 9293 の接続確立](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.5) を参照。

## 独立レビューと動作確認

実装担当と別の担当が RFC 9293 と順序・確認番号、前提、保存・開放・焦点を照合。ローカルで集いと４地域の達成状態を用意した記録から、幅 213・390・1200 px で誤答、キーボード、途中保存・再開と達成を確認した。冒険開始からの通し到達は含まない。
