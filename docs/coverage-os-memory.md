# OS-Memory：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.210–211。[既存の調査](os-memory.md)と関連する依頼・テストを照合。状態は[追跡方法](coverage-status.md)に従う。固定模型は実 OS や実プログラムの開発能力を直接評価しない。

## トピック

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | KA Core | 物理メモリ、アドレス変換、管理ハードウェア | 部分 | 依頼40で固定ページ表による変換と保護の例。実機ハードウェアは未対応 |
| 2 | KA Core | キャッシュを含むメモリ階層が OS の仕組みと方針に与える影響 | 部分 | 依頼25でキャッシュの固定例。CPU ごとのキャッシュや OS 方針への影響は未対応 |
| 3 | KA Core | 論理・物理アドレスとアドレス空間の仮想化 | 部分 | 依頼40で４頁と３枠、依頼385で２プロセスの同じ仮想頁が別または同じ物理枠に対応する固定例。一般の仕組みは未対応 |
| 4 | KA Core | ページング、置換、スラッシング、ページと枠の割当 | 部分 | 依頼34・137の固定例と、依頼487で５種類・最大12参照の列を組み立て、３・４枠の FIFO・LRU・理想方式を比較。実際のスラッシングや一般の割当は未対応 |
| 5 | KA Core | メモリの確保・解放・格納手法の性能と柔軟性 | 部分 | 依頼387で先頭適合・最小適合、外部断片化と隣接空きの結合の固定例。実時間や一般の割当は未対応 |
| 6 | KA Core | メモリキャッシュ、一貫性、脆弱性対策としてのフラッシュ | 部分 | 依頼485で TLB の切替時消去と空間識別を操作。一般のキャッシュや脆弱性対策は未対応 |
| 7 | KA Core | サンドボックス、保護、分離と攻撃経路 | 部分 | 依頼40で読み取り専用頁、385で別枠と共有枠、491で Dirty COW の概要と参照先の変化を扱う架空模型。一般の保護や実際の攻撃手順は未対応 |
| 8 | Non-core | 仮想メモリのハードウェアを利用した OS の効率化 | 部分 | 依頼486で頁保護と書込み時の複製を操作する固定例。一般の仮想化や実装は未対応 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | KA Core | メモリ階層と費用・性能のトレードオフを説明 | 部分 | 依頼489で仮定した２階層の費用と読取り時間を比較。一般の階層と自由記述は未対応 |
| 2 | KA Core | キャッシュ・ページングにおける仮想メモリの原理を要約 | 部分 | 依頼34・40：３枠のページ置換と固定ページ表の住所変換。一般の原理と自由記述は未対応 |
| 3 | KA Core | 記憶容量とプロセッサ速度のトレードオフを評価 | 部分 | 依頼489で容量・費用と仮定した読取り時間を比較。プロセッサ速度の変化や実機は未対応 |
| 4 | KA Core | キャッシュの目的・利用と分離への影響を説明 | 部分 | 依頼485で TLB の空間混同と切替時消去・印を比較。一般の分離や VM は未対応 |
| 5 | KA Core | ページ置換と枠割当を考慮した効率的なプログラムを開発 | 部分 | 依頼488で同じ表の走査順を選び２枠の頁取寄せを比較する代替体験。実言語のプログラム開発能力は直接評価しない |
| 6 | Non-core | 効率的な仮想化へのハードウェア利用を説明 | 部分 | 依頼486で頁保護を使うコピーオンライトの固定例。一般的な説明や自由記述は未対応 |

`tests/paging.test.js`、`tests/free-space.test.js`、`tests/tlb-switch.test.js`、`tests/table-locality.test.js` 等は各模型の一部を検査する。前提・出典・限界は[既存の調査](os-memory.md)を参照。原典トピック５の各割当器、トピック６の投機実行対策、成果３のプロセッサ速度の変化などは未評価。
