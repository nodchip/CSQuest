# SPD-Mobile: モバイルプラットフォーム

出典：[CS2023 印字 pp.303–304](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。固定模型は実際のモバイルアプリを設計・開発する能力を評価しない。

| KA Core 2 UI とセキュリティ上の制約 | 依頼351でボタンとキー、394で操作対象の大きさ・間隔の固定比較。実端末 UI とセキュリティは未対応 |

依頼354は圏外で１件を端末に記録し、通信回復後に依頼Ａを送信する。サーバーは処理するが、返事が端末に届かない。再送が同じ番号Ａなら、この模型のサーバーは既存結果を返し１束のまま、別番号Ｂなら新しい依頼として２束にする。実際の API ではキーの保存期間、同時処理、内容の整合性、認証などが結果を左右する。[Android のオフライン同期ガイド](https://developer.android.com/topic/architecture/data-layer/offline-first) と [Stripe の冪等リクエストの仕様](https://docs.stripe.com/api/idempotent_requests) を参考にした固定例で、あらゆる API の振る舞いではない。

依頼1321は２要求の返事の到着とコールバック、古い結果の上書き、画面が待つ模型を比較する。固定例であり実機・実コードの実装やテストではない。出典と限界は [項目別対応表](coverage-spd-mobile.md) を参照。

依頼1322は1321の返事の順を練習用 Promise で制御し、成功・失敗を待つ試験を操作する。実端末・実サービスを検査したものではない。詳細は [項目別対応表](coverage-spd-mobile.md) を参照。

依頼1323は架空の位置権限の拒否・精度・変更と手動代替を操作する。実位置や実端末の許可は使用しない。出典と限界は [項目別対応表](coverage-spd-mobile.md) を参照。
