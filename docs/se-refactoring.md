# SE-Refactoring: リファクタリングとコードの進化

出典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.249–250。依頼234は３人の架空の利用者と３つの変更案に限る模型で、実際の利用者の発見や互換性の保証、プログラムの変更・自由記述を評価しません。

| トピック | 区分 | 対応と不足 |
|---|---|---|
| 1 暗黙のインターフェースと Hyrum の法則 | KA Core | 依頼234で、約束されていない一覧順に依存する利用者の固定例。未知の利用者や一般的なリスク分析は未対応 |
| 2a–b 後方互換性と提供側・利用側の関係 | KA Core | 依頼234で旧２人・新１人と３案を比較。一般の互換性モデルは未対応 |
| 3a–d リファクタリングの型、IDE・静的解析、技術的負債 | KA Core | 依頼224で依存先を変更し、依頼235で重複した条件を共通化する固定例。実際のリファクタリング、ツールと負債の評価は未対応 |
| 4a–b バージョン付け、SemVer、トランクベース開発 | KA Core | 未対応 |
| 5a–c 大規模な変更、旧 API と新 API の併存、見えない利用者 | Non-core | 依頼234で新旧窓口の併存と利用者ごとの結果を比較。段階的移行や未知の利用者の調査は未対応 |

|---|---|---|
| 1 明示・暗黙の振る舞いとリスクを特定 | KA Core | 依頼234で一覧の明示された内容と暗黙の順序依存を比較。一般的な特定・説明は未評価 |
| 2 静的解析や設計原則から改善箇所を特定 | KA Core | 未対応 |
| 3 支持する利用方法を踏まえた後方互換性の判断 | KA Core | 依頼234で３種類の利用者を固定条件で比較。一般の判断は未評価 |
| 4 既存利用者への影響を抑えた実装のリファクタリング | KA Core | 依頼235で共通条件への参照先を変更し、６試験で比較する固定例。実際の実装の変更は未評価 |
| 5 バージョン付け方針に照らした変更の安全性 | KA Core | 未対応 |
| 6 API の既定動作を安全に変える複数段階の計画 | Non-core | 依頼234は新旧の窓口を併存させる単一の固定案。移行計画は未対応 |

依頼234では旧窓口の明示的な約束は２種類を返すことであり、順序は未指定。順序変更は一覧を読む書庫には影響しないが、旧来の先頭に依存する薬師には影響する。名前変更で旧窓口を削除すれば旧２利用者は呼び出せず、新旧を併存し旧来の順序を維持する案は、この３人の期待を満たす。これは暗黙の順序を将来の正式な保証とみなすものではなく、利用側の修正や未知の利用者の確認は別途必要。

依頼235は画面と受付の「２個以上」という重複した条件を、共通部品へ参照を切り替えて整理する模型。３個以上を誤って選ぶと２個の境界で結果が変わる。元の条件を使用中は削除できず、変更のたびに６試験の記録を無効にする。有限の例と試験であり、一般的なプログラムの振る舞いの等価性は証明しない。
