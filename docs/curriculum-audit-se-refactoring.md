# 分母照合：SE-Refactoring

[CS2023 最終報告書 印字 pp.249–250](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=249) の SE-Refactoring と[候補台帳](coverage-se-refactoring.md)を 2026-11-10 に照合した。これは原典の範囲と項目の照合であり、教材の完成や正確性、操作・保存、独立レビューの実施を証明しない。

## トピック

KA Core 9件：

- 1：暗黙のインターフェースと Hyrum の法則。
- 2a・2b：後方互換性は提供者と利用者の関係であり、利用の形態や提供者の約束を踏まえて評価する。
- 3a・3b・3c・3d：名前変更・inline・outline などの標準的なリファクタリング、IDE のツール、改善箇所の検出や変更生成のための静的解析、技術的負債の対策としての価値。
- 4a・4b：Semantic Versioning、トランクベース開発。

Non-core 3件：

- 5a・5b・5c：旧 API と新 API の併存、振る舞いの変更を小さくすること、それらが必要となる理由と見えていない利用者。

原典の 2・3・4 は子項目をまとめる見出しとして、子項目をそれぞれ数える。5 の親文には、変更が一度に安全にコミットするには大きすぎる場合や、複数リポジトリ・非公開コードなどのため提供者と全利用者を同時に変更できない場合、という適用条件がある。この条件を上記 5a–c の共通の文脈として保持し、親と子を重複して数えない。旧台帳の3aの「型」は原典の標準的なパターンとその例を含む。

## 例示学習成果

KA Core 5件（1〜5）：明示・暗黙の振る舞いとリスクを特定する、静的解析や設計原則から改善箇所を特定する、対応する利用形態を踏まえて後方互換性を判断する、既存利用者への影響を最小に実装をリファクタリングする、採用する版管理方針に照らし変更の安全性を評価する。

Non-core 1件（6）：API の既定動作を安全に変更する複雑な複数段階のリファクタリングを計画する。

トピック12件と成果6件は別々に追跡する。原典が挙げる具体例は対象範囲を理解するために残し、例だけで項目全体の達成とはしない。

## 現行の冒険との区別

台帳中の番号付き依頼は旧教材の記録であり、この照合だけでは現在の冒険から到達できる根拠にはならない。現行の冒険に関する SE-Refactoring の項目別評価は、この記録時点では未作成である。未作成は教材が存在しないことの証明ではない。実コードの変更や自由な説明を含む原典の成果は、ゲーム内操作で練習できる範囲と直接評価できない範囲を別途記録する必要がある。

2026-11-10、照合担当とは別の `review_candidate` が原典・区分・項目数・親５の条件と候補台帳の対応を確認した。これは原典範囲の照合に対するレビューであり、教材の正確性、現行の冒険からの到達、操作・保存やブラウザを確認したものではない。整合性検査の範囲ハッシュは候補 ID と台帳要約を対象とし、監査文書の記述や学習内容の正しさを保証しない。
