# NC-Applications の対応状況

出典: [CS2023, NC-Applications](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 199。原典を要約した作業用一覧。依頼62は固定された簡略モデルであり、実際の通信やアプリケーションの実装ではない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | CS Core | DNS や URI などの名前と住所 | 依頼421で DNS の固定例、669で相対参照・検索条件・フラグメントを比較。別名、実通信と一般的な名前付けは未対応 |
| 2 | CS Core | クライアント・サーバー、P2P、クラウドなど | 依頼62で端末とサーバー、667で中央書庫と既知の仲間からの受信・複製を比較。クラウドや一般の構成は未対応 |
| 3 | CS Core | 遅延・帯域・損失耐性などアプリケーションの要求 | 依頼668で全断片の必要性と３刻目の新しさを固定到着例で比較。帯域や一般的な要求分析は未対応 |
| 4 | CS Core | HTTP などのアプリケーション層プロトコル | 依頼62で POST と再送、425で HTTPS の GET と証明確認の固定例。HTTP 全体や実通信は未対応 |
| 5 | CS Core | TCP・UDP・ソケット API との相互作用 | 依頼424で TCP の接続開始、668で順序付きバイト列とデータグラムの損失時の固定例。ソケット API と実通信は未対応 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 名前、住所、資源の位置の原則を定義 | 依頼421で DNS、669で固定 URI の構成と相対参照を操作。一般の資源の位置や自由な説明は未対応 |
| 2 | CS Core | ネットワークアプリの要求を分析 | 依頼668で完全性と期限の異なる２用途を固定条件で比較。一般の分析は未対応 |
| 3 | CS Core | アプリケーション層プロトコルの詳細を説明 | POST 再送の一例のみ。プロトコルの詳細や自由な説明は未対応 |
| 4 | CS Core | 単純なクライアント・サーバーのソケットアプリを実装 | 未着手。ゲーム操作は実装能力を評価しない |

依頼62は、最初の処理が成功し返事だけが失われる状況をプレイヤーに明示する。HTTP が自動的に重複を抑えるわけではなく、識別番号に対応するサーバーを仮定した例である。

依頼421は架空の `library.example` と文書用住所 `192.0.2.42`、４刻の TTL を使う。最初と期限後はルート・TLD・権威サーバーを順に訪れ、期限内は保存した住所を返す。[RFC 1034](https://www.rfc-editor.org/rfc/rfc1034) と [ICANN の説明](https://www.icann.org/en/rssac/faq)を参照。実際には委任情報も保存され、期限切れデータを例外的に使用できる場合もあるため、毎回同じ経路になるとは限らない。

依頼425は [RFC 9110 の HTTPS の証明確認](https://www.rfc-editor.org/rfc/rfc9110#section-4.3.4) を参考に、DNS・TCP・証明・HTTP を固定模型として結ぶ。証明の期限と秘密鍵の保有確認は与件とし、対象名や信頼関係の不一致では送信前に中止する。実通信・暗号計算や HTTP/3 の接続処理は扱わない。

依頼667は最新の版２を持つ中央書庫と、初め版１を持つ既知の仲間への独立した通信を切替える。中央断でも仲間から受け取れるが古い版の場合があり、両接続中に旅人が版２を仲間へ渡すと、その後の中央断でも版２を受信できる。探索・認証・多拠点の同期、実通信や一般の可用性は扱わない。中央方式も複製を利用でき、P2P が中央の発見機能を使う場合もある。[RFC 5694](https://datatracker.ietf.org/doc/html/rfc5694)。

依頼668は１番が１刻目、２番が消失、３番が３刻目に到着し、TCP 模型では４刻目に２番の再送が届く固定例。順序付きバイト列の上にアプリ側のメッセージ区切りを仮定し、UDP 模型では再送しない。３断片が必要な用途と３刻目に最新の３番を使いたい用途を比較する。実際の到着時刻・成功や期限を保証せず、UDP アプリも独自の確認・再送を実装できる。[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html)、[RFC 768](https://www.rfc-editor.org/rfc/rfc768.txt)。

依頼669は `https://library.example/herbs/index.html` を基準に５つの参照を解決し、HTTP の依頼対象からフラグメントを分ける。書庫が application/x-www-form-urlencoded 形式で条件を解釈する固定例として、`name=moon%26star` と `name=moon&star` を比較する。一般の URI の全検索形式、実通信や認証は扱わない。[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986.html)、[WHATWG URL Standard](https://url.spec.whatwg.org/)。
