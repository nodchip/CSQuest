# NC-Applications の対応状況

出典: [CS2023, NC-Applications](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 199。原典を要約した作業用一覧。依頼62は固定された簡略モデルであり、実際の通信やアプリケーションの実装ではない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | CS Core | DNS や URI などの名前と住所 | 未着手 |
| 2 | CS Core | クライアント・サーバー、P2P、クラウドなど | 依頼62で端末がサーバーへ依頼する例。方式の比較は未対応 |
| 3 | CS Core | 遅延・帯域・損失耐性などアプリケーションの要求 | 応答消失の一例のみ。一般的な要求の分析は未対応 |
| 4 | CS Core | HTTP などのアプリケーション層プロトコル | 依頼62で POST と再送の固定例。HTTP 全体や実通信は未対応 |
| 5 | CS Core | TCP・UDP・ソケット API との相互作用 | 未着手 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 名前、住所、資源の位置の原則を定義 | 未着手 |
| 2 | CS Core | ネットワークアプリの要求を分析 | 未着手 |
| 3 | CS Core | アプリケーション層プロトコルの詳細を説明 | POST 再送の一例のみ。プロトコルの詳細や自由な説明は未対応 |
| 4 | CS Core | 単純なクライアント・サーバーのソケットアプリを実装 | 未着手。ゲーム操作は実装能力を評価しない |

依頼62は、最初の処理が成功し返事だけが失われる状況をプレイヤーに明示する。HTTP が自動的に重複を抑えるわけではなく、識別番号に対応するサーバーを仮定した例である。
