# SF-Performance の対応状況

出典: [CS2023 SF-Performance](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 294–295。原典を要約した作業用一覧。固定モデルのクリアから、実機の性能評価や自由な説明能力の達成を主張しない。

| 3 | CS Core | データベース・OS・分散システム・計算機でのキャッシュと一貫性 | 依頼104で単一の共有値と無効化の固定例。実プロトコルと各システムへの応用は未対応 |

| 5 | KA Core | 平均メモリアクセス時間の式 | 依頼103でミス率・棚の時間・追加時間から３構成の平均を計算。複数階層や実機は未対応 |
| 6 | KA Core | 仮想化と分離の理由 | 依頼135で共有カーネルと別ゲストの互換性、２ VM の固定した資源制限を比較。実際の保護と性能分離は未対応 |
| 7 | KA Core | 仮想メモリによる間接参照 | 依頼40・385で仮想頁と物理枠の固定対応。一般の仕組みは未対応 |

## 例示学習成果

| 番号 | 分類 | 要約 | 状況と限界 |
|---:|---|---|---|
| 1 | CS Core | メモリ、ディスク、ネットワークの遅延の内訳を説明 | 未着手 |
| 2 | CS Core | 局所性と性能の関係を説明 | 依頼25で時間的局所性、依頼103で空間的局所性と容量の固定例を比較。自由な説明は未対応 |
| 3 | CS Core | 平均アクセス時間、容量・ヒット率・時間の関係を計算・説明 | 依頼103の平均式と489の容量・費用・時間を比較。実測と自由な説明は未対応 |
| 4 | KA Core | 実行環境の分離・保護の重要性を説明 | 依頼385で別枠と共有枠を比較。一般の VM の保護は未対応 |
| 5 | KA Core | 間接参照と共有資源による専用環境の見かけを説明 | 依頼385の仮想頁から物理枠への固定対応。専用機械全体の見かけは未対応 |
| 6 | KA Core | 別 VM で動く二つのアプリの性能分離を評価 | 依頼135で資源共用と各２個の上限の４条件を比較。実 VM の実測と一般的な評価は未対応 |

依頼25は、完全連想・容量２・LRU・読み込み専用の抽象的な棚を使う。ヒット時間１、ミス時の合計時間６は架空の単位。両列とも A・B・C を２回ずつ要求するが、A B A B C C は３ヒット・合計21、A B C A B C は０ヒット・合計36。実際のキャッシュの階層、並列性、書き込み、一貫性や実測値は対象外。

同じ依頼の光の模型では、真空中の光速を 299,792,458 m/s とし、0.3・3・30 m の片道を 1 GHz の約１・10・100周期と比較する。0.3 m の伝搬時間は約1.0007 ns で、2 GHz の周期数は約２倍。各値は概数で、媒体中の伝搬速度、往復、回路処理、待ち時間や実機の応答時間は扱わない。光速の定義：[NIST の SI 単位](https://www.nist.gov/si-redefinition/definitions-si-base-units)。

依頼103の平均時間の追加試験では、毎回の棚を調べる時間に、ミス率とミス時の追加時間の積を足す。３構成の平均はそれぞれ 3.5・3.25・4.5 で、棚を調べる時間が長くてもミス率が低い棚Ｂが最短となる固定例。時間と割合は仮定であり、複数階層や実機の並列性・実測は扱わない。参考：[Cornell の平均アクセス時間](https://www.cs.cornell.edu/courses/cs3410/2025fa/notes/caches.html)。

依頼135の追加模型では、１刻の容量４、Ａの要求４、Ｂの要求０または３とする。Ｂを先に処理する共用方式のＡは４または１、各２個を上限にして貸し借りしない方式のＡはどちらも２。後者は安定するが、Ｂが休むと２個分を使わない。この優先順・上限は模型の仮定で、実 VM のスケジューリング、他の資源、時間や安全性を保証しない。参考として [Linux の CPU 帯域制限](https://docs.kernel.org/admin-guide/cgroup-v2.html) は期間あたりの最大 CPU 時間を設定できるが、この模型と同一の割当を主張しない。
