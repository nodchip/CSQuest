# ４ビット加算と読み方の範囲：教材監査

[CS2023 AR-Representation 印字103頁](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=103) の成果７、同じ加算器と符号なし・２の補数の読み方に関する固定例。旧 `src/adder.js` の依頼37は加算器を組んで任意の４ビット入力を試せる。現行の `forge-integer-addition` は５＋３、15＋１、８＋15で結果と範囲超過を入力する。今回、旧加算器の各桁の結果を活用し、右端から繰り上がりの伝播を一桁ずつ操作して、同じ出力の２種類の読みを比較する。

0111＋0001＝1000、桁上がり０は符号なし７＋１＝８で範囲内、符号付き７＋１＝８は範囲外で1000は−８。1111＋0001＝0000、桁上がり１は符号なし15＋１＝16で範囲外、符号付き−１＋１＝０で範囲内。４ビットの範囲はそれぞれ０〜15、−８〜７。符号なしの範囲超過は最上位からの繰り上がり、符号付きは最上位への繰り上がりと外への繰り上がりの不一致で分かる。

固定２例であり、任意の入力・ビット幅、一般の証明、減算、実 CPU の状態フラグやプログラミング言語の振る舞い、自由な説明は評価しない。[Cornell の桁あふれ判定](https://www.cs.cornell.edu/courses/cs314/2004fa/l11.pdf) を参照。

2026-11-11、実装担当と別の `signed_review` が原典と [Cornell の整数表現講義](https://www.cs.cornell.edu/courses/cs314/2004fa/l11.pdf) に照らし、２例の各桁の繰上り・符号なし／２の補数の範囲超過、画面・保存・開放を独立レビューした。親担当が準備済み記録から幅 213・390・1200 px の鍛冶街の分類に到達し、誤答、キーボード、途中保存・再開、開放条件、達成後の保存をブラウザ確認した。新規開始からの通し操作、スクリーンリーダー音声、利用者による面白さは未確認。
