# NC-Fundamentals の対応

原典: CS2023 p.198。依頼78は、送り手・二つの口を持つ中継塔・受け手による２区間の単純化した通信。アプリケーションの伝言にトランスポート層とネットワーク層の封を重ね、区間ごとにデータリンク層の封を選ぶ。物理層は区間を通して送るという説明に留める。ネットワーク層の端点を保ちつつ、各区間の送り元・次の受け手を変える例である。参考: [RFC 791](https://www.rfc-editor.org/rfc/rfc791)、[RFC 894](https://www.rfc-editor.org/rfc/rfc894)。IP の TTL などは中継で変化するため、すべてのネットワーク層の情報が不変だとは示していない。

例示学習成果は CS Core。1 インターネットの組織は依頼517の固定例。2 通信の用語、4 エッジやコア等の複雑さは未対応。3 の階層構造は依頼78の固定例に限り、一般的な説明能力やプロトコル実装を評価しない。

依頼271は空の行列の容量２通、到着を先に処理し各刻１通送る模型。時刻０に３通が来ると最後の１通が落ち、１刻ごとなら全３通が届く。到着順は固定で、伝搬遅延、再送、可変長パケットや輻輳制御は扱わない。参考：[MIT、通信路と待ち行列](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/950e349a9779e491000426ccb218746e_MIT6_02F12_chap16.pdf)。

依頼272は３通を、各１刻の２区間と蓄積転送の中継塔を通して４刻で届ける固定模型。中継塔は刻の始めに保持する伝令のみを送る。２区間を異なる伝令で同時に使えるが、伝搬遅延、処理時間、消失、可変長や他の通信は扱わない。参考：[MIT、通信ネットワーク](https://ocw.mit.edu/courses/res-6-004-principles-of-computer-system-design-an-introduction-spring-2009/e962408d900226fef264fd1cd1b81468_part_ii_open_5_0.pdf)。

依頼516は１区間が１刻に１通を送る４刻の模型。Ａ専用の予約中はＢを受け付けず、Ａが送らない刻は空く。共有では到着を先に待機させ、プレイヤーがＡ・Ｂを選ぶ。交互到着では専用は２通・空き２刻、共有は４通送れる。毎刻Ａ・Ｂが１通ずつ届く場合、専用はＡ４通・Ｂ４通受付不可、共有で交互に送ると各２通・４通待機となり、待機時間は０・１・１・２刻。全合法な共有操作で伝言の保存と容量を検証した。有限バッファ、パケットの大きさ・損失、回線設定、伝搬や一般の保証は未対応。[MIT の通信路の共有](https://ocw.mit.edu/courses/6-02-introduction-to-eecs-ii-digital-communication-systems-fall-2012/950e349a9779e491000426ccb218746e_MIT6_02F12_chap16.pdf)を参照。

依頼517は端末から接続事業者へ進み、事業者内の複製、中継事業者経由、または合意済みの相互接続点を介した配信元への経路を比べる。中継が使えない条件も扱う。自律システムは共通の経路方針を示す IP の網のまとまりであり、事業者との１対１対応を仮定しない。接続点だけで通信が成立するわけではなく、経路と合意を所与とする。模型内の区間数は実際の遅延ではない。実際の契約・BGP・復旧・キャッシュ更新や復路は扱わない。参考：[Internet Society のピアリング](https://www.internetsociety.org/our-work/connectivity/peering/)、[RFC 1930](https://www.rfc-editor.org/rfc/rfc1930.html)。

依頼556は A・B・ルータの一方が同一 LAN、C がルータの別側にある固定模型。ハブは A の入力以外へ信号を繰り返し、スイッチは B の宛先を既知なら B 側のみ、未知なら B 側とルータ側へフレームを送る。送出と端末の受理は区別する。C 宛てでは A の最初の MAC 宛先はルータの LAN 側、ルータは C 側 MAC を送り元とし C の MAC を宛先とする新しいフレームを作る。IP の送信元・宛先を保ち、TTL 5 を４とする例。入力の宛先３通りと４場面を検査した。ARP の解決、VLAN、無線、フィルタ、断片化や一般のルータ実装は扱わない。[Cisco の転送](https://www.cisco.com/en/US/docs/internetworking/troubleshooting/guide/tr1923.pdf)、[RFC 1812](https://www.rfc-editor.org/rfc/rfc1812)。

依頼557は A・B・ルータ G が同じ Ethernet、C が別ネットワークにある固定模型。A は B 宛てなら B、C 宛てなら G の IP を ARP 要求で問い合わせ、同じ LAN の応答と次のフレームの MAC 宛先を確かめる。C の IP を直接尋ねると代理 ARP のない条件では応答がない。問い合わせと予想の全組合せ、保存の検証と再挑戦を検査した。ARP 表の期限、損失、なりすまし、代理 ARP、IPv6、実装の詳細は扱わない。[RFC 826](https://www.rfc-editor.org/rfc/rfc826) を参照。
