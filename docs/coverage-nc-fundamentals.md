## 例示学習成果

| 番号 | 区分 | 内容 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | インターネットの組織を説明 | 部分 | 517 は固定の接続と経路。一般の説明や実事業者は未評価。 |
| 2 | CS Core | ネットワーク用語を列挙し定義 | 部分 | 複数の依頼でパケットや階層等を扱う。用語全体の体系的な定義と自由な列挙は未評価。 |
| 3 | CS Core | 一般的なネットワーク構成の階層を説明 | 部分 | 78 は固定された２区間の封。一般の説明は未評価。 |
| 4 | CS Core | エッジやコア等の複雑さの種類を特定 | 部分 | 1015で中継と端点の返事・再送・重複処理を２つの消失例で比較。一般の中継器やネットワーク設計は未評価。 |

依頼1015は２端点と２中継器の固定経路で、初回のデータまたは返事が１回消える場合を比較する。端点Ａは返事なしの時間切れ後に同じ番号を再送し、Ｂは重複を利用者へ再度渡さず返事を返す。時間切れは通信中の品が消失した後だけ操作する固定模型で、実際には遅延中にも起こり得る。中継は宛先へ転送するだけという模型で、[RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html) の確認・順序・再送と [RFC 791](https://www.rfc-editor.org/rfc/rfc791.html) の IP の役割を参照。実際の TCP はバイト列・接続管理・ウィンドウ等を持ち、中継器にも様々な機能がある。故障が続く場合の到達保証、実 API や実通信は評価しない。`tests/end-to-end.test.js` で両経路、到着・重複・完了、途中記録を検査する。
