# OS-Process の対応状況

出典: [CS2023, OS-Process](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 210。原典を要約した作業用一覧。この固定例の達成は知識単位全体の習得を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | KA Core | プロセスとスレッド、状態、仮想化、保護と分離 | 依頼53で状態、179でスレッドとプロセス、385で頁の分離・共有、386で親子の生成と終了の固定例。一般の仕組みは未対応 |
| 2 | KA Core | スタックやヒープなどメモリの構成 | 依頼388で呼出しの局所領域と明示的に確保・解放する領域の寿命の固定例。その他の構成や一般の処理系は未対応 |
| 3 | KA Core | 実行ファイルの作成・読込み、共有ライブラリと動的リンク | 依頼386で子の実行内容の置換え、依頼392で実行ファイル作成と起動時の共有部品・シンボル解決の固定模型。実ファイルや一般の動的リンク処理は未対応 |
| 4 | KA Core | ディスパッチとコンテキスト切替え | 依頼390でタイマー割込み、保存・選択・復元の固定例。実際の切替え処理は未対応 |
| 5 | KA Core | 共有メモリやメッセージなどプロセス間通信 | 依頼385で共有枠、389でパイプと通信選択、386でシグナル、153で起動時に渡す環境情報の固定例。一般の IPC や実装は未評価 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | KA Core | プロセスとスレッドによる制御の仮想化 | 一部試作：単一の計算装置で二つの仕事を進める例。スレッドと仮想化の一般的な説明は未対応 |
| 2 | KA Core | 並行性と仮想化を支える割込み、ディスパッチ、コンテキスト切替えの理由 | 依頼390でタイマー割込みと位置・値の切替えの固定例。一般の割込みや実際の切替え処理は未対応 |
| 3 | KA Core | タスクの状態と、多数のタスクの管理に必要なデータ構造 | 依頼391で三つの仕事の実行待ち列と入出力待ちの固定例。実際の管理構造の実装は未対応 |
| 4 | KA Core | タスクへのメモリ割当て方式とその長所・短所 | 依頼387で連続領域の先頭適合・最小適合と断片化の固定例。一般的な割当て方式の評価は未対応 |
| 5 | KA Core | 目的に合うプロセス間通信を選びプログラムに適用 | 依頼389でパイプの固定例を操作し、パイプ・共有メモリ・TCP と注意点を３用途から選択。実際のプログラム作成や一般の設計は未評価 |

入出力の完了をプレイヤーが進めるモデルであり、実際の装置や割込み、経過時間、プリエンプションは再現していない。

依頼385では A・B の仮想頁０を別枠または同じ共有枠に対応付ける。順に A が７を書き、B が読み、B が３を書き、A が読む。別枠の読取りは０・７、共有枠は７・３。アクセスは順序どおりに完了し、権限はあるものとする。実装、競合やメモリ順序は扱わない。[OSTEP のページ表](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf)、[Linux の共有マッピング](https://man7.org/linux/man-pages/man2/mmap.2.html)。

依頼386は単一スレッドの親が開いた記録 ABC を引き継ぐ固定模型。子の私有メモリ変更は親に反映されず、同じ開いた記録の読取り位置は親子で共有される。子の exec 相当で実行内容とメモリを置き換えるが子の識別子と、close-on-exec を設定しない番号は維持する。待たない確認、正常終了と終了状態の回収も操作する。実際の OS、異常終了やスケジューリングは扱わない。[fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)、[execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html)、[waitpid(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html)。

依頼386の別の通知例では SIGTERM の既定の終了と、処理が戻って継続する例、SIGKILL の処理設定ができず既定で終了する例を比べる。送信と配送は手動で分ける模型。[signal(7)](https://man7.org/linux/man-pages/man7/signal.7.html)を参照。配送時刻・送信権限・シグナル処理内の安全な操作・複数スレッドや実 OS は扱わない。

依頼388は C の自動・動的な寿命を単純化した模型。呼出し元に場所を伝えても局所の対象は呼出しから戻ると寿命が終わり、明示的に確保した対象は解放まで続く。実際の配置は処理系や言語によって異なり、寿命終了後の読取りは保証されない。[OSTEP: Memory API](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-api.pdf)。

依頼389では空の単方向パイプでの待機、二つの書込み口、蓄積済みデータの読取りと終端を扱う。単一の受け手と固定の AB を使う模型であり、非待機操作、満杯時の書込み、エラーや実プログラムの作成は扱わない。[pipe(7)](https://man7.org/linux/man-pages/man7/pipe.7.html)。

依頼389の追加例は、親子の一方向パイプ、同一端末の共有領域、別端末への TCP 接続から、指定した３用途に合う方法と注意点を選ぶ。書込み口の終了、共有メモリの同期、TCP のバイト列の区切りと接続失敗を区別する。[共有メモリ](https://man7.org/linux/man-pages/man7/shm_overview.7.html)、[ソケット](https://man7.org/linux/man-pages/man2/socket.2.html)を参照。選択肢以外の手段もあり、TCP 単体は認証や秘匿を保証しない。実 API や一般の設計は評価しない。

依頼153では親のシェル変数に渡す印を付けた場合と付けない場合を比べ、子の起動時に渡る値と親子の後の変更を操作する。外部プログラムの一度の起動に別の値を渡し、次の起動は親の値を受け取る例も扱う。[Bash の環境](https://www.gnu.org/software/bash/manual/html_node/Environment.html)を参照。環境は起動時に渡される情報であり、親子の継続的な共有メモリではない。実際のシェル構文や他の特殊なコマンドは扱わない。

依頼390ではタイマー割込み後、A と B の位置と値を保存・復元し、A の続きを再開する。割込みと切替えは区別するが、実際の CPU や OS の処理、アドレス空間と他のレジスタは扱わない。[OSTEP: Limited Direct Execution](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-mechanisms.pdf)。

依頼391では単一 CPU で三つの仕事を順に進め、A の入出力待ちと完了後の列への復帰、持ち時間による末尾への移動を操作する。到着時刻はプレイヤーが決める。複数 CPU、実時間、実際の管理構造や他の選択方針は扱わない。[OSTEP: The Process](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-intro.pdf)。

依頼392は原稿から部品と実行ファイルを作り、起動先で共有ライブラリの不在または必要シンボルの不在を確認して修復する固定模型。起動時に結合する設定であり、遅延結合、実際の検索順や互換性は扱わない。[GCC](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)、[ld.so(8)](https://man7.org/linux/man-pages/man8/ld.so.8.html)。
