# OS-Process の対応状況

出典: [CS2023, OS-Process](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 210。原典を要約した作業用一覧。この固定例の達成は知識単位全体の習得を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | KA Core | プロセスとスレッド、状態、仮想化、保護と分離 | 依頼53で状態、179でスレッドとプロセス、385で頁の分離・共有、386で親子の生成と終了の固定例。一般の仕組みは未対応 |
| 2 | KA Core | スタックやヒープなどメモリの構成 | 依頼388で呼出しの局所領域と明示的に確保・解放する領域の寿命の固定例。その他の構成や一般の処理系は未対応 |
| 3 | KA Core | 実行ファイルの作成・読込み、共有ライブラリと動的リンク | 依頼386で子の実行内容を置き換える固定模型。実ファイルの作成・読込みと動的リンクは未対応 |
| 4 | KA Core | ディスパッチとコンテキスト切替え | 一部試作：空いた計算装置へ実行待ちの仕事を割り当てる例。実際の切替え処理は未対応 |
| 5 | KA Core | 共有メモリやメッセージなどプロセス間通信 | 依頼385で明示的な共有枠の固定例。同期や一般の IPC は未対応 |

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | KA Core | プロセスとスレッドによる制御の仮想化 | 一部試作：単一の計算装置で二つの仕事を進める例。スレッドと仮想化の一般的な説明は未対応 |
| 2 | KA Core | 並行性と仮想化を支える割込み、ディスパッチ、コンテキスト切替えの理由 | 一部試作：待機中に別の仕事を動かせることを示す。割込みと実際の切替えは未対応 |
| 3 | KA Core | タスクの状態と、多数のタスクの管理に必要なデータ構造 | 一部試作：二つの仕事の状態。待ち行列などのデータ構造は未対応 |
| 4 | KA Core | タスクへのメモリ割当て方式とその長所・短所 | 依頼387で連続領域の先頭適合・最小適合と断片化の固定例。一般的な割当て方式の評価は未対応 |
| 5 | KA Core | 目的に合うプロセス間通信を選びプログラムに適用 | 未着手 |

入出力の完了をプレイヤーが進めるモデルであり、実際の装置や割込み、経過時間、プリエンプションは再現していない。

依頼385では A・B の仮想頁０を別枠または同じ共有枠に対応付ける。順に A が７を書き、B が読み、B が３を書き、A が読む。別枠の読取りは０・７、共有枠は７・３。アクセスは順序どおりに完了し、権限はあるものとする。実装、競合やメモリ順序は扱わない。[OSTEP のページ表](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf)、[Linux の共有マッピング](https://man7.org/linux/man-pages/man2/mmap.2.html)。

依頼386は単一スレッドの親が開いた記録 ABC を引き継ぐ固定模型。子の私有メモリ変更は親に反映されず、同じ開いた記録の読取り位置は親子で共有される。子の exec 相当で実行内容とメモリを置き換えるが子の識別子と、close-on-exec を設定しない番号は維持する。待たない確認、正常終了と終了状態の回収も操作する。実際の OS、異常終了やスケジューリングは扱わない。[fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)、[execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html)、[waitpid(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html)。

依頼388は C の自動・動的な寿命を単純化した模型。呼出し元に場所を伝えても局所の対象は呼出しから戻ると寿命が終わり、明示的に確保した対象は解放まで続く。実際の配置は処理系や言語によって異なり、寿命終了後の読取りは保証されない。[OSTEP: Memory API](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-api.pdf)。
