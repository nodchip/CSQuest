# FPL-Functional の対応状況

出典: [CS2023 FPL-Functional](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 131–133。原典を要約した作業用一覧。依頼51はあらかじめ用意された道具をつなぐ固定例であり、実言語で関数を定義する能力を評価しない。

## トピック

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | CS Core | ラムダ式、束縛、スコープ、引数、評価順序 | 未着手 |
| 2 | CS Core | 副作用を持たない処理、不変データ、再帰・反復・map/reduce | 依頼51で元の列を変えずに map・filter・合計をつなぐ固定例。一般の副作用・不変性や再帰との比較は未対応 |
| 3 | CS Core | 構造化データの各部分の処理、永続データ構造 | 依頼51で数の列の固定例。木や永続データ構造は未対応 |
| 4 | CS Core | 関数を受け取り、返し、保持する高階関数 | 依頼51の道具は操作を組み込んだ固定例。プレイヤーが関数自体を渡す・返す操作は未対応 |
| 5 | KA Core | メタプログラミングとリフレクション | 未着手 |
| 6 | KA Core | クロージャ、スコープ、コールバック、遅延評価 | 未着手 |
| 7 | Non-core | グラフ簡約機械と必要時評価 | 未着手 |
| 8 | Non-core | 遅延評価の実装 | 未着手 |
| 9 | Non-core | 等式論理や単一化による論理型との統合 | 未着手 |
| 10 | Non-core | 手続き型・オブジェクト指向などとの統合 | 未着手 |

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | CS Core | 変更可能な状態への代入を避けるアルゴリズムを開発 | 依頼51で入力列を変更しない固定道具を操作。実言語による開発は未対応 |
| 2 | CS Core | 関数を受け取り返す関数を開発 | 未着手 |
| 3 | CS Core | 手続き型・関数型・オブジェクト指向の解法を比較 | 未着手 |
| 4 | CS Core | 各パラダイムのデータ定義・保護方法を比較 | 未着手 |
| 5 | KA Core | 仮想機械でのラムダ式と環境の管理を説明 | 未着手 |
| 6 | KA Core | クロージャ内の変数と静的スコープを解釈 | 未着手 |
| 7 | KA Core | クロージャやモジュールによるカプセル化 | 未着手 |
| 8 | KA Core | 状態を持つ実行と持たない実行を比較 | 依頼51は入力を変更しない例のみ。対照となる状態付き実行は未対応 |
| 9 | KA Core | 複数言語で反復子や集約操作を定義・利用 | 依頼51で列操作を組み合わせる固定例。実言語や自作関数は未対応 |
| 10–13 | Non-core | グラフ簡約、抽象機械、単一化、並行構文の例示 | 未着手 |

依頼51は [1,2,3,4] と [2,3,5] を２倍、６以上の選択、合計の順に処理し、それぞれ14と16を得る。４種類の道具を３段に置く全64通りを両入力で検査し、両方の目標に合うのはこの組合せだけと確認する。入力列が変更されないことと、列を要求する道具に数を渡す場合の失敗をテストする。
