依頼51は [1,2,3,4] と [2,3,5] を２倍、６以上の選択、合計の順に処理し、それぞれ14と16を得る。４種類の道具を３段に置く全64通りを両入力で検査し、両方の目標に合うのはこの組合せだけと確認する。入力列が変更されないことと、列を要求する道具に数を渡す場合の失敗をテストする。

依頼52では倍率を受け取って関数を返す装置を２回呼び、作成ごとに異なる倍率の束縛を保持する例を扱う。２倍・３倍の封印に４を渡すと８・12、３倍・１倍の封印に３を渡すと９・３。元の設定を変更しても各呼び出しの引数束縛は変更されない。クロージャが常に値のコピーを持つとは主張せず、変更可能な束縛は依頼591で別に扱う。

依頼590では元の A→B→C に X を先頭追加後、元の２番目を９にする。直接書換えでは B を共有する二つの入口から９が見え、新たな石は０個。版を残す方法では A と B に対応する新しい P・D を作り、末尾 C を共有する。元の版と X の版は変化しない。[Cornell の関数型データ構造](https://courses.cs.cornell.edu/cs3110/2021sp/textbook/modules/functional_data_structures.html)を参照。固定の一方向鎖の例で、一般の永続構造の実装・計算量やディスクへの保存は扱わない。

依頼591は二つの生成呼び出しが各々０の束縛を持ち、それぞれの増加・読取り封印が同じ組の束縛を共有する。Ａ増加・Ｂ読取り・Ａ増加・Ｂ増加・Ａ読取り・別の部屋からＡ読取りの返り値は１・０・２・１・２・２。部屋に同名の９があっても静的スコープで作成元のＡを参照する。[MDN のクロージャ](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures)を参照。独自の小模型で、全言語のスコープ規則、並行処理や実言語での開発は評価しない。
