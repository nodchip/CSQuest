# SF-Reliability の対応状況

原典: [CS2023 SF-Reliability](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.296。固定例の操作であり、一般の設計や自由記述を評価しない。

| 番号 | 区分 | 内容と現状 |
|---|---|---|
| 1 | CS Core | バグ・故障・障害の違い。依頼23で書き間違い・記憶破損・内部結果・サービスの約束違反を比較。一般の分類や複数障害の連鎖は未評価 |
| 2 | CS Core | 信頼性と可用性の違い。依頼108で同じ稼働割合の２記録と４刻連続稼働を比較。一般の確率モデルや将来の推定は未対応 |
| 3a | CS Core | 確認と再試行による冗長性。依頼10・62で消失と再送の固定例。一般的な障害対処は未対応 |
| 3b | CS Core | 冗長符号化。依頼106・107でハミング符号、追加の全体パリティと CRC の固定例。FEC の一般論や RAID は未対応 |
| 3c | CS Core | 複製・ミラー・レプリカ。依頼229で装置故障時の複製への切替と、誤更新が複製に伝わる例を比較。非同期複製・分断・一般の復旧は未対応 |
| 4 | KA Core | ジャーナリングなど。依頼35は送金の途中停止と確定の固定例。一般の復旧機構は未対応 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1 | CS Core | プログラム・システムの誤り、ハードウェア故障、例外の区別。依頼23で固定の書き間違い・記憶破損・０除算の未処理と処理済みを比較。一般の分類や自由な説明は未評価 |
| 2 | CS Core | 検出・処理・復旧の違いと方法。依頼23で理想的な独立検査・代替・例外処理、依頼10・35・106・107・229で別の固定例。一般の分類と自由な説明は未評価 |
| 3–4 | CS Core | 冗長符号の役割、簡単な訂正操作。依頼106・107の固定例で訂正と CRC の検出を操作。各媒体への応用や一般的な説明は未対応 |
| 5 | KA Core | 誤り検出・訂正方式の余分なデータ量、複雑さ、時間を比較。依頼107で４ビットのデータに３ビットを加える CRC と、４ビットを加える８灯方式の固定例を扱う。実行時間と実装の複雑さの比較は未対応 |

依頼107では依頼106と同じデータに全体の偶数パリティを１ビット加える。最大２ビットの誤りという仮定で、不一致の組の合計が６かつ全体が奇数なら位置６の１ビット誤り、全体が偶数なら２ビット誤りと判断し、後者は訂正せず知らせる。全体パリティの１ビット誤りは不一致の合計０・全体奇数となる。16データの全１・２ビット誤りを列挙して検証した。３ビット以上の誤りは区別を保証しない。参考: [University of Michigan の (8,4) 符号の解説](https://www.eecs.umich.edu/courses/eecs373.w05/lecture/hamming.html)。

同じ依頼の別の模型では、４ビット 0101 に生成多項式 1011 による３ビットの剰余 100 を付ける。受信列を XOR の筆算で割り、変化なし、１・２ビットの検出と、４・６・７番の反転を見逃す例を比べる。剰余０は無誤りの保証ではなく、この模型は訂正位置を特定しない。16通りのデータと各７ビットの誤りパターン全128通りを独立した整数の多項式除算と照合し、全１・２ビット誤りの検出を検査した。生成多項式と長さを固定した例であり、一般の CRC の性質は同一とは限らない。参考：[Carnegie Mellon University の CRC の除算](https://www.cs.cmu.edu/~15451-f22/recis/reci12.pdf)。

依頼108は２つの架空の12刻の記録 111011101110 と 111111111000 を比較する。いずれも稼働９/12。各記録で１〜９刻目に出発できるか調べ、開始時に稼働中の窓に限ると４刻連続稼働はそれぞれ０/７、６/９。窓は重複し独立ではなく、これらはこの記録の数え上げであり将来の信頼性推定ではない。信頼性の定義の参考: [NIST glossary](https://csrc.nist.gov/glossary/term/reliability)。

依頼23の追加試験は、門の下限の書き間違い、上限を５から２へ破損した記憶、０除算の例外を固定模型で比較する。前二者は特定入力で内部結果と約束が異なり、独立した正しい検査と代替が成功する仮定では利用者への結果が修正される。別の割り算の約束は入力０で０を返すことで、例外未処理なら返答なし、捕捉して代替すれば０を返す。書き間違いがあっても２人の入力では表面化しない。検査・代替の成功は仮定であり、実際の検出・復旧やすべての言語の例外の挙動を保証しない。参考：[Avizienis ほか、信頼性の用語](https://www.ece.iastate.edu/~mai/docs/papers/2004_Taxonomy.pdf)、[Python の ZeroDivisionError](https://docs.python.org/3/library/exceptions.html#ZeroDivisionError)。
