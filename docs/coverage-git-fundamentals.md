# GIT-Fundamentals：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.155–156。[追跡方法](coverage-status.md)に従う。原典の項目を子項目まで分け、固定模型と実装・自由な説明を区別する。GIF は原典で非可逆形式の例に挙げられているが、圧縮そのものと色数の制限・減色による情報損失を区別して扱う必要がある。詳細な既存例は [記録](git-fundamentals.md) を参照。

関連検査には `tests/raster.test.js`、`tests/color-mixing.test.js`、`tests/vector-raster.test.js`、`tests/transform.test.js` がある。各模型の範囲のみを検査する。

依頼947は [MDN の画像の収め方](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit)を参考に、正方形の絵を２種類の枠に保持・伸長し、２・４ fps の固定コマを表示する。画面の実測リフレッシュ、再生精度や人の知覚は評価しない。

依頼948は [Linux DRM の表示モード](https://docs.kernel.org/gpu/drm-uapi.html)を参考に、表示領域と総走査数、画素クロック、フレーム頻度の関係を固定条件で操作する。プログレッシブ走査の単純模型であり、インターレース・変動リフレッシュ・実機信号は評価しない。

依頼949は [MDN の画像形式](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types)と[動画のコンテナー](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)を参考に、５種類の用意された候補を固定の要件で比較する。容量や受信側の対応は架空であり、全形式の全機能や実用環境を評価しない。

依頼950は米国議会図書館の[動画デジタル化の形式比較](https://blogs.loc.gov/thesignal/2014/12/comparing-formats-for-video-digitization/)と[映像保存の記録](https://www.loc.gov/static/programs/national-film-preservation-board/documents/tvturner.pdf)を参考に、量子化、複製、再符号化と欠損を区別する。値と誤差は架空であり、実際の画質や保存性能を測定しない。`tests/video-preservation.test.js` で模型の数値、誤答、保存と達成条件を検査する。

依頼951は [MIT の標本化教材](https://ocw.mit.edu/courses/2-161-signal-processing-continuous-and-discrete-fall-2008/80ec6fb9bd027f30adcdc16577e8ab16_samplingdft.pdf)を参考に、同位相の１ Hz と５ Hz の波形を４・８・12 Hz で記録して比較する。`tests/temporal-sampling.test.js` は４ Hz での一致、８・12 Hz での差、保存と達成条件を検査する。２つの固定波形の例であり、一般の再構成や実機の精度は検証しない。

依頼952は [Reinhard らの論文](https://w3.impa.br/~lvelho/ip02/papers/reinhard/)の単純な大域圧縮と [W3C の sRGB](https://www.w3.org/TR/css-color-4/)を参考に、線形明るさの上限切捨てと圧縮、３露光を比較する。`tests/tone-mapping.test.js` で固定例の値と保存・達成条件を検査する。表示値は端末の実測輝度や人間の知覚ではなく、色画像や一般の方法も未評価。

依頼953は [Merck の TN 型 LCD 解説](https://www.emdgroup.com/en/expertise/displays/solutions/liquid-crystals/lcd-technologies/twisted-nematic.html)を参考に、背後の光を液晶・直交偏光板・RGB フィルターで制御する模型を扱う。`tests/lcd-workshop.test.js` は灯りと３小窓の全16条件、保存と達成条件を検査する。理想的な２状態・透過型の例であり、中間階調や他の LCD 方式・実機は未評価。

依頼954は [ウィーン大学のハーフトーン解説](https://www.mat.univie.ac.at/~kriegl/Skripten/CG/node6.html)を参考に、４場所の閾値順序で黒点を置き、５段階の面積を作る。`tests/halftone-press.test.js` は５濃度と全16配置、保存と達成条件を検査する。等面積の点による固定模型であり、実際の印刷機構・色・紙・人間の知覚は未評価。

依頼955は 949・951・953・954 の模型を再利用する冒険。標本化、半透明を保つ形式、LCD の光の制御、点の版を各場所で使い、番人の封印を解く。`tests/image-rescue.test.js` で進行制約、誤りと再挑戦、途中記録、準備の変更を検査する。元の依頼と同じ固定条件であり、実機や自由な設計を評価しない。
