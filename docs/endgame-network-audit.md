# 集いの後：空の中継塔の通信

原典：[CS2023 最終報告書](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印刷ページ198–199。二つの依頼はいずれも通信の仕組みの固定例です。

| 依頼 | 関連項目と操作 | 今回の範囲外 |
| --- | --- | --- |
| 名前から宛先を調べる | NC-Applications：名前帳で宛先を探し、名前ごとの一時控えと期限を確かめる。該当なしと番号の更新を含む。 | DNS の階層・実装、URI、複数レコード、名前解決全般の説明や実装。塔の控えは二分間というこの模型の規則。 |
| 塔の送信口を手伝う | NC-Fundamentals：一つの送信口で到着順に四つの場面を送り、到着から送信開始までの待ち時間を比べる。 | 処理・伝搬の遅延、損失、優先制御、一般の輻輳やサービス水準、実通信の性能評価。 |

2026-11-10、実装担当とは別の next_topic が原典・模型・画面をレビューしました。名前帳では期限ちょうどのテストが実際の期限判定を検証できない点を指摘し、控えの有効性で独立に拒否するよう修正後に再確認しました。送信口では到着順と待ち時間を独立計算し、同時到着の扱いと待ち時間の定義を画面に明示するよう指摘しました。画面接続後は、正解ボタンへの自動フォーカスを避ける指摘を受けて状況表示へ移し、同担当がコードと検証スクリプトを再確認しました。独立担当自身によるブラウザ操作は行っていません。

進行済みの検証用記録を用い、390・1,200 CSS px と幅320px・150%表示を213 CSS pxで模擬したブラウザで、誤答、途中保存、全場面の達成を確認しました。実際のブラウザ倍率、スクリーンリーダー実機、利用者本人の評価、公開後の確認は未実施です。
