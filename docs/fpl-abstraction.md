# FPL-Abstraction：プログラムの抽象化と表現

出典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.140–141。以下は原典の項目の要約と限定的な対応であり、依頼の達成が実際のプログラム作成・説明能力の証明になるわけではない。

| 番号 | 区分 | 内容と対応状況 |
|---|---|---|
| 1 | KA Core | BNF・正規表現。依頼154で限定した正規表現の固定例。BNFと一般的な構文の記述は未対応 |
| 2 | KA Core | 他のプログラムを入力にするインタプリタ・コンパイラ等。依頼73・75で命令や式を操作する固定例。一般的な翻訳器や型検査器は未対応 |
| 3–4 | KA Core | 言語の文字・区切り・文・構文・意味、曖昧でない有意味な文。依頼75で固定した式の木と評価の例。一般の定義や曖昧性は未対応 |
| 5 | KA Core | 定数、変数、宣言、命令、式、代入、選択、繰り返し、関数、モジュール、例外など。依頼01〜04・197〜199・224等で一部を操作。一般の構文や抽象化は未対応 |
| 6 | KA Core | 可変・不変とコピー・再計算の比較。依頼197・201〜203で代入、回収、参照の固定例。一般的な費用比較は未対応 |
| 7–9 | KA Core | 静的・局所・非局所・大域の変数、静的・動的スコープと副作用。依頼199で局所変数、52でクロージャ、307で大域箱の副作用、308で静的・動的スコープの固定例。一般のスコープ規則と副作用は未対応 |
| 10–11 | Non-core | 左辺値・右辺値、環境とストア。依頼306で値の写しと元の箱への参照を比較。一般の形式的な意味論は未対応 |
| 12–13 | Non-core | データ・制御の抽象化、プログラム単位間の情報交換。依頼199・224・306で関数、モジュール境界、値・参照渡しの固定例。他の方式と一般的設計は未対応 |
| 14–15 | Non-core | コードの表現と低水準命令表現。依頼73・75で架空の命令と固定式の木。一般の表現・変換は未対応 |
| 16 | Non-core | ラムダ計算、変数束縛と変数名の変更。関連する固定例は依頼52・283。一般の形式的操作は未対応 |
| 17 | Non-core | 操作的・公理的・表示的・振る舞いの意味論、抽象構文木と具体構文。依頼75・281で固定式の木と操作的な評価の例。他の意味論と一般の比較は未対応 |

| 例示学習成果 | 区分 | 対応状況 |
|---|---|---|
| 1 | KA Core | 依頼199・308で局所的な箱と静的・動的スコープの固定例。一般のスコープ・可視性の説明は未対応 |
| 2 | KA Core | 依頼306で可変整数の値渡しと参照渡しを比較。他の引数渡し方式は未対応 |
| 3 | KA Core | 依頼307で大域箱の変更と明示的な入力・返り値による固定例。一般の非局所変数や自由な説明・修正は未対応 |
| 4 | KA Core | 依頼73・75で命令・式を扱う固定例。プログラムを入力データとして処理する一般的な説明は未対応 |
| 5–6 | KA Core | 依頼75で固定された式の抽象構文木。文法の記述や文字列以外の表現の利点を一般的に説明する能力は未対応 |
| 7 | KA Core | プログラムを処理するプログラムの実装は未対応。操作型の模型は実装能力を評価しない |

依頼306は、初期値２の変更可能な整数の箱、３を足す精霊、返り値５という架空の固定例で、値の写しと元の箱への参照、および返り値を元の箱に代入するかどうかの４通りを比較する。実在の言語では値として参照が渡される場合もあり、その参照を通じた対象の変更と引数変数そのものの変更は区別する。参考：[Cornell: State and Call by Reference](https://www.cs.cornell.edu/courses/cs6110/2025sp/lectures/state-sp25.pdf)。

依頼307は大域の箱を更新する処理と、毎回入力２を渡して３を返す処理の２回の呼び出しを比較する。特定の目的に対し共有箱を書き換えない方法を選ぶ。共有状態が必要な場合もあり、副作用自体を常に誤りとはしない。一般の非局所状態・並行実行や実言語の仕様は未対応。参考：[MIT: State and Referential Transparency](https://ocw.mit.edu/courses/6-001-structure-and-interpretation-of-computer-programs-spring-2005/d4d959b3cc2df3f12fe9492adf4421e4_lecture22webhan.pdf)。

依頼308は工房で定義した精霊を工房または同名の箱を持つ部屋から呼ぶ固定例で、静的スコープと動的スコープの探索を比較する。束縛と値の区別を説明するが、一般の言語規則は未対応。参考：[Cornell: Static and Dynamic Scoping](https://www.cs.cornell.edu/courses/cs6110/2017sp/lectures/lec12.pdf)。
