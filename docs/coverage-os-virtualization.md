| 番号 | 区分 | 要約 | 状態 | 体験と残る範囲 |

依頼135・137の仮定と限界は [OS-Virtualization](os-virtualization.md) と [SF-Performance](sf-performance.md) を参照。依頼40・485・486の仮想メモリの模型は [OS-Memory](os-memory.md)、依頼751の線形対応は [OS-Devices](coverage-os-devices.md) を参照。原典のトピック５はスラッシングの例として Popek–Goldberg を併記するが、ページの過剰な入替えと再帰的仮想化の要件を混同せず、後者は別途未評価として追跡する。

依頼754は [Linux Symposium の仮想化支援の説明](https://www.kernel.org/doc/mirror/ols2007v1.pdf) を参考に、単一の設定を２つのゲストが直接共有する例と、対象の変更を捕まえ、門番がゲスト別に記録・切替えする固定模型を比較する。直接共有ではＢが７・Ａが９、門番ありではＢが０・Ａが７を読む。`tests/vm-trap.test.js` で順序・値・途中復元を検査する。実際の命令や装置、性能、安全性、複数 CPU や全ての仮想化方法は扱わない。

依頼755は [QEMU のエミュレーション](https://www.qemu.org/docs/master/about/emulation.html) と [セキュリティの説明](https://www.qemu.org/docs/master/system/security.html) を参考に、同じ・異なる符、直接実行・読み替え、隣へのアクセスを拒否する壁の有無を独立に選ぶ。異なる符を直接実行できず、読み替えは双方を実行でき、壁が正しく働くと仮定した模型。`tests/emulation-isolation.test.js` は８構成と予想・記録・復元を検査する。実際の互換性、安全性、処理速度やエミュレーターの構築は評価しない。QEMU は用途により安全性の扱いが異なり、エミュレーションを使うだけで隔離が保証されるとは限らない。

依頼756は [Linux KVM の MMU](https://docs.kernel.org/virt/kvm/x86/mmu.html) のゲスト仮想→ゲスト物理→ホスト物理の変換を参考に、２塔・各２頁・４物理枠で両段階の書込み権限と共有を操作する。ゲストＡとＢの物理頁１を別の枠、または同じ枠へ対応させ、値の読み書きを比較する。`tests/two-stage-memory.test.js` で全ての塔・頁・操作・対応先と拒否時の値、共有、復元を検査する。頁内の位置、TLB、頁表自身の変換、フォールトと実装固有の権限は扱わない。
