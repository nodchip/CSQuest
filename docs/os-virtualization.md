# OS-Virtualization：仮想化

出典: [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.213–214。固定した模型は実際の仮想化環境の構築能力や安全性を直接評価しない。

| トピック | 区分 | 内容と現状 |
|---|---|---|
| 1–3 | KA Core | 仮想化・隔離による保護と性能、高度なページング・仮想メモリ、仮想ファイル・装置。依頼34・40でページ置換と変換、135で２ VM の資源割当、751で仮想装置、756で二段階変換と共有を比較。実際の隔離・性能と他の項目は未評価 |
| 4 | KA Core | コンテナと仮想マシンの比較。依頼135で共通カーネルと別々のゲストカーネルにおける架空の互換性の固定模型。実際の環境、資源や安全性の比較は未対応 |
| 5 | KA Core | スラッシング等。依頼137で繰返し参照と２・３枠の読み込み回数の固定例。実際のスラッシングと他の内容は未対応 |
| 6–10 | Non-core | 754で門番が設定を切替える模型、755で符の読み替えと隣の箱へのアクセス制限を比較。各種仮想化、実際の移植性、費用、脱出の危険、実際のハイパーバイザー実装は未評価 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1–3 | KA Core | 754で保護された変更を門番へ渡す模型、135で資源制限、755で読み替えとアクセス制限を比較。実際の効率や一般の実装は未評価 |
| 4 | Non-core | 754で門番による設定の分離を比較。ハイパーバイザーの種類や実装は未評価 |

依頼135は月の道具が架空の土台１、星の道具が土台２でのみ動くと仮定する。２コンテナは同じホストカーネルを共有し、土台１と２のどちらでも片方だけが動く。２仮想マシンはそれぞれのゲストに土台１・２を用意でき、両方が動く。実際にはコンテナが仮想マシン内で動く場合もあり、CPU、ライブラリー、設定など他の互換性条件も必要。別の資源割当模型は [SF-Performance](sf-performance.md) を参照。いずれも実際の速度、資源、安全性は評価しない。参考: [Docker: What is a container?](https://docs.docker.com/learn/content/what-is-a-container/)。
