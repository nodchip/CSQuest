# AI-Planning の対応

原典: CS2023 p.78。依頼85は２種類の小さな迷宮を持つ。状態は場所・鍵の有無・残り時間、操作は隣接する部屋への移動、目的は鍵を持って門に到達すること。鍵は祭壇に到着すると取得し、各移動の時間は１。２つ目では鍵を取って入口に戻らなければならず、同じ場所でも鍵を持つ前後で状態が異なる。独立した幅優先探索で、鍵を考慮した最短移動回数がそれぞれ３・４であることを確認する。

例示学習成果1は与えられた状態・目的・操作を使う固定例に留まり、一般の構築は未対応。2–4の PDDL、一般の半順序計画と GraphPlan は未対応。ゲーム操作は実際の計画器を実装する能力を直接評価しない。

依頼100は鍵と水晶を取得後、紋章の間で起動してから塔へ入る。仕掛けの前提では２道具の取得順は自由だが、道路と灯りが可能な順序を制約する。古い道は最短６移動、新しい橋は５移動。道具の状態を含む独立した幅優先探索で最短を照合した。半順序計画の一般的な構築や自動計画は未対応。

依頼541は４作業から作れる12本の前後関係を選び、24通りの全作業順を調べる。２つの収集はいずれも調合より先、調合は配達より先であり、収集の順序は自由。選択した関係の4,096通りを別の再帰的な順序生成と照合した。有限の固定作業であり、任意のアクションの計画や因果リンクを扱わない。

依頼542では、点灯が開門の条件を作り、風が条件を壊す。風を点灯前または開門後に置くと脅威を防げる。６本の順序制約の全64選択と３作業の順序を照合した。固定した１つの因果リンクであり、一般的な計画器や変数は扱わない。

依頼543では初期状態を「お菓子あり」、食べる操作を「食べた・お菓子なし」を加えて「お菓子あり」を削除、焼く操作を「お菓子なし」が前提で「お菓子あり」を加えて「お菓子なし」を削除する模型とする。１段階後は「お菓子あり」と「食べた」が候補に現れるが支える操作が相互排他であり、２段階後は食べて焼くことで同時に満たせる。操作の前提・削除効果と支援の相互排他を計算し、独立した状態遷移と照合した。依頼543では最後の目標から両立する支援操作を選び、その前提を一段ずつ遡る。一般の探索や自動的なバックトラックは扱わない。

依頼544は閉門・開門のどちらかと鍵の有無を持つ４状態で、開門操作の前提・追加・削除を選ぶ。鍵と閉門を必要とし、開門を加えて閉門を除き、鍵を保つ。事実が追加と削除の両方に入る操作は拒否する。３種類の事実に対する512通りの札を集合操作と照合した。固定された行動と４状態で、変数・負の前提・PDDL の自由な記述は扱わない。

依頼545は配達を準備・移動・受け渡しに分解し、準備は在庫の受取か収集・調合、移動は橋か山道・峠を選ぶ。２状況で在庫や通行の前提と具体的な行動を確認する。全ての許可される方法の組合せと状態の再生を検査した。固定された全順序の分解であり、任意のタスクネットワーク、複数人の資源競合や自動的な計画探索は扱わない。

依頼546は出発時に橋の通行可否を知らず、分かれ道で正確な知らせを得る。通れるなら橋、通れなければ必ず通れる山道を使うという課題で、２通りの知らせについて、事前に両分岐を作る方法と、橋を予定して観測後に選び直す方法を比較する。固定された２状態であり、観測誤り、確率、道路の追加変化や自動計画探索は扱わない。

依頼547は確かな選択が４点で終了、挑戦は確率1/2で６点終了、1/2で０点のまま門に戻る。時間切れ後の追加報酬は０、割引率は１。残り１回の挑戦は期待３点、残り２回で失敗後に確かな選択を使えば期待５点、もう一度挑戦するなら4.5点。さいころ２回の全36組で照合した。既知の固定確率と有限２段階の模型で、確率の推定や一般の計画器ではない。

依頼548は西・中央・東の一本道と、中央に待避所がある道で、東西からの２人の位置を交換する。各刻に待機か隣へ移動し、同一地点と逆方向の同時通過を禁じる。一本道では左右の順番が変わらず不可能、待避所ありでは４刻の解がある。有限の全位置と可能な同時移動を検査した。今回の衝突規則による固定模型で、実際の移動時間・大きさや一般の複数エージェント計画は未対応。

依頼544の巻物では、PDDL の `:init`、`:goal`、`:precondition`、`:effect` を４つの固定断片で読み分ける。`and` と効果内の `not` を含む。変数、任意の問題や実際の計画器は対象外。[ANU の計画領域と問題の解説](https://users.cecs.anu.edu.au/~patrik/pddlman/writing.html)を参照。

依頼544では鍵の有無が異なる２つの初期状態から、鍵の取得と開門を実行して開門の目標を満たす。取得は鍵を追加し、開門は鍵と閉門を前提に開門を追加・閉門を削除する。状態を変えない行動はこの画面では記録せず、最小手数の探索や実際の PDDL 計画器の実行は扱わない。
