# NC-Applications：条件付き GET と地図の写し

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.199、NC-Applications 4 の HTTP。旧依頼670 `src/http-validation.js` の地図・版・200／304模型を現行の塔に再利用し、旧教材と独立した範囲として重複計上しない。現行の塔の HTTP 教材は GET／HEAD の違いであり、条件付き GET と写しの再検証は扱わない。

初回は写しがなく条件なし GET で版１の本体８単位・目印を受ける。条件付き GET の If-None-Match と現在の目印が一致すると304、本文なしで手元の版１を利用する。版２への更新後はこの正常な固定例では不一致となり200と版２の本体８単位を受け取る。同じ操作順（初回・再取得・更新後の取得）の毎回取得は本体24単位、条件付きは16単位。304 も要求・応答の通信があり、架空の単位は本文量のみで、ヘッダーや通信全体は含まない。[RFC 9110 の If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2) と [304](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4.5) を参照。

固定された正常応答と二つの版の模型であり、弱比較・複数値・ヘッダーの更新・鮮度やキャッシュ制御、他の HTTP 応答、通信障害や実通信、実装と一般の性能は評価しない。NC-Applications 全体の完成を示さない。
