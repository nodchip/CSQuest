# 観測所の配達人形：範囲と未完了

[CS2023 印字 78 ページ（PDF 78 ページ目）AI-Planning](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の Non-core にある行動・状態表現と全順序計画の入口。[Poole と Mackworth の計画の解説](https://artint.info/3e/html/ArtInt3e.Ch6.S1.html)は、行動の前提条件と状態への効果、初期状態と目標を説明する。

旧 `strips-door.js` 等は現行冒険への到達を示さない。現行観測所ではエージェントの固定規則、観測、期待損失、探索などを扱うが、今回の依頼は別に、鍵・門・位置・荷物の状態と、各行動の前提・効果を使う。鍵を取ると棚からなくなり手元に移る一方、門を開いても鍵は残る。入口で開いた門を通る方法や庭で荷物を渡す条件を、異なる初期状態で操作する。条件を満たさない行動は状態を変えず、到達時点で目標を確認する。門が開いている場合、鍵を取ってから通る方法と取らずに通る方法の両方を許す。

状態と行動、二つの目標は固定されている。目標が初期状態ですでに成立する例や、成立後に取り消される行動、一般の探索・最短性、PDDL の記述、実際の計画器、自由な状態設計や説明は未評価であり、原典の広い範囲を完成としない。

`observatory-planning-rules` と `observatory-planning-steps` の２件を終えると `observatory-planning-plan` が開く。観測所の依頼分類から選び、地図の全達成判定にも含まれる。

実装担当とは別の `review_candidate` が原典、上記資料と [STRIPS 原論文](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/strips.pdf)、固定例の前提・状態への追加と削除・無関係な事実の保持、複数の有効な手順、説明、分類と保存をコード上で確認した。一般の探索器や PDDL による実装を評価したものではない。レビュー担当自身はブラウザを操作していない。

`tests/endgame-planning.test.js` は前提違反、効果の追加・削除と他の状態の保持、可能行動なし、初期状態に応じた複数の有効順序、途中履歴と修正を確認する。`tests/late-region-quest-groups.test.js` は分類と開放を確認する。`scripts/endgame-planning.playwright.js` は集いと４地域などの達成を用意した検証用記録から、213・390・1200 px 幅で分類からの到達、キーボードによる依頼と回答、誤答の案内、途中復元、段階開放、３依頼の達成と達成後の再開を確認した。新規開始からこの依頼群までの通し操作、実際のスクリーンリーダー音声、利用者による面白さの評価は未確認。
