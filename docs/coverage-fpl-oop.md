依頼778の C3 順序は [Python の解説](https://docs.python.org/3/howto/mro.html)に基づく。根の後の `object` を省略し、固定の３階層について列の先頭から条件を満たす最初の候補を選ぶ。実際の Python で対応する２階層の `__mro__` と矛盾階層での `TypeError` を確認した。`tests/mro-merge.test.js` は各段階の不正操作と途中復元を検査する。これは探索順の例であり、協調的な `super()` の呼出しや他言語の多重継承規則は評価しない。

依頼779は [Oracle の Reflection API](https://docs.oracle.com/javase/tutorial/reflect/) の実行時の型・メンバー情報の利用を参考に、固定された２種類の公開操作情報を模型上で調べ、その情報から操作札を生成する。対象の交代で古い札を持ち、対象が対応しない操作の実行を拒否してから更新する。`tests/reflection-menu.test.js` は情報の写し・古い札の拒否・再生成・各段階の不正操作・復元を検査する。モデル内の定義済み情報を使う簡略化で、Java Reflection API 自体の利用や、権限・例外・継承・任意のクラスの検査は扱わない。
