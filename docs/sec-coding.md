# SEC-Coding の対応

原典: CS2023 p.259。依頼82は、固定した台帳と３種類の名前について、引用符で囲んだ SQL 条件へ入力をそのまま連結する例と、名前を正しくパラメータとして渡す例を比較する。３札×２方式の結果は別途 SQLite の一時データベースでも照合した。ゲーム自体はデータベースや一般的な SQL パーサを実行しない。参考: [OWASP SQL Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)。

| 分類・番号 | 内容と現状 |
|---|---|
| CS Core 1–2 | 一般的な脆弱性と SQL 等へのインジェクション。依頼82で固定された文字列連結と値のパラメータ化の例。一般の脆弱性や他のインジェクションは未対応 |
| CS Core 3 | XSS と緩和策。依頼528で固定された札を HTML として解釈する場合とテキストとして表示する場合を比較。実ブラウザの実行や属性・URL 等の文脈は未対応 |
| CS Core 4 | 入力検証とサニタイズ。依頼524で数の範囲を画面側だけ／サーバー側でも検証する固定例。一般の入力処理やサニタイズは未対応。パラメータ化は文法と値の分離であり、一般の入力検証や認可の代替ではない |
| CS Core 5 | 型安全。依頼24は道具の入出力の型検査の固定例であり、セキュリティへの影響は未対応 |
| CS Core 6–7 | 依頼578で８ビットの容量計算と領域外書込み・計算前検査、818で在庫確認と更新の競合の固定模型。実言語、一般のバッファ管理や悪用・防止は未評価 |
| KA Core 8–17 | 196で集計からの推論、349・657で限定した検査と解析、789で翻訳の意味保存の固定例。形式的な情報フロー、マルウェアや一般の安全性は未評価。詳細は[項目別台帳](coverage-sec-coding.md)を参照 |

例示学習成果は CS Core 1–8 と KA Core 9–16。CS Core 7 は、固定例の問題とパラメータ化による違いを操作するのみで、実アプリケーションの評価や修正は未対応。他の成果も固定例や未照合が残る。[項目別台帳](coverage-sec-coding.md)にそれぞれの範囲と不足を記す。実際の API を使った安全なプログラムを書く能力や、一般的な安全性は評価しない。

依頼578は０〜255の容量を256で剰余化する架空の道具で、31・32・40枚×８区画と32枚×４区画を３種類の検査で比較する。32×８は必要256に対して確保０、40×８は必要320に対して確保64。計算前に枚数が ⌊255 ÷ １枚の区画数⌋ 以下か検査する方法はこの模型の桁あふれを防ぐ。実機の整数型・符号、確保失敗、実際のメモリ操作や全般的な安全性は扱わない。参考: [CWE-190](https://cwe.mitre.org/data/definitions/190.html)、[CWE-680](https://cwe.mitre.org/data/definitions/680.html)。
