依頼65では同じ合図に火・月の精霊が異なる結果を返し、同じ種類の２体が別の力を持つ。依頼521では種類を選んで２体を作り、個別に操作する。クラスや継承の実装をプレイヤーが作るわけではなく、種類と状態を持つ簡略モデルである。

依頼512は初期２×２の長方形と、横・縦の変更で常に両辺を等しくする正方形を、横４と縦３の変更を２順序で試す。長方形はどちらも４×３、正方形は横→縦で３×３、縦→横で４×４。同じ操作名でも、変更していない辺を保つ契約を正方形の操作が破る例を扱う。読み取りのみや均等な拡大など、別の契約なら結論は異なり得る。一般の実装・証明は評価しない。[Liskov・Wing の振る舞いによるサブタイプ](https://www.cs.cmu.edu/afs/cs/project/venari/www/subtype-toplas.html)を参照。

依頼513は記録がない・権限不足の２種類と正常時を、内側の係の種類別捕捉と外側の捕捉・伝播の選択で比較する。内側で扱われない異常は鍵を返した後に外側へ伝わる。取得・返却・処理が成功する固定模型で、例外階層、後片付けや捕捉処理での新たな例外、実プログラムの回復や安全性は評価しない。[Python の例外と後片付け](https://docs.python.org/3/tutorial/errors.html)を参照。

依頼579は容量０〜５の袋 A・B を初期３・１とし、内部への直接変更の可否と公開操作の範囲検査を４通り比較する。各条件で適切な追加、超過追加、過大な取出し、直接変更を独立に試す。非公開だけでは検査のない操作から不正状態になり、検査だけでは直接変更で回避できる。固定操作の模型で、言語ごとの可視性や任意の実装の安全性は評価しない。[Oracle のアクセス制御](https://docs.oracle.com/javase/tutorial/java/javaOO/accesscontrol.html)を参照。

依頼580では２種類の動きと２種類の合図を、共通の親から４組合せの子クラスを設ける設計と、２＋２の部品を持つ設計で比較。後者は合図を交換できる仕様とし、前者は固定とする。３種類目の合図には、前者は２つの子クラス、後者は１つの部品を追加する仮定。一般に継承や合成のいずれかが常に優れるという主張ではない。実言語の実装や任意の設計は評価しない。参考: [Oracle の継承](https://docs.oracle.com/javase/tutorial/java/concepts/inheritance.html)、[CMU の比較](https://www.cs.cmu.edu/~aldrich/courses/15-214-13fa/slides/04%20Inheritance%2C%20type-checking%2C%20and%20Method%20dispatch.pdf)。

依頼581は Java 風の固定模型。親の案内役に精霊・火の精霊を受ける２操作があり、火の案内役は両方を上書きする。引数の式の宣言型で操作を選び、受け手の実際の種類で実装を選ぶ。６組の結果を確認する。実言語の全てのオーバーロード規則、型変換、曖昧性、静的メソッドは扱わない。[Java 言語仕様 8.4.9](https://docs.oracle.com/javase/specs/jls/se8/html/jls-8.html#jls-8.4.9)を参照。

依頼582では同じ種類の二体 A・B の力を、個体ごとの変数と種類で共有する変数に置く。A 加算→B 読取り→B 加算→A 読取り→A クリア→B 読取りの結果は、個体ごとで０・１・１、共有で１・２・０。１クラス・逐次操作の模型で、クラス初期化、継承や並行更新は扱わない。[Oracle のクラス変数とインスタンス変数](https://docs.oracle.com/javase/tutorial/java/javaOO/classvars.html)を参照。

依頼583は A・B・C の列を２つの独立した反復子で操作する模型。A で A・B を読み、B で A を読んだ後、A 自身の削除で B を除く。A は C を読めるが、B の古い反復子は次の操作で停止し、再作成後に A・C を読む。検出を保証する固定模型であり、Java ArrayList の fail-fast はベストエフォートであり正しさの保証に使えない。削除をサポートしない反復子もある。実言語での開発、並行処理や全実装の振る舞いは評価しない。[Java ArrayList](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/ArrayList.html)、[Iterator](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Iterator.html)を参照。

依頼778は共通祖先を持つ２つの親の指定順と、相反する順序の C3 マージを操作する固定模型。根の後の object は省略し、探索は最初に見つかった技で止める。Python の実際のクラス階層との照合と、一般化の限界は[項目別台帳](coverage-fpl-oop.md)に記録する。

依頼779は精霊の種類と公開操作を調べ、操作札を生成する固定模型。対象の交代後、古い札の操作が対応していなければ実行を止めて更新する。実言語の反射 API と一般のアクセス制御は扱わない。[項目別台帳](coverage-fpl-oop.md)を参照。

依頼780は配達の抽象操作と共通の具体操作を持つ基底に、子の配達実装と鈴のミックスインを組み合わせ、作成可否と振る舞いを予想する。４組合せを実際の Python の抽象クラスと照合した。トレイトや一般の実言語による開発は未評価。[項目別台帳](coverage-fpl-oop.md)も参照。

依頼781は65の精霊と579の袋の模型を再利用する応用依頼。直接変更と範囲検査の比較に加え、独立した二体へ同じ合図を送り、種類ごとの色を確かめる。固定操作に限られ、一般の設計の安全性は評価しない。
