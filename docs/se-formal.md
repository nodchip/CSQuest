依頼242は精霊Ａ・Ｂが各自「外、確認後、部屋の中、退出済み」を順に一度だけ進む有限模型。相手が部屋にいる間は外から確認後へ進めない。「別々」では確認後に再確認せず入室でき、Ａ確認・Ｂ確認・Ａ入室・Ｂ入室が同時入室の反例となる。「一つにする」では入室時にも相手がいないことを原子的に確認するため、到達可能状態に同時入室はない。探索は安全性のみを扱い、実装の正しさ、無限の動き、公平性や進行性は証明しない。

依頼243は在庫と依頼数を０〜３に限る16組について、正常・数不正・在庫不足の結果と残数を契約に照らして比較する。「在庫３・依頼１」の一件は４通りの規則ですべて成功するが、０の拒否や在庫と同数の許可に欠陥がある規則は他の入力で反例が出る。有限範囲の網羅は、負の値、範囲外、同時更新や実際のプログラムの正しさを保証しない。

依頼244は二人が赤・青の鍵をそれぞれ一度ずつ取得し、両方を持った後に返す有限模型。逆順ではＡが赤、Ｂが青を取得した後、互いに次の鍵を待つ状態が到達可能。同じ順序では到達可能な未完了の行き止まりはない。各鍵の排他は両方の模型で保たれる。無限の実行、公平性や実プログラムの進行性は評価しない。

依頼349は３ビットの鍵を手動で変異させ、鍵６の故障を観察する。故障の分岐を含む模型と省いた模型のそれぞれについて０〜７の全入力を調べ、観察した扉の結果と比べる。模型の網羅検査が示すのはその模型・範囲についての性質で、模型が対象と一致する保証はない。参考：[Lamport の仕様と実システムの違い](https://lamport.azurewebsites.net/pubs/high-level.pdf)、[LLVM の libFuzzer](https://llvm.org/docs/LibFuzzer.html)。この例は実際の自動ファザー・検査器や一般のプログラムを扱わない。
