# SPD-Interactive: 対話型計算プラットフォーム

出典：[CS2023 印字 pp.308–309](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。すべて Non-core。固定模型の操作は、実際のノートブック、分析サービス、AI、量子プラットフォームの利用能力を評価しない。

| トピック | 対応と不足 |
|---|---|
| 1a データ分析プラットフォーム・ノートブック | 依頼357で三つの頁と保存状態の固定模型。実際のツール、コードやデータの取込みは未対応 |
| 1b クラウド SQL・分析基盤、分散処理、可視化 | 依頼111・112で固定の表示、357で平均の棒を表示。実際のクラウドや分散分析は未対応 |
| 1c データを用いた対話型プレゼンテーション | 依頼357で場所の切替と図の更新。プレゼンテーションの作成は未対応 |
| 1d 低遅延の反応を必要とする描画・グラフィック設計ツール | 未対応 |
| 2 生成 AI・大規模言語モデルへのプロンプト | 未対応 |
| 3a–b 量子演算のプログラム・量子サービスの API | 依頼74で固定の量子状態の操作。量子サービスの実利用は未対応 |
| 3c 信号・フーリエ解析・音声や無線の処理 | 依頼175で４点の固定フーリエ変換。実際の信号処理は未対応 |

依頼357では森の収穫２・６の平均が４、村の４・８の平均が６。各頁は前の頁が保存した値を使うため、場所だけを変えて平均と図を再実行すると古い森の結果が残る。状態がノートのセル間で保持される仕組みは [Jupyter の説明](https://docs.jupyter.org/en/latest/what_is_jupyter.html)、実行順による隠れた状態は [Jupyter Blog](https://blog.jupyter.org/posts/2021/ploomber-maintainable-and-collaborative-pipelines-in/) を参照した。
