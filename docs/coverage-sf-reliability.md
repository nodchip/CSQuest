# SF-Reliability：項目別の対応状況

原典は [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.296。番号と区分を原典に合わせ、既存の依頼の実装・検証と照合した。[追跡方法](coverage-status.md)に従い、「部分」は記した固定例があることを示し、原典項目全体の完成を示さない。親のトピック３とその子を同時に数えない。原典のこの単位に Non-core の項目は列挙されていない。

## トピック

| 番号 | 区分 | 要約 | 状態 | 対応する体験と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | バグ・故障・障害の区別 | 部分 | 依頼23で門の書き間違い、記憶破損、内部結果と約束違反を比較。一般の分類と障害連鎖は未評価。 |
| 2 | CS Core | 信頼性と可用性 | 部分 | 依頼108で同じ稼働割合の２記録と４刻連続の航海を比較。一般の確率モデルや将来の推定は未対応。 |
| 3a | CS Core | 確認と再試行 | 部分 | 依頼10・62で消失後の再送と重複の固定例。一般の障害対処は未評価。 |
| 3b | CS Core | 冗長符号化 | 部分 | 依頼106・107でハミング符号、全体パリティ、CRC を操作。一般の FEC と RAID は未対応。 |
| 3c | CS Core | 複製・ミラー | 部分 | 依頼229で装置故障と誤更新を比較。非同期複製・分断時の復旧全般は未評価。 |
| 4 | KA Core | 冗長化以外の方法、ジャーナリングなど | 部分 | 依頼136で先行ログの前後値・確定印から単一送金を復旧。ファイルシステムのジャーナリングや一般の復旧手法は未評価。 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応する体験と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | プログラム・システムの誤り、ハードウェア故障と例外を区別 | 部分 | 依頼23で書き間違い、記憶破損、０除算の固定例を比較。一般的な説明や自由記述は評価しない。 |
| 2 | CS Core | 検出・処理・復旧の違いと実現方法を説明 | 部分 | 依頼23の検出・代替、依頼229・136の復旧は固定模型。方法の一般的な分類と自由な説明は未評価。 |
| 3 | CS Core | メモリ・記憶装置・ネットワークにおける誤り検査と訂正符号の役割を説明 | 部分 | 依頼106・107で伝達時の符号と訂正・検出を操作。各媒体の実際の使用例や自由な説明は未評価。 |
| 4 | CS Core | 冗長情報を使う簡単な訂正手順を適用 | 部分 | 依頼106の７ビット符号で固定の単一誤りを訂正。任意の符号や一般的な手順の構築は評価しない。 |
| 5 | KA Core | 検出・訂正方式のデータ量、実装の複雑さ、符号化・検出・訂正に要する相対時間を比較 | 部分 | 依頼107で４ビットのデータから７ビットの CRC と８ビットの訂正符号を扱い、検出と訂正を区別。符号化・検出・訂正の時間や実装の複雑さの比較は未対応。 |

依頼23、106–108、136、229 の模型と限界は [既存の記録](sf-reliability.md)と[先行ログの記録](dm-internals.md)に記載。自動検証はそれぞれ `tests/fault-lab.test.js`、`tests/hamming.test.js`、`tests/secded.test.js`・`tests/crc-lab.test.js`、`tests/availability.test.js`、`tests/wal-recovery.test.js`、`tests/mirror-recovery.test.js` を参照。テスト成功は原典の成果全体の達成を意味しない。
