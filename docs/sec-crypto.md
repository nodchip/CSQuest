依頼58は同じ４ビット鍵の再利用により、既知の平文と暗号文から別の平文を復元する例。別鍵の操作は安全な乱数生成を再現せず、XOR 自体は完全性を保証しない。実際の暗号システムの実装や安全性の証明ではない。

依頼128は実際の暗号を使わず、署名者・署名時の本文・検証鍵を固定した模型。公開鍵と本人の対応が確認済みで秘密鍵が漏れていないと仮定し、改変・別鍵・別人による署名を比較する。署名は機密性を提供しない。実用上は鍵の認証・保護や安全な実装が必要。参考: [NIST Digital Signature](https://csrc.nist.gov/glossary/term/digital_signature)。

依頼426は６文字の環でシフトの全候補を比較し、既知の最初の印により候補を選ぶ。[MIT の講義資料](https://ocw.mit.edu/courses/6-1200j-mathematics-for-computer-science-spring-2024/mit6_1200j_s24_lec10.pdf) のシフト暗号を参考にした教材用模型であり、安全な通信には使えない。短い暗号文のみでは元の文が一意に決まらない場合がある。

依頼259・260は法55・公開指数３の決定的な教科書的 RSA。候補１〜４の暗号文はそれぞれ１・８・27・９で、公開鍵を使って候補を照合できる。極小の鍵や決定的な暗号化は安全でなく、実用方式を再現しない。参考：[Stanford、RSA の講義](https://crypto.stanford.edu/~dabo/courses/cs255_winter18/lectures/rsa.pdf)。

依頼261は法23、底５、秘密６・15による直接交換と、秘密７の中間者による差し替えを比較する。直接の共通値は２、差し替え時の両者の値は12・15で、中間者はそれぞれを計算できる。認証済みの公開値は仮定であり認証プロトコルは実装しない。極小の法は盗聴に対しても安全でない。参考：[Boneh と Shoup、Applied Cryptography](https://crypto.stanford.edu/~dabo/cryptobook/BonehShoup_0_5.pdf) §10.7。

依頼262は公開の単純な指紋と、鍵を知らない人物の一つの推測が失敗すると仮定した印の表を比較する。本文と印の置換や古い伝令の再送を扱うが、暗号学的ハッシュや MAC の演算、偽造確率、再送防止の実装ではない。参考：[NIST Message Authentication Codes](https://csrc.nist.gov/Projects/message-authentication-codes)。

依頼263は本文だけ、または本文と番号を認証すると仮定する２方式を比較する。受け手は次の番号のみ受け入れ、成功時だけ次へ進む。番号を認証しない方式では、受取済み伝令の番号を変更して再受理できる。厳密な順序に限る架空の模型で、実際の MAC、再起動、損失や順不同を扱わない。参考：[RFC 4303](https://www.rfc-editor.org/rfc/rfc4303) の再送検出は、実際には順不同を考慮する窓を使用する。

依頼264は８種類から独立・一様に選ぶ１〜９個について、任意の２つの衝突と、指定の１種類の出現を比較する。４個ではそれぞれ約58.98%と41.38%。実際のハッシュ関数や攻撃に対する安全性は評価しない。参考：[Boneh と Shoup、Applied Cryptography](https://crypto.stanford.edu/~dabo/cryptobook/BonehShoup_0_5.pdf) 付録 B.1。

依頼598は依頼426と同じ６印のシフトを、方式と平文・暗号文の一組を知る仮定で調べる。２→５なら鍵３、鍵の変更後に２→１なら鍵５が一致する。小さい候補集合と既知平文による固定例であり、変更した鍵の安全性を一般に評価しない。方式の公開だけで安全とは限らず、独自方式の回避、評価された方式・保守される実装と鍵管理を選ぶ。[OWASP の暗号利用](https://top10proactive.owasp.org/archive/2024/the-top-10/c2-crypto/)を参照。実際の暗号、認証付き暗号、鍵の生成・配布・運用や自由な議論は扱わない。

依頼599は依頼259・260と同じ教材用 RSA で、55＝５×11、互いに素な剰余の個数40、指数３の逆数27を選ぶ。12の３乗は法55で23、23の27乗は12。指数５は40と互いに素でなく、２と７の５乗はいずれも32になる。因数から40と秘密指数を求められるが、因数分解だけが攻撃法とは主張しない。全55剰余で復号を検査。[Stanford の RSA と合同算術](https://crypto.stanford.edu/pbc/notes/numbertheory/order.html)、[NIST の鍵確立](https://csrc.nist.gov/pubs/sp/800/56/b/r2/final)を参照。極小の決定的模型であり、実用上のパディング・鍵生成・実装や安全性は評価しない。

依頼600はブラウザの Web Crypto API に公開の固定 AES-128 鍵、４バイトの固定平文２通と96ビットの固定初期値を渡し、GCM の暗号文と128ビットタグを計算する。同一鍵・初期値の再利用で暗号文の XOR が平文の XOR と一致する例、初期値が異なる固定例、暗号文の１ビット改変による認証失敗を比べる。別の初期値でも偶然の一致はありうるため、不一致は安全性の証明ではない。AES-GCM の既知入力・出力例、４条件と改変拒否を自動検査し、公開サイトと API 不可時も検証する。[NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)、[MDN の AES-GCM 初期値](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)を参照。固定鍵と固定初期値は教育用であり、実際のデータを保護せず、AES 内部・鍵生成・配布・一般的な安全性は評価しない。

依頼601は公開された固定本文 ABC・ABD と教材用固定鍵を Web Crypto に渡し、SHA-256 と HMAC-SHA-256 を比較する。元の本文、本文だけ改変、本文と印を作り直す、古い本文と印を再送する８条件を試す。変更した本文の公開ハッシュは誰でも計算し直せる一方、この実験で異なる鍵を使った HMAC は検証に失敗する。再送は両方式とも印だけでは拒否しない。HMAC は暗号化や再送防止ではなく、共有鍵を持つ者同士も区別しない。公開固定鍵は実データを守らない。[RFC 4231](https://www.rfc-editor.org/rfc/rfc4231) と [NIST HMAC](https://csrc.nist.gov/pubs/fips/198-1/final)を参照。RFC の既知入力・出力、８条件、API 不可時と非同期計算中の条件変更を検査。実際の鍵管理・一般の攻撃や実装の安全性は未評価。

依頼602は Web Crypto で実験ごとに P-256 の二組の一時鍵を生成し、固定本文に ECDSA/SHA-256 署名を作る。元の本文、本文改変、署名改変、別の公開鍵、別人の署名と鍵への差替え、同じ署名の再検証を操作する。差替えた署名はその人の公開鍵で通るが、それがミラの公開鍵であることは確認されていない。同一の署名と本文の再検証は通り、新しさの保証には別の仕組みが必要。鍵と本人の対応は模型の仮定で、実在の本人認証・証明書・鍵管理は行わない。Web Crypto の生成署名を Node の公開鍵検証とも照合し、API 不可や非同期条件変更を検査。[NIST FIPS 186-5](https://csrc.nist.gov/pubs/fips/186-5/final)、[MDN 署名](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/sign)を参照。

依頼603は Web Crypto の P-256 ECDH、HKDF-SHA-256 と AES-GCM を使い、直接交換と中間者による両方向の公開鍵差し替えを比較する。後者では中間者が復号し別の鍵で再暗号化して中継する。事前に相手の公開鍵を確認できたと仮定すると、受け取った鍵との比較により今回の差し替えを検出できる。固定の HKDF 情報と実験用の一時鍵を用いる限定例であり、本人認証、証明書、鍵管理や実用の通信プロトコルは実装しない。[NIST SP 800-56A](https://csrc.nist.gov/pubs/sp/800/56/a/r3/final)、[RFC 5869](https://www.rfc-editor.org/rfc/rfc5869)を参照。

依頼604は法11で秘密 s と係数 a を０〜10から選び、(x, s + ax mod 11) の３欠片を作る。全121組について、一欠片は11個の秘密それぞれに対応する係数があり、異なる番号の二欠片は１組に決まることを列挙して検査する。続いて秘密を伏せた３例に対し、候補から最初の欠片に合う係数を求め、二つ目と照合して復元する。秘密に依存しない一様な係数の選択には０を含める必要がある。プレイヤーが係数を選んで全値を表示する教材であり、安全な乱数や秘匿・認証された配布、欠片の改ざん検出は行わない。[Shamir の原論文](https://dspace.mit.edu/entities/publication/91c51bfc-5678-409c-80c5-44ce8fcdbadf)参照。

依頼605は６ビットの BB84 風の固定例で送受信の基底を照合し、一致した４個から２個を公開して比較する。途中で別の基底により測定して送り直す影がいる場合、固定した測定結果では１・３番に不一致が生じるが、４・６番の標本では見逃す。公開したビットは残りから除く。測定結果を固定した模型であり、確率分布、量子装置、誤り訂正、プライバシー増幅、認証や有限長の安全性評価は実装しない。雑音でも不一致が生じるため、一般に不一致だけから盗聴を断定できない。[IBM Quantum の量子鍵配送](https://quantum.cloud.ibm.com/learning/en/modules/computer-science/quantum-key-distribution)参照。
