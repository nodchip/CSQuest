# DM-Processing の対応

原典: CS2023 p.118–119。依頼89は固定の８行について、索引なし、種類、種類→値段、値段→種類の４つのアクセス方法を比較する。先頭列の等値条件とその次の範囲条件までを使う単一の連続範囲を模型化し、スキップスキャンは実装しない。候補数には索引の探索費用、元の行の読取り、更新や記憶領域を含めず、実時間の優劣を主張しない。参考: [PostgreSQL の複合索引の説明](https://www.postgresql.org/docs/current/indexes-multicolumn.html)。

例示学習成果 8 は固定した２条件と候補数での比較に限る。依頼662は葉の探索と範囲走査を部分的に扱う。他の学習成果は未対応。実際の索引作成、実行計画の解釈や性能を評価する能力は直接評価しない。

依頼662は葉に２鍵、案内頁に２境目までの B+ 木に６つの一意な整数を任意順で追加する。葉の右側最小値を親に伝え、案内頁のあふれを上へ伝播し、葉を次の葉につなぐ。等値２件と範囲検索を扱い、索引頁数と固定３頁の全走査を比較。全720挿入順の各段階で順序・境目・同じ葉深さ・葉の連結を、各範囲の検索結果を独立に照合した。重複、削除、実データ頁へのアクセス、キャッシュ、実機性能は未対応。[PostgreSQL: B-Tree Structure](https://www.postgresql.org/docs/current/btree.html)。

依頼663は容量２の桶、下位ビットで指定する案内表、深さに応じた倍化・分割を扱う。６札の全720挿入順で各段階の桶容量・深さ・参照数・配置と３検索を検査。等値は対応する桶、範囲は全桶を読み、B+ 木との特徴の違いを示す。削除、同一ハッシュの大量衝突、実際のディスクや実装の速度は未対応。[CMU: Extendible Hash Index](https://15445.courses.cs.cmu.edu/spring2024/project2/)。

依頼664は４人と５依頼の固定データで、内部結合の前後に人の条件を適用し最後に依頼番号を取り出す２計画、および左外部結合の前・結合条件・結合後に右側の条件を置く３計画を比較する。内部結合の結果はどちらも甲・乙で、単純な総当たりの番号照合は10回と20回。左外部結合では右側を事前に絞る場合と結合条件が同じ行を返し、結合後に絞ると準備前のみの B と依頼のない C が落ちる。実行時間、他の結合方法や一般の問合せ変換は扱わない。[PostgreSQL: Table Expressions](https://www.postgresql.org/docs/current/queries-table-expressions.html)。

依頼665は１頁１札の８頁を３・４頁の机でそれぞれ初期整列し、入力用 B−1 頁と出力用１頁で列の先頭を選びながら併合する。余った１列も各回で読み書きする模型では、３頁の机は初期整列と２回の併合で計48頁の読書き、４頁では初期整列と１回の併合で計32頁。実際の頁容量、キャッシュ、一時列の書戻し省略や実機性能は扱わない。[CMU: Sorting & Aggregation](https://15445.courses.cs.cmu.edu/spring2026/notes/11-queryI.pdf)。

依頼666は４人と５依頼の内部等値結合を、２で割った余りを使う２桶のハッシュ結合として操作する。人を構築側にすると４行、依頼を構築側にすると５行を桶に入れ、いずれも候補の元の番号を10回照合し、重複する番号１の２依頼を含む４組を返す。両結果を独立した総当たりと照合。実際の記憶量、NULL、メモリ不足、外部結合と実行速度は扱わない。[CMU: Join Algorithms](https://15445.courses.cs.cmu.edu/spring2024/notes/11-joins.pdf)。

依頼89では２問い合わせの条件確認・候補数に基づく計画・実行・返却の順序も操作する。固定模型であり、実際の SQL 構文解析や最適化器は評価しない。
