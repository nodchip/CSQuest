# SPD-Common：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.302–303。[既存の調査](spd-common.md)と依頼を照合。すべて CS Core。[追跡方法](coverage-status.md)の「未照合」は未実装を意味しない。分類だけの親は重複計上せず、１のプラットフォーム全体の概要は子項目にない内容として別に追跡する。

## トピック

| 番号 | 内容 | 状態 | 対応と限界 |
|---|---|---|---|
| 1-本体 | Web・モバイル・ゲーム・ロボット・組込み・対話型の各開発プラットフォームの概要 | 未照合 | 複数プラットフォームを見渡す教材と検証を確認する。子項目が扱わない概要を追跡する。 |
| 1a | 入力・センサー・操作・触覚機器 | 部分 | 219〜222 で光センサーの固定模型、351 で画面上の入力。実機や触覚機器は未評価。 |
| 1b-i | 計算資源の制約 | 未照合 | 計算能力・費用に関する体系的な比較の確認が必要。 |
| 1b-ii | 保存資源の制約 | 未照合 | 固有プラットフォームの保存容量・制約の照合が必要。 |
| 1b-iii | メモリの制約 | 未照合 | 固有プラットフォームのメモリ制約の照合が必要。 |
| 1b-iv | 通信の制約 | 部分 | 354 の圏外と再送、356 の送信回数・待ち時間の模型。実環境は未評価。 |
| 1c | 安全性・可用性・耐障害性などの要件 | 部分 | 353 は復旧と訓練の固定例。全プラットフォームの要件は未評価。 |
| 1d | 出力・駆動・触覚機器 | 部分 | 219 はセンサーから角度指示を出す固定模型。実機と触覚機器は未評価。 |
| 2 | 固有 API と従来のアプリ構築 | 部分 | 354 の通信断と再送の固定模型。実 API によるプログラミングとの比較は未評価。 |
| 3 | プラットフォーム向け言語の概要 | 部分 | 1289で Web の HTML・CSS・JavaScript の固定例を比較。他のプラットフォームの言語や実際の記述は未評価。 |
| 4 | プラットフォームの制約・要件下でのプログラミング | 部分 | 356 で固定の通信・待ち時間制約を比較。実際のプログラムと安全性は未評価。 |
| 5 | 固有言語の学習・習熟方法 | 未照合 | 学習方法と実際の習熟の照合が必要。 |

## 例示学習成果

| 番号 | 内容 | 状態 | 対応と限界 |
|---|---|---|---|
| 1 | モバイルプログラミングの制約を列挙 | 部分 | 354・356 で通信断と遅れを操作。他の制約や自由な列挙は未評価。 |
| 2 | スクリプト言語の特徴を列挙 | 未照合 | 言語の特徴と比較を確認する必要がある。 |
| 3 | Web の３層モデルを説明 | 部分 | 803 で画面・処理・データの役割と固定の申込みを操作。一般の構成や自由な説明は未評価。 |
| 4 | Web の状態維持を説明 | 部分 | 354 の端末内の送信待ち、804 の Cookie とサーバー側の記録による状態維持の模型。実装や他の方法は未評価。 |

依頼803では在庫２個の台帳に対し、１個と３個の申込みを別々に扱う。表示層から処理層へ要求し、処理層は台帳を読んで判定し、受理する場合だけ在庫を更新して結果を返す。両分岐で各段階の誤操作と途中復元を検査した。これは一例であり、役割を必ず別の機械に配置することや、全 Web アプリが３層であることを意味しない。同時更新、認証、障害や実サービスの構築は未評価。参考：[Microsoft: ３層の役割](https://learn.microsoft.com/en-us/windows/win32/cossdk/using-a-three-tier-architecture-model)。

依頼804は２端末とサーバー側の記録を操作し、同じ番号での再訪、別端末の分離、端末側の番号削除とサーバー側の期限切れを比べる。番号は説明用の連番で、実際の Cookie・認証・安全なセッション管理は実装しない。参考：[MDN: HTTP Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies)。
