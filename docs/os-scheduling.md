# OS-Scheduling の対応状況

出典: [CS2023, Operating Systems, OS-Scheduling](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 209–210。原典を要約した作業用一覧。方式の一例を操作したことは、この知識単位全体の習得を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | KA Core | プリエンプティブと非プリエンプティブの方式 | 試作：１時間ごとに交代する方式と、完了まで継続する方式の比較。依頼176で途中到着と２種類の切替え費用を考察。一般的な割込みや実 OS の費用は未対応 |
| 2 | KA Core | 先着順、最短ジョブ優先、優先度、ラウンドロビン等 | 依頼14で先着順と量子１のラウンドロビン、134で優先度継承、569で最短ジョブと最短残り時間の固定例。他の方式や一般の負荷は未対応 |
| 3 | KA Core | 対称型マルチプロセッサのスケジューリングとキャッシュの一貫性 | 依頼624で２炉の負荷分散とキャッシュ親和性を比較。一貫性の一般的な扱いと実装は未対応 |
| 4 | KA Core | タイマー | 依頼623で２刻のタイマー、到着と仕事の交代を比較。実装や割込みの細部は未対応 |
| 5 | KA Core | 公平性と飢餓 | 依頼177で固定優先度の飢餓と待機に応じた優先度上昇の固定例。一般的な公平性の評価や保証は未対応 |
| 6 | Non-core | 省エネルギー・リアルタイムのスケジューリング | 依頼133で２仕事の期限と順序の固定例。省エネルギーと一般の方式は未対応 |
| 7 | Non-core | 協調的なスケジューリング | 依頼623で自発的な譲渡の有無を鐘の有無と比較。一般の協調的方式は未対応 |

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | KA Core | 一般的な方式の優先度、性能、公平性を比較 | 依頼14で３仕事の完了時刻、134で優先度継承、569で２方式の到着から完成までの時間を比較。他の方式や多様な負荷は未対応 |
| 2 | KA Core | 方式とアプリケーション分野の関係を説明 | 未着手 |
| 3 | KA Core | 短期・中期・長期・I/O スケジューラの違いを説明 | 依頼625で受付、CPU 割当て、退避・復帰とディスク要求の選択を操作。一般的な方式や自由記述は未対応 |
| 4 | KA Core | 非対称・対称マルチプロセッシングの適否を評価 | 依頼626で固定指揮役と対等な処理装置を、仕事数と故障の固定条件で比較。一般的な性能・実システムの復旧は未対応 |
| 5 | KA Core | プロセスとスレッドの適否を評価 | 依頼627で同じ値の参照、明示的通信、プロセス終了時の固定例を比較。一般の設計・障害や自由記述は未対応 |
| 6 | KA Core | プリエンプションや期限付きスケジューリングが有益な状況 | 依頼133で期限内の仕事順序、176で途中到着の仕事の完了時刻と切替え費用の固定例。多様な負荷や一般的な適用条件は未対応 |
| 7 | Non-core | 同様の順番付けの考え方を他の OS 機構や計算機以外へ応用 | 工房の炉の例のみ。一般化した比較は未対応 |

依頼14は全仕事が時刻０に到着し、交代の費用と I/O 待ちがない固定シナリオ。現実の OS の性能を予測するものではない。

依頼134では時刻０に低優先度が鍵を持ち、時刻１に高・中優先度が到着する。高は鍵を待ち、中は鍵を使わない。継承なしでは中の３刻の後に低が鍵を返し、高の完了は時刻６。継承ありでは低が先に鍵を返し、高の完了は時刻３。単一鍵・１待機者・切替費用なしの模型。参考: [FreeRTOS Reference Manual, mutexes](https://www.freertos.org/media/2025/FreeRTOS_Reference_Manual_V8.2.1.pdf)。

依頼569は A=(到着0,時間8)、B=(1,4)、C=(2,2)、単一炉・切替費用なし・仕事時間既知の固定例。非割込みの最短ジョブ優先では完成時刻 A=8・C=10・B=14、滞在時間合計29。最短残り時間では C=4・B=7・A=14、合計22。各刻の選択と履歴を検査する。予測誤差、切替費用、I/O、一般的公平性や飢餓は扱わない。参考：[OSTEP、Scheduling](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched.pdf)。

依頼623は時刻０から６刻の A、時刻２到着で１刻の B を用いる。鐘なしで A が通算４刻後に譲る場合の実行順は AAAABAA、譲らない場合は AAAAAAB。２刻ごとに制御を取り戻し、待つ B を優先する鐘ありでは両方 AABAAAA。到着を同時の鐘より先に扱い、費用・I/O 待ちは０とする。タイマー自体と OS の選択を区別し、実際の公平性や期限を保証しない。[OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-mechanisms.pdf)。

依頼624は２炉と２仕事の固定模型で、各仕事は記録の残る炉なら２刻、もう一方なら３刻。同じ炉では A の後に B を処理し、別々なら並行する。A・B の記録が別炉にある場合、割当て 00・01・10・11 の全仕事の完了時刻は５・２・３・５。両記録が炉１にある場合は４・３・３・６。各試行は同一初期状態から始め、記録の追出し・資源競合・一貫性と切替え費用は扱わない。[OSTEP: Multiprocessor Scheduling](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched-multi.pdf)。

依頼625は受付待ちの２仕事を入場し、A をディスク待ち中に退避、B も要求してから装置の処理を選ぶ。A の要求は位置70、B は12、針は10から開始。先着順 A→B の移動は60＋58＝118、近い要求から B→A は２＋58＝60。A は I/O 完了後も退避中で、復帰後に CPU を使う。退避中も装置が I/O 領域にアクセスできる仮定で、費用や一般の装置・公平性は未対応。[Illinois: Scheduling](https://cs341.cs.illinois.edu/coursebook/Scheduling)、[OSTEP: Hard Disk Drives](https://pages.cs.wisc.edu/~remzi/OSTEP/file-disks.pdf)。

依頼626は同じ能力の炉番２人と２刻の仕事を使い、指揮役専用の炉番１・実行専用の炉番２を置く方式と、稼働中の炉番が共有待ち列から実行する方式を比較する。前者は指揮費用０、後者は開始時同期１刻と仮定。仕事１件の完了は２・３刻、２件では４・３刻。開始前に１番が故障した場合、前者は代役なしで停止、後者は共有待ち列が無事なら２番のみで５刻。固定費用と限定した故障の模型であり、方式一般の性能や可用性を保証しない。[UIC: Multiple-Processor Scheduling](https://www.cs.uic.edu/~jbell/CourseNotes/OperatingSystems/5_CPU_Scheduling.html)。

依頼627は同一プロセスの２スレッド、別プロセスで通信なし、別プロセスで値を送る３場面を比較。A が０から１に更新した後、B の３回の読みはそれぞれ (１,１,終了)、(０,０,０)、(０,１,１)。３回目は A の属するプロセス全体を終了した後。正常なスレッド単独終了と区別し、別プロセスの共有メモリや並行更新時の同期の必要性を明示。通信は成功すると仮定し、一般の性能・障害は未評価。[OSTEP: Concurrency](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-intro.pdf)。
