# NC-Routing：宛先の先頭と転送（部分対応）

[CS2023 原典](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.199–200、NC-Routing 2 の転送表と照合の入口。現行の中継塔は配送・名前解決・再送を扱う。旧依頼61 `prefix.js` は８ビットと IPv4 の最長接頭辞一致を扱い、今回との重複を独立した完成範囲として二重計上しない。

４ビットの架空宛先で、空接頭辞→Ｒ、10→Ａ、101→Ｂ、0→Ｃ。空接頭辞は全てに一致し、複数一致なら最も長い接頭辞を選ぶ。1011は空・10・101に一致しＢ、1001はＡ、0110はＣ、1110は既定のＲ。`tests/endgame-route-prefix.test.js` は４件の操作と全16宛先を独立な期待値表と照合する。

参考：[RFC 1812, Section 5.2.4](https://www.rfc-editor.org/rfc/rfc1812#section-5.2.4) の最長一致。固定４ビットの模型で IPv4/IPv6 のヘッダー、表の構築、同長候補、通信障害・実経路や実装・自由な説明は評価しない。NC 全体の完成を示さない。

実装担当とは別の `review_candidate` が原典・RFC、全16宛先の期待値、画面の前提、誤答・履歴、分類と開放、旧記録の既定値を確認した。関連６テストも成功した。実網・実装を検証したものではなく、レビュー担当自身はブラウザを操作していない。

`scripts/endgame-route-prefix.playwright.js` は集いと４地域の達成状態を用意した検証用記録から、213・390・1200 px 幅で分類経由の到達、キーボード操作、誤答案内、途中保存・再開、段階開放と達成後の再開を確認した。新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者による面白さの評価は未確認。
