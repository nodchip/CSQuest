# 項目別評価：NC-Mobility の端末間通信と遅延耐性

2026-11-05 に [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.201、依頼316の実装と試験、公開版の操作を照合した。対象はトピック３・４と例示学習成果３・４の４行。

## 評価 — いずれも部分対応

原典は端末間通信と複数区間の無線を挙げ、実用例や移動ネットワークの説明を求める。依頼316は３人の固定接触予定に沿って１通を手渡し、接続のない時間は中継者が保持する３例で、直接の受渡しと途切れる接続での中継を扱う。NASA の ISS 実験装置から地上への転送事例と模型を比較するが、実際の端末発見や無線、一般の方式と自由な説明は扱わないので４行とも部分とする。

[RFC 9171 §1](https://www.rfc-editor.org/rfc/rfc9171.html#section-1) の断続的接続に対応する保存・運搬・転送の考え方に沿うが、これは Bundle Protocol の実装ではない。予定が事前に分かり、転送が必ず成功し、手紙を移すと元の人は保持しないという模型で、複製、経路選択、配送保証、期限、認証や障害は評価しない。

`tests/delay-tolerant.test.js` の４件で全選択列、受渡し不能、復元と達成条件を確認。390px幅の公開版で会えない相手への誤操作、再読込後の途中再開、２経路の配達と解説を確認し、横あふれはなかった。

NASA の[実例](https://ntrs.nasa.gov/archive/nasa/casi.ntrs.nasa.gov/20190028812.pdf)は中継衛星の切替えと通信の遅延を背景に、接続可能なときの保存・転送を扱う。事例の３択について誤答・説明・修正と途中再開を390px幅の配信用ビルドで確認した。実際の経路や運用全体を再現するものではない。

接触順序を変えた３つ目の場面では、出発者が待って直接渡すと２刻目、中継者に預けると３刻目に届く。２経路と途中再開を390px幅で確認。接触予定は既知であり、一般の経路選択や伝送の失敗は評価しない。
