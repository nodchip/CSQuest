# OS-Protection：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.209。[追跡方法](coverage-status.md)に従う。原典の７トピック・４例示学習成果を記録し、トピック６の例示概念は別行で追跡する。親子を集計時に重複させない。固定模型は実 OS の安全性を保証しない。

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 体験と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | OS の保護と安全性の機構が必要な理由を理解 | 部分 | 54・180で保護対象と経路を扱う。実 OS の脅威全体は未評価。 |
| 2 | CS Core | OS の脆弱性を利用する攻撃経路を列挙・説明 | 部分 | 180で３経路、491で脆弱性の概要と架空模型を比較。一般の列挙や自由記述は未評価。 |
| 3 | CS Core | OS 資源のアクセス制御機構を理解 | 部分 | 11・54・490で権限と方針・機構の固定例。実 OS の機構は未評価。 |
| 4 | KA Core | OS の安全性に関係する機能・限界を要約 | 部分 | 180で各対策の前提と限界。体系的な要約や自由記述は未評価。 |

依頼180・490・491の前提と限界は [OS-Protection](os-protection.md)、依頼754の仮想化の模型は [OS-Virtualization](coverage-os-virtualization.md) を参照。`tests/access.test.js`、`tests/syscall.test.js`、`tests/policy-mechanism.test.js`、`tests/race-cow.test.js`、`tests/vm-trap.test.js` 等は模型の一部を検査し、原典の範囲全体の達成を意味しない。
