# SDF-Practices の対応状況

出典: [CS2023, Software Development Fundamentals, SDF-Practices](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 232。原典を要約した作業用一覧。ゲーム内の操作は実際の開発環境や文章作成の能力を評価しない。

## トピック

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | テストケース設計を含む基本的なテスト | 依頼23で境界を含む試験の選択、198で４つの列を試す固定例。実際のモジュールのテスト作成は未対応 |
| 2 | CS Core | 汎用 IDE とデバッガの利用 | 依頼198で反復の状態を追う固定模型。実際の IDE とデバッガは未対応 |
| 3 | CS Core | 読みやすさを高めるプログラミングスタイル | 依頼555で用意された名前・注釈・字下げを選び、３例の動作と照合。一般のプログラム作成は未対応 |
| 4 | CS Core | モジュールの機能を自然言語で仕様化 | 依頼523で候補の説明を選び振る舞いと照合。自由な文章作成は未対応 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | モジュールのテストを作り、複数の設計戦略を適用 | 依頼23で固定された試験候補を選択。実際のテストの記述や広い戦略は未対応 |
| 2 | CS Core | プログラムのテストの限界を説明 | 依頼23で欠陥があっても一部の入力では表面化しない例、198で４つの列の試行が一般的な証明ではないことを扱う。自由な説明は未対応 |
| 3 | CS Core | IDE とデバッガでビルド・実行・デバッグ | 依頼198で状態の記録を読む固定模型。実際の開発環境の操作は未対応 |
| 4 | CS Core | コメント、字下げ、名前などのスタイルを適用 | 依頼555で候補を選び、名前と注釈を動作に合わせ、字下げによる処理範囲を比較。自由な記述や他の言語の構文は直接評価しない |
| 5 | CS Core | モジュールの機能をコメントで仕様化 | 依頼523で候補の説明を選び照合。文章を書く演習は設けず、コメント作成能力は直接評価しない |

依頼555は非負の石の重さを合計し、空なら０を返す架空の指示書。名前・注釈・返す行の字下げを候補から選ぶ。返す行が繰り返しの中なら [2,3] は２、空列は値を返さず、繰り返しの後なら５と０。名前と注釈は動作を変えず、記述の正しさと読みやすさを３つの例で比較する。言語によって字下げの意味は異なり、有限例の一致は証明ではない。実際に名前やコメントを書く能力は評価しない。参考：[PEP 8](https://peps.python.org/pep-0008/)、[Google Go Style Guide](https://google.github.io/styleguide/go/guide.html)。
