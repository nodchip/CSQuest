# SE-Refactoring：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.249–250。[既存調査](se-refactoring.md)と依頼・検査を照合。状態は[追跡方法](coverage-status.md)に従う。「未照合」は未実装の証拠ではなく、「部分」は項目全体の完成を意味しない。原典の細目を分けた場合、親と子は数値上で重複計上しない。実際の開発・協働・自由な説明やコード記述の能力は固定例だけでは直接評価しない。

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 代替と限界 |
|---|---|---|---|---|
| 1 | KA Core | 明示・暗黙の振る舞いとリスクを特定 | 部分 | 依頼234で一覧の明示された内容と暗黙の順序依存を比較。一般的な特定・説明は未評価 |
| 2 | KA Core | 静的解析や設計原則から改善箇所を特定 | 部分 | 依頼680で２受付に重複した数量確認を比較し、異なる配達料を保持しながら共有する固定例。実際の静的解析や一般のコード調査は未対応 |
| 3 | KA Core | 支持する利用方法を踏まえた後方互換性の判断 | 部分 | 依頼234で３種類の利用者を固定条件で比較。一般の判断は未評価 |
| 4 | KA Core | 既存利用者への影響を抑えた実装のリファクタリング | 部分 | 依頼235で共通条件への参照先を変更し、６試験で比較する固定例。実際の実装の変更は未評価 |
| 5 | KA Core | バージョン付け方針に照らした変更の安全性 | 部分 | 依頼236で互換性の性質が所与の３変更と番号を比較。実際の互換性分析や一般の方針は未評価 |
| 6 | Non-core | API の既定動作を安全に変える複数段階の計画 | 部分 | 依頼237で既定数変更に伴う窓口併存・利用者の移行・旧窓口の閉鎖を操作。実際の計画や未知の利用者の発見は未評価 |

依頼の前提・出典・検証と、一般化できない範囲は[既存調査](se-refactoring.md)を参照する。
