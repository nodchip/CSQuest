# 物語の一区切り：教材と進行の確認

## 対応する CS の考え方

参照：[Computer Science Curricula 2023 最終報告書](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。既存の17分野の入口と範囲は [world-finale-audit.md](world-finale-audit.md) に記録する。ここでは新しい３依頼が触れる小さな例と限界を記す。分野や知識単位の修得を意味しない。

| 依頼 | 関連分野と例 | この依頼で扱わないこと |
| --- | --- | --- |
| 手紙の道筋 | DM：時刻つき記録の順序と事実の照合。NC-Routing：記録と現在の道しるべを比べ、現在地から次の中継先を選ぶ。 | データベースの実装、時刻のずれ、一般の経路探索・実際の通信プロトコル。 |
| 荷車を渡す | OS-Scheduling：準備状態と急ぎ具合を考え、実行する仕事を決める。PDC-Coordination：一台の資源を同時に使わず受け渡す。 | 実際のスケジューラ、競合を防ぐプログラム、待ち時間や公平性の一般的な分析。 |
| 手紙を渡す | HCI-User / HCI-Accessibility：本人の希望を聞いて伝え方を選ぶ。SEC-Foundations：事前共有した秘密を周囲に知られないよう確認し本人を確かめる。 | 現実の本人確認制度や認証システムの設計全般。合言葉の強度、盗難、再利用、通信路の保護等はこの場面では扱わない。 |

三つとも同じ手紙を届ける架空の事例であり、二つの分野を用いる操作は依頼内に表示する。依頼２では仕事の選択と共有物の受け渡しを区別し、依頼３では本人の使いやすさと本人確認を区別している。

## 今回の進行と旧記録

上側12地域の異なる２依頼ずつを記録した時に新しい集いへ進める。導入の灯りと下側の依頼は不足を補わない。旧イベントの達成記録は維持するが、新イベントを達成したことにはしない。旧イベントの途中で保存した場合は元の地域へ戻す。すでに訪問・解放していた下側の４地域も、新しい区切りの後に再び訪問できる。達成済みの依頼と設定は保持する。

## 開発中の検証

- 工房から実際に始めて12地域を巡り、各地域の２依頼、３つの共同依頼、地図の拡張、四地域で各２件以上を操作した。最初の３地域を巡る順番を変えた経路でも確認した。
- 既存の17分野の入口として上記の対応表に挙げた17依頼を変更後の冒険で達成した。該当する依頼の全分野が深く学べると判断したものではない。
- 独立した進行済み記録で、３依頼の各選択肢の誤答時の手がかりと正答、途中再読込、３回の達成表示、家族の反応、四地域の同時解放を確認した。
- 旧６地域の集いを終了した記録で、元の依頼達成を保持しつつ、旧イベント画面からの復帰と下側地域の再解放待ちを確認した。
- 12・16地点の地図は320・375・768・1280pxで地点名の重なりと地図外へのはみ出しを調べた。16地点では同じ４幅で地図を150%に拡大しても地点名が重ならず、キーボードの Enter と Escape で地点詳細を開閉できた。PC の16地点の背景は画像として確認した。公開後の表示は別途確認する。

この記録は開発時の結果であり、公開後の確認やプレイヤー本人による面白さの評価を意味しない。
