# AR-IO の対応状況

原典: [CS2023 AR-IO](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.105。依頼105は１装置と固定時間を使う簡略模型で、実装や実機測定は評価しない。

| 番号 | 区分 | 内容と現状 |
|---|---|---|
| 1a | CS Core | ハンドシェイクとバッファリング。未対応 |
| 1b–c | CS Core | プログラムによる入出力と割込み駆動。依頼105で毎刻のポーリングと完了通知の固定例。転送方式全般や実装は未対応 |
| 2 | CS Core | ベクタ、優先順位、割込み応答。依頼105で単一の通知と処理・復帰の固定例。ベクタ、優先順位と応答機構は未対応 |
| 3 | CS Core | 入出力装置。依頼54・105は架空の装置のみ。具体的な装置は未対応 |
| 4 | CS Core | 外部記憶の物理構成と装置。未対応 |
| 5 | CS Core | バス、プロトコル、調停、DMA。依頼132で直接転送と DMA の固定模型。他は未対応 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1 | CS Core | 割込み制御図を分析し、入出力制御と転送への利用を説明。依頼105で単一の完了通知・処理・復帰を操作。一般の制御図分析、転送機構と自由な説明は未対応 |
| 2 | CS Core | バスの種類を列挙。未対応 |
| 3 | CS Core | 磁気ディスクと SSD の利点を比較。未対応 |

依頼105では装置は開始３刻後に完了し、CPU が各刻で確認を続ける方式と、完了通知まで他の仕事を行う方式を比べる。どちらもその後１刻で結果を処理する。前者の待機中の他の仕事は０刻、後者は３刻。処理費用と完了時刻を固定した教材例で、一般に割込みが常に有利だとは示さない。実装上の通知遅延、複数割込み、待機中のスケジューリングやデータ転送は扱わない。

依頼132は DMA の準備・４刻の転送・完了確認を固定し、CPU の別作業と転送の重なりを比較する。バスの競合や実装・実機測定は扱わない。[詳細](os-devices.md)
