# 港の道具と待機

[CS2023 OS-Concurrency、印字208ページ](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=208) のデッドロックと飢餓に関連する固定模型。各１個の道具を二人が異なる順で持ち、互いが相手の道具を待つ状態と、同じ順に借りて双方が終える状態を操作する。道具２個と３個の共通順序、および偏った貸出と先着順も比べる。

道具は同時に一人だけが持ち、待機中の強制回収や時間切れはない。待たない所有者は動けて、すべての道具をそろえた人が仕事を終えると返却する。共通順序はこの資源の循環待ちを防ぐが、別の待ちや永久に返されない道具まで解消する保証ではない。[MIT の OS 講義資料](https://people.csail.mit.edu/rinard/teaching/osnotes/h4.html) も参照した。有限回の待機自体を飢餓の証明とせず、偏った選択を無期限に続けた場合の可能性として示す。先着順の例は有限時間での返却、割込みなし、継続した受付と処理を仮定する。

実 OS のスケジューラ、実機の公平性、任意の資源やプログラムに対する保証は未評価であり、関連項目は部分対応である。実装担当と別の coverage_next が原典、待ちの輪、共通順序、飢餓の説明、保存と開放をコード上で確認した。先着順への切替で長く待つ人より直前に返却した人が先になる矛盾を指摘され、待機順を修正して再確認を受けた。独立担当自身のブラウザー操作は行っていない。

`tests/endgame-deadlock.test.js` は輪の成立条件、順序違反、返却後の再要求、待機順と立場を入れ替えた場面を検証し、`scripts/endgame-deadlock.playwright.js` は集いと４地域の達成状態を用意した記録から誤操作、途中保存、再挑戦、開放と達成を確認する。実スクリーンリーダー音声は未検証。
