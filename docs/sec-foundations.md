# SEC-Foundations の対応状況

出典: [CS2023, Security, SEC-Foundations](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 257–258。原典を要約した作業用一覧。部分的な体験は項目全体の達成を意味しない。

ゲーム内の「王城を守る道」は、依頼493の３性質から認証・認可、保護方針、暗号、安全な通信、可用性、復旧とプライバシーの関連する依頼へ進む任意の道しるべ。達成済みの依頼は他の道と共有し、途中を飛ばすこともできる。道を一通り終えても SEC 全トピックの網羅や実務能力の証明にはならない。

城門の依頼では本人確認の成否を既知として扱う。認証情報の発行・検証・失効や、実運用での安全性を再現・評価するものではない。

依頼492は毎刻妨害３通が先、村の依頼１通が後に届く４刻の模型。待合所は４通、処理は毎刻２通、制限は送信元ごとに毎刻１通。単一送信元の妨害と別の村では制限により村４通を処理するが、３送信元に分散すると制限なしと同じく１通のみ処理、村と妨害が同じ送信元では制限により村４通を拒否する。６試行・各刻の要求の保存と処理を検証した。送信元は人を一意に表さず、制限だけで DDoS 全般を防げるわけではない。固定到着順・容量・再送なしの模型で、実通信や防御性能は未評価。[CISA の DDoS 対応](https://www.cisa.gov/sites/default/files/2024-03/understanding-and-responding-to-distributed-denial-of-service-attacks_508c.pdf)・[Cloudflare の共有送信元と制限](https://developers.cloudflare.com/waf/rate-limiting-rules/parameters/)を参照。

依頼493は秘密の開示、許されない変更、受付の故障、秘密の開示と変更が重なる４報告を扱う。機密性・完全性・可用性と、読取りの権限確認・保護された印による変更検出・独立した予備受付の対応を選ぶ。４報告について被害と備えの全組合せを検証した。印の検証は変更の防止・復元ではなく、各対策の正しい動作は仮定であり、未報告の被害がない保証や実システムの安全性を示さない。[NIST の情報セキュリティ定義](https://csrc.nist.gov/glossary/term/information_security)を参照。

依頼495は２次元の１近傍分類で、出所不明の誤った学習札の混入と、妨害の行為を変えずに観測値を変える場合を比較する。混入を除くと固定の妨害１件は警報になるが、同距離を札順で決める入力変更の例は通される。２種類の学習札と３種類の伝令について距離・同順位・予想と保存復元を検証した。出所の確認と実際の種類は仮定で、実際の攻撃・防御や一般的な性能は評価しない。[NIST の敵対的機械学習の分類](https://www.nist.gov/publications/adversarial-machine-learning-taxonomy-and-terminology-attacks-and-mitigations-0)を参照。
