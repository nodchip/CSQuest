# HCI-User の対応状況

出典: [CS2023, Human-Computer Interaction, HCI-User](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 174–175。原典を要約した作業用一覧。架空の人物を扱う模型は、実際の利用者調査や当事者の参加を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 利用者中心設計、ニーズの発見、面接・調査・試用 | 依頼188で架空の旅人と係の声を聞き、案内の選択と場面確認を操作。実際の面接、調査、利用者試験は未対応 |
| 2 | KA Core | ペルソナ、物語、ニーズ分析、利用の過程、評価、関係者とチーム | 依頼87・188で架空の声と要求、依頼60で架空の評価記録。実際の分析、協働、物語の作成は未対応 |
| 3 | KA Core | 身体的・認知的特性、注意、記憶と心理 | 依頼188で座って確認したい場面の固定例。身体や認知の体系的なモデルは未対応 |
| 4 | KA Core | 多様な利用者、文化、国際化、評価上の課題、ユニバーサルデザイン | 依頼22・188で異なる利用条件の固定例。国際化、文化や代表性のある評価は未対応 |
| 5 | KA Core | 複数利用者の協働・通信、コミュニティ、仮想世界 | 依頼188で案内を利用する人と維持する係を区別。複数利用者の協働やコミュニティは未対応 |
| 6 | Non-core | 複数利用者システム | 未着手 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | プロジェクトに統合した利用者中心設計を行う | 依頼188は架空の声・設計・場面確認の固定模型。実際のプロセスの実施は未対応 |
| 2 | KA Core | 利用者と設計者のニーズを比較 | 依頼188で旅人と維持担当の事情を比較。実際の設計者との比較は未対応 |
| 3 | KA Core | 代表的な利用者と他の影響を受ける人を特定 | 依頼188で利用する旅人と案内を維持する係を扱う。代表性や他の関係者の調査は未対応 |
| 4 | KA Core | 共感と評価の役割を説明 | 依頼188で声を聞いて場面を確認する固定例。自由な説明は未対応 |
| 5 | KA Core | 利用者とニーズの分析・記録 | 架空の声を読むのみ。実際の分析・記録は未対応 |
| 6 | KA Core | ニーズ分析から利用者物語を作成 | 依頼87で２つの固定事情に合う立場・望み・理由を選択。実際の分析と自由な作成は未評価 |
| 7 | KA Core | 異なる利用者集団向けに既存案を再設計 | 依頼22で３条件に合わせて案内板を改善する固定例。実際の集団への再設計は未対応 |
| 8 | KA Core | ニーズを発見する方法を比較 | 依頼188で架空の３目的に応じ面接・現場観察・試作品の試用を選び、それぞれの限界を比較。実際の調査や一般の方法選択は未評価 |
| 9 | KA Core | 低技術・非技術の要素が役立つか考察 | 依頼188で通信不要な紙と手作業による更新を扱う。実際の運用条件や他の選択肢の検討は未対応 |
| 10 | Non-core | 複数利用者の状況で設計する影響を認識 | 依頼188で旅人と維持担当の異なる事情を確認。実際の複数利用者システムは未対応 |

依頼188は架空の配達人、座って待つ旅人、案内を維持する係の３人について、紙・座席・更新手順を選んで確認する。読みやすさ、実際の場所や更新遅れなどは評価せず、当事者による検証が必要。

依頼188は追加で、現場の行動と環境、一人の経験、試作品での時刻探しという３目的について、面接・現場観察・試用のうち目的に直接合う方法を選ぶ。実際には複数の方法を組み合わせ、参加者の同意・募集と多様性を考慮する。固定された選択肢であり実際の調査を実施したことや代表性は示さない。参考：[GOV.UK の利用者調査](https://www.gov.uk/service-manual/user-research)、[面接](https://www.gov.uk/service-manual/user-research/using-in-depth-interviews)、[現場観察](https://www.gov.uk/service-manual/user-research/contextual-research-and-observation)、[試用](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)。

依頼87では、練習用に与えた２つの事情から「立場・望み・理由」を選び、食い違う希望は未解決として扱う。理由は練習の仮定で実際の聞き取り結果ではない。実際の関係者との合意や自由な文書作成は評価しない。参考：[Agile Alliance の利用者物語](https://agilealliance.org/glossary/user-stories/)。
