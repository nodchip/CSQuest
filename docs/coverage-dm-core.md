# DM-Core：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.115–116。原典番号・区分を保ち、[データベース基礎の記録](dm-core.md)、関連する依頼の実装・テストを照合した。状態は[追跡方法](coverage-status.md)に従う。

ゲーム内の札や固定模型は、実際の SQL の記述、DBMS の設計・運用や自由な文章による説明を直接評価しない。個別の例の存在を原典項目全体の完成とは扱わない。

依頼89の各検索経路の結果、依頼123のビュー対応、35の中断時の模型はそれぞれ個別テストで検査される。これらは固定例の検証であり、原典全体の網羅性、大学水準の深さ、実システムの安全性を示さない。各前提は[データベース基礎の記録](dm-core.md)を参照。

依頼189の配達表は固定列、配達札は記録ごとに異なる名前付き項目、日誌は自由な文章として扱う。いずれも２件の薬草の配達から５束を読み取る例。半構造化データの項目の違いについて [Google Cloud のデータモデリング](https://cloud.google.com/blog/topics/developers-practitioners/definitive-guide-databases-google-cloud-part-1-data-modeling-basics) を参照。形式だけで検索やスキーマ検査の可否は決まらない。実際の抽出・集計システムの評価ではない。
