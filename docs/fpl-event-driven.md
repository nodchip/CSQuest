# FPL-Event-Driven の対応

原典: CS2023 p.134。依頼92では太陽・月のイベントに処理を登録し、固定された２種類の到着順を、単一の FIFO 待ち行列への送信と先頭の処理に分けて操作する。処理の組合せと、送信・処理の全ての有効な交互順序を検証する。実際の言語での関数定義や特定のイベントループの仕様を再現するものではない。

| 分類・番号 | 内容と状態 |
|---|---|
| CS Core 1 | 手続き型と反応型の比較。依頼92はイベントに反応する固定例のみ。長短の体系的な比較は未対応 |
| CS Core 2 | 発生源、信号、リスナー、ディスパッチ、イベント・アダプタ・処理。依頼92の２種類の信号と単一待ち行列、594の札に登録されたコールバックと参照先の固定例。一般のイベントオブジェクトやアダプタは未対応 |
| CS Core 3 | 状態を持たないモデルと状態遷移。灯りの数の状態遷移のみ |
| CS Core 4 | GUI、端末、ロボット、サーバなどでの利用。未対応 |
| KA Core 5–7 | 反応型フレームワーク、MVC、状態遷移としてのプログラム。未対応 |

例示学習成果 CS Core 1 は処理の選択・登録という固定例のみで、実言語の実装能力を評価しない。CS Core 2 と KA Core 3–4 の一般的な説明・フレームワーク・MVC は未対応。

依頼594では三つの案内札に処理を順に登録し、登録後の押下時に参照先を調べる。共有の変更可能な箱では最後の案内を全処理が読み、札ごとの箱では異なる案内を読む。[MDN のクロージャとイベント](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures)を参照。押下は同期的な模型で、実ブラウザのイベント伝播や非同期順序は扱わない。
