# AR-Representation の対応状況

出典: [CS2023 AR-Representation](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 103。原典を要約した作業用一覧。依頼36は４ビットの固定例であり、実機の数値形式全体や実装能力を評価しない。

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | CS Core | 命令を含め、コンピュータ内で扱うものがデータである理由を議論 | 依頼73で命令と値を同じ記憶に置く固定例。一般的な議論は未評価 |
| 2 | CS Core | 固定長表現が正確さや精度に及ぼす影響を説明 | 依頼36の整数の範囲超過と依頼68の小数の丸め・計算順序。自由記述と一般的な分析は未対応 |
| 3 | CS Core | 負の整数の符号と絶対値、２の補数表現を説明 | 依頼36・461で４ビットの符号と絶対値・２の補数の比較。自由記述や一般のビット幅は未対応 |
| 4 | CS Core | 数値を表す異なる形式を議論 | 依頼36で同じビット列の符号なし・２の補数の読み方を比較。一般の議論は未対応 |
| 5 | CS Core | 文字、文字列、レコード、配列などのビット表現を説明 | 依頼93で５文字列の符号位置と UTF-8 バイト列を選択。一般的な説明、レコード・配列は未対応 |
| 6 | CS Core | 数値データを異なる形式に変換 | 依頼36で10進整数に対応する４ビット列を選択。一般的な変換は未対応 |
| 7 | CS Core | 同じ加算器で符号なしと２の補数を扱える仕組みを説明 | 依頼37で一桁の加算器を組み、４桁につないだ結果を符号なし・２の補数で比較。固定構造の例であり、自由記述は未対応 |

依頼36の解答は符号なしの 6 が `0110`、２の補数の −3 が `1101`、`0111` と `0001` の４ビットの和が `1000`。最後の結果は符号なしでは 8、２の補数では −8 であり、符号付きの数学的な和 8 は４ビットで表せない。ビット演算の全16通りを自動テストする。

依頼37は依頼06で作った XOR を含む５部品で一桁の加算器を作り、８入力を試す。これを４桁につないだ加算結果と桁ごとの繰り上がりを示し、符号なしと２の補数の読み方を比較する。４ビットの入力２つを自由に選び、結果と符号なしの繰り上がり・符号付きの範囲超過を比較できる。全256通りを独立した整数加算と照合する。

依頼68は仮数の小数部３ビット、正規指数 −4〜2 の非負の架空形式で、最近値・中間時は末尾０への丸めを操作する。ゼロと非正規値を含む表現可能値の各隣接対の中間点で、丸め先を検証する。1 と 0.0625 を使う２通りの加算順序は、それぞれ 1 と 1.125 を得る。実際の IEEE 形式、負数、オーバーフロー、無限大、NaN、実機での演算を再現しない。

依頼93は A、あ、é、e＋結合アクセント、😀の符号位置と UTF-8 バイト列を操作する。正規化しない２種類の é のバイト列が異なることを示す。UTF-8 の仕様は [RFC 3629](https://www.rfc-editor.org/rfc/rfc3629)、符号位置と結合文字は [Unicode Core Specification 第３章](https://www.unicode.org/versions/Unicode16.0.0/core-spec/chapter-3/) を参照。一般の符号化や表示上の文字の分割規則は扱わない。

依頼460は 0x1234 を２バイトに分け、小さい側からなら番地０・１に 0x34・0x12、大きい側からなら 0x12・0x34 と配置する。同じ順序で読むと 0x1234、逆なら 0x3412。全65,536の16ビット値と両順序を JavaScript DataView と照合した。[MDN のバイト順](https://developer.mozilla.org/en-US/docs/Glossary/Endianness)を参照。16ビットを１ワードとする模型で、実機のワード長や命令を一般化しない。

依頼461は４ビットの符号と絶対値と２の補数を比較する。−３ は 1011 と 1101、1000 は負の０と −８。前者は −８ を表せず、後者は表せる。16通りの読みと符号化の往復を検査。[Cornell の符号付き整数](https://www.cs.cornell.edu/courses/cs3410/2026sp/notes/numbers.html)を参照。固定４ビットの整数で、浮動小数点の符号や一般の演算は扱わない。

依頼710は８ビットの２の補数整数を16で割る固定小数点を扱う。16倍した値を最近の整数へ丸め、中間は偶数側、丸め後の整数が範囲外なら拒否する。0.03125→0、0.09375→0.125、7.96875 は128に丸まり範囲外、−8.03125 は−128に丸まる。同じ８ビットを符号あり・なしで比較し、全256列を DataView と照合した。他の丸め方・演算・実機は未評価。[項目別台帳](coverage-ar-representation.md)。

依頼711は依頼710の固定小数点を掛け合わせ、16ビットの途中積、目盛りの調整、中間偶数への丸めと保存範囲を比較する。全65,536組で積と丸めを検査した。下位８ビットだけを残す実験は途中幅の問題を示すもので、実機の規則を一般化しない。[詳細](coverage-ar-representation.md)。
