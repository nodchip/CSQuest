依頼186では固定された単位法線と灯り方向の内積を０以上に制限し、0.25 と 0.75 を境に３段階へ分ける。簡略化した拡散光であり、影・輪郭線・実際の描画 API やプログラミング能力は評価しない。

依頼187は２地図の各３本の道で、光から最も近い深さと地面の深さ５を比較する。記録より地面が奥なら影、等しい場合は明るいとする。平行光と離散的な道を仮定し、実際の深度画像、精度誤差や半影は扱わない。

依頼732は高さ２の線状光源を５点で近似し、高さ１の壁と地面の３点の遮蔽を比較する。壁の端を含め、届く光点はそれぞれ５・３・０個。方向や距離による光量を等しいとする２次元の可視性模型で、連続的な面光源の積分・実画像・収束性は評価しない。[Cornell の面光源と影](https://www.cs.cornell.edu/courses/cs4620/2012fa/lectures/36raytracing.pdf)。原典の各項目は [対応台帳](coverage-git-shading.md) を参照。

依頼733は732の影の縁の５光点 (可視１が３点、０が２点) を用いる。５点から独立一様に１回・２回選ぶ全順序と中央固定を列挙し、可視割合の推定値を比較する。一様な見積もりの期待値は0.6、分散はそれぞれ0.24・0.12。中央固定の値は常に１。この例は乱数による実行でなく厳密な有限列挙で、連続的な光源の積分や一般的な一致性を評価しない。[PBRT の Monte Carlo 推定](https://www.pbr-book.org/4ed/Monte_Carlo_Integration/Monte_Carlo_Basics)。

依頼734は既存の４×４画素の深度を２×２領域の最大値３・４・３・９に集約する。小さい値が手前で、候補の最も近い深さが領域最大より大きければ、全画素で奥と判断して省ける。等しい場合は省かず、判定不能も可視確定ではない。さらに４領域をまとめた全画面の最大深度９を使い、全体の省略と下位の検査を区別する。完全に覆う不透明な壁と深度の誤差がない模型で、一般の解像度・透明物体・実 GPU の性能は未評価。[NVIDIA の遮蔽カリング](https://developer.nvidia.com/gpugems/gpugems/part-v-performance-and-practicalities/chapter-29-efficient-occlusion-culling)。
