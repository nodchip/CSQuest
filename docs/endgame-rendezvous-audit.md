# PDC-Coordination：精霊の待ち合わせ

[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.222–223、PDC-Coordination 2a のバリア。旧依頼90 `src/barrier.js` の同一の２精霊・２と３の模型を現行の港で再利用しており、旧依頼と独立の教材範囲として数えない。現行の分割集計とは異なり、両方の到着を待ってから両方が進む例を扱う。

棚は０から開始し、各自の書込みは直ちに双方に見えるという模型。待ち合わせなしでＡが置いて読む後にＢが置いて読むと、Ａは２、Ｂは５を読む。待ち合わせありでは先着者が待ち、両者が数を置いて到着した後、双方５を読む。Ａ先着・Ｂ先着とも検査する。[POSIX の仕様](https://pubs.opengroup.org/onlinepubs/9699919799/functions/pthread_barrier_wait.html) は所定の数の参加者が到着するまで待つ操作を定義する。

この固定模型は一回の２人の待ち合わせのみであり、実際のメモリモデル、複数回のバリア、参加者の故障、停止・取り消し・公平性や一般の並行プログラムの実装・正しさを評価しない。PDC-Coordination の全体が完成したとはしない。

実装担当とは別の `review_candidate` が原典・POSIX、固定例の到着・待機・合計、各画面の前提、誤答・履歴、分類と開放、旧記録の既定値を確認した。待機中もボタンで進むように読める説明を指摘し、相手の到着まで進めないと修正後に再確認した。関連９テストも成功した。実際の並行実装を検証したものではなく、レビュー担当自身はブラウザを操作していない。

`scripts/endgame-rendezvous.playwright.js` は集いと４地域の達成状態を用意した検証用記録から、213・390・1200 px 幅で分類経由の到達、キーボード操作、待機と案内、途中保存・再開、段階開放と達成後の再開を確認した。新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者による面白さの評価は未確認。
