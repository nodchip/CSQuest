# DM-NoSQL の対応状況

出典: [CS2023, Data Management, DM-NoSQL](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 120–121。原典を要約した作業用一覧。固定模型の達成は知識単位全体の習得を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | KA Core | NoSQL を使う動機、アプリケーションと関係データの違い | 依頼189で鍵だけの取得と構造に対する検索の固定模型。実際のアプリケーションや関係データベースとの総合的な選択は未対応 |
| 2 | KA Core | キー・バリューと文書のデータモデル | 依頼189で鍵による値の取得、札の配列と索引付きの検索・更新を比較。実製品の多様な機能や一般のデータモデルは未対応 |
| 3 | Non-core | キー・バリューやデータレイクなどの保存方式 | 依頼189で鍵の固定模型。実装、データレイクや運用は未対応 |
| 4 | Non-core | 分割配置と複製 | 依頼190で２複製と更新の配送、191で奇数・偶数と番号範囲による２棚への分割と検索の固定模型。実際の分割配置や複製方式は未対応 |
| 5 | Non-core | グラフデータベース | 依頼192で薬師・薬草・症状の有向ラベル付き関係を２段階たどる固定模型。問い合わせ言語、索引や実 DB は未対応 |
| 6 | Non-core | 整合性、クォーラムと CAP | 依頼190で単一更新の未配送時に古い複製を読む固定例。形式的な整合性モデル、クォーラムと CAP は未対応 |
| 7 | Non-core | MapReduce と段階的な処理 | 依頼130で分割した小計の集約の固定模型。NoSQL の処理基盤や増分処理は未対応 |
| 8 | Non-core | クラウド保存、グラフ DB、NoSQL が適さない場合の事例 | 未着手 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | KA Core | 関係 DB より NoSQL を使う用途を設計 | 依頼189で異なる検索方法の例を比較。実際の要件から用途を設計する能力は未対応 |
| 2 | KA Core | キー・バリューと文書モデルの特徴を説明 | 依頼189で鍵による取得と札の構造・索引を操作。一般的な特徴の自由記述と製品差は未対応 |

依頼189では３記録から「回復」の札を探し、K1 の札の削除前後で同じ結果を確かめる。鍵の箱は値を順に取得し、文書の箱には札の索引があると仮定し、更新時に索引も変更する。鍵方式や関係 DB に索引がないと主張するものではなく、実製品の機能や性能は評価しない。

依頼190では両方４の２複製に対し、本館だけを３に更新する。通信断では配送が失敗して分館は４を返し、復旧後に配送すると３を返す。１回の更新と手動配送の模型であり、形式的な整合性保証や CAP 定理は示さない。

依頼191は４鍵を奇数・偶数または番号１〜２・３〜４で２棚へ分け、K3 と K1〜K2 の検索に必要な棚を選ぶ。追加の索引と複製がない固定模型であり、実システムの負荷分散や性能は評価しない。

依頼192は薬師２人、薬草２種類、症状２種類の有向関係をたどる。寒気に合う経路は３つだが始点の薬師は２人、腹痛に合う経路と薬師は各１つ。グラフ DB の問い合わせ言語や一般の探索は評価しない。
