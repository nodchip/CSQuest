# 鍛冶街の装置と完成通知：範囲と未完了

[CS2023 印字 105 ページ（PDF 105 ページ目）AR-IO](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の programmed I/O と interrupt-driven I/O の入口。[Linux の装置入力文書](https://docs.kernel.org/input/input-programming.html)は、通知を出さない装置を繰り返し確認する場合と割り込み資源に触れている。

旧教材の `interrupt.js` 等は現行冒険への到達を示さない。現行の鍛冶街には命令やキャッシュの模型があるが、CPU の依頼は割り込みを扱わない。今回の固定模型は、装置が３枠目の終わりに完了し、仕事・確認・受付と処理の各操作が１枠かかると仮定する。確認の間に別の仕事を行える例と、通知が受付待ちとなり次の枠で受け付け・処理してから元の仕事を再開する例を、同じ５枠で比べる。通知が発生したことと CPU による受付・処理は区別し、受付と処理は模型上１操作にまとめている。

この条件では別の仕事の枠が２対４になるが、確認頻度・処理負荷・通知遅延等が違えば結果も変わる。常に通知方式が有利とは言えない。実際の割り込みの受付・優先度・ネスト・マスク・装置との同期、ハードウェアや OS の実装、測定、自由な説明は未評価であり、原典全体の達成を示さない。

`forge-io-poll` と `forge-io-interrupt` の２件を終えると `forge-io-compare` が開く。鍛冶街の依頼分類から選び、地図の全達成判定にも含まれる。

実装担当とは別の `review_candidate` が原典、上記 Linux の資料、５枠における完了・受付待ち・確認と仕事の各時刻、比較結果、説明、分類と保存をコード上で確認した。受付と処理を１操作にまとめた固定手順であり、一般的な割込み設計の能力や実装置の性能を確認したものではない。レビュー担当自身はブラウザを操作していない。

`tests/endgame-io.test.js` は装置完了の時刻、確認前の状態、受付待ち・処理・仕事の再開、固定条件の比較、誤操作と履歴再開を確認する。`tests/forge-station-quest-groups.test.js` は分類と開放を確認する。`scripts/endgame-io.playwright.js` は集いと４地域などの達成を用意した検証用記録から、213・390・1200 px 幅で分類からの到達、キーボードによる依頼と回答、誤答の案内、途中復元、段階開放、３依頼の達成と達成後の再開を確認した。新規開始からこの依頼群までの通し操作、実際のスクリーンリーダー音声、利用者による面白さの評価は未確認。
