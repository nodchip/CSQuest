# SEP-Communication：コミュニケーションの項目別対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.279–280。[既存調査](sep-communication.md)と依頼・検査を照合。状態は[追跡方法](coverage-status.md)に従い、「未照合」は未実装の証拠ではない。「部分」は関連する固定例を示し、項目全体の修得を意味しない。実際の社会調査・法的判断・自由な説明や文章作成は固定例だけでは直接評価しない。

| 3 | CS Core | 顧客、管理者、一般の人など異なる相手への伝達 | 部分 | 依頼295で旅人と修理係の必要を聞き、報告を選ぶ固定例。他の相手・状況は未対応 |

| 6 | CS Core | 自然言語の違いを含む文化的配慮 | 部分 | 1132で本人の希望する言葉と時間帯を聞き、日付を明記する。実際の翻訳、異文化の幅広い配慮は未評価。 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 代替と限界 |
|---|---|---|---|---|
| 1 | CS Core | 簡潔・正確な技術文書と形式、図表、参照の重要性 | 部分 | 依頼295で事実・範囲と未確認事項の札を選ぶ固定例。実際の文書構成は未対応 |
| 2 | CS Core | 技術文書の正確性、簡潔さ、明確さと対象者への配慮を分析 | 部分 | 依頼295で不確かな断定・不要な個人情報を除き相手に必要な情報を選ぶ固定例。自由な分析は未対応 |
| 3 | CS Core | 対象者に配慮したアクセシブルな正式発表 | 部分 | 1133で２人の希望に合わせ図・読み上げ・字幕を比較し発表を準備。実際の発表や利用者による検証は未評価。 |
| 4 | CS Core | 多様な意見と参加を尊重する交流の計画 | 部分 | 650・1044で異なる事情を聞き、確認と追加相談を選ぶ。実際の交流の計画・実行は未評価。 |
| 5 | CS Core | 効果的な伝達の性質の特定と説明 | 部分 | 依頼295で２人の必要を聞き、限定された情報を選ぶ固定例。一般的な説明は未対応 |
| 6 | CS Core | チーム内の効果的な伝達と対立解決 | 部分 | 1044で時刻の異なる意見、代替案、未解決事項を記録・共有する固定例。現実の対話や対立解消は未評価。 |
| 7 | CS Core | 多様で異文化のチームの成果に影響する方法 | 未照合 | 対応例を要照合。 |
| 8 | KA Core | 多様な遠隔チームで働く際の自身の強みと弱みの評価 | 未照合 | 対応例を要照合。 |
| 9 | KA Core | 繊細な倫理的懸念を伝える適切な方法の選択 | 未照合 | 対応例を要照合。 |

各依頼の前提・出典と検証、実際の状況に一般化できない範囲は[既存調査](sep-communication.md)を参照する。

依頼1044は [W3C の非同期参加を含む決定方針](https://www.w3.org/WAI/about/groups/apawg/decision-policy/)と [遠隔会議のアクセシビリティ](https://www.w3.org/TR/remote-meetings/)を参考に、650の橋の事情と964の記録をつなぎ、参加時間の異なる３人の意見、予約の可否、暫定案または追加相談を扱う。共有記録が全員に読めることは模型の仮定で、共有を同意と見なさない。`tests/team-relay.test.js` は両結果、順序、未確認の採用拒否、保存と達成を検査する。実際の参加、利用可能性、合意、自由な対話は評価しない。

依頼1130は [Diátaxis](https://diataxis.fr/) の目的別資料を参考に、学習・作業・参照・理解と実装の変更調査の５つの目的に対し、架空の巻物を選ぶ。版２の参照が必要な場合、旧版１の参照を選ぶと版の違いを示す。`tests/document-finder.test.js` は全30組の判定、途中保存と達成条件を検査する。実際の資料は複数の目的を持ち得るため、固定例は資料分類の唯一の方法を示さず、実資料の評価・作成や自由な説明は評価しない。

依頼1131は [Diátaxis の参照資料](https://diataxis.fr/reference/)を参考に、1130の続きとして架空の２版の灯具を操作する。各版の参照には起動・調整の名前と前提・範囲を記し、版違い、未起動、範囲外を試して４台を修正する。`tests/lantern-manual.test.js` は操作の結果、達成と途中保存を検査する。実際の API・文書の正確性の検証や自由な資料作成は扱わない。

依頼1131では０〜６を選択でき、版１は１〜３、版２は１〜５を受け付ける。範囲外の値は理由を示し、以前の明るさを維持する。各版の全14条件と途中保存を検査する。０と６は範囲外を試すための選択肢で、版により有効となる値は異なる。

依頼1132は [W3C の日付形式](https://www.w3.org/International/questions/qa-date-format)と[言語選択の限界](https://www.w3.org/International/questions/qa-when-lang-neg)を参考に、962と同じ瞬間の案内を２人の明示した希望に合わせる。日本語・東京は2024年４月４日08:30、英語・ロサンゼルスは４月３日16:30。`tests/language-notice.test.js` は２人×２言語×３時間帯×２日付形式、日時、保存と達成を検査する。言語から所在地や文化を決めつけず、固定例で実翻訳、広範な文化的配慮、実利用者との対話や送信は評価しない。

依頼1133は [W3C のアクセシブルな発表](https://www.w3.org/WAI/teach-advocate/accessible-presentations/)を参考に、図が見えず音声を聞く人と、音声が聞こえず図と字幕を読む人の明示した条件で、架空の点検結果を伝える。図の項目・数値、読み上げの具体性、字幕の有無の８組合せを比較し、字幕は読み上げた内容に従う。`tests/accessible-report.test.js` は８条件、予想、５比較の達成条件と保存を検査する。文字による模型で、実際の音声・字幕、支援技術、会場、個々の利用者の検証や正式発表能力を示さない。
