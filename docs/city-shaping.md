# CS Quest：街への旅と今後の開発方針

2026-11-07 の対話で選択された次の区切り。設計であり、街・おすすめ機能が実装済みであることは示さない。実装と検証の設計は [city-breadboard.md](city-breadboard.md)、実行用プロンプトは [CSQUEST_CITY_GOAL.md](../CSQUEST_CITY_GOAL.md)。前の [工房から旅立つ冒険](workshop-journey-shaping.md) は公開済みの前段階を記録する。

## 要件

会話中に用いた R0〜R9 を継続する。開始地点７か所、合流、７つの保存先は再検討の結果取り下げた。

| ID | 要件 | 状態 |
| --- | --- | --- |
| R0 | 冒険を楽しみながら、CS2023 の全分野を大学のカリキュラムに近い深さで学べる。 | 長期目標 |
| R1 | 体験版で好評だった分かりやすさと冒険の楽しさを保つ。 | 必須。楽しさは人による評価が必要 |
| R2 | 冒険と教材を地域単位で一緒に広げ、CS2023 全体の扱い残しを把握する。 | 必須 |
| R3 | 既存教材を確認し、生かせる部分を使い、必要な部分は改善する。 | 必須 |
| R4 | 地域ごとに複数の変更をまとめて公開し、遊んだ感想を次に反映できる。 | 必須 |
| R5 | 工房からの冒険を続け、街と水辺の村を選んで訪れ、それぞれの依頼に戻って取り組める。 | 必須 |
| R6 | 冒険は精霊の工房１か所から始める。 | 必須 |
| R7 | 街のギルドと市場で、祭りに関係する荷物と整列の２依頼に出会える。各依頼は独立して取り組め、１件達成で祭りの準備を見られる。もう一方も後から受けられる。 | 必須 |
| R8 | おすすめの依頼を任意に選べ、各依頼で必要な情報を確認できる。 | 必須 |
| R9 | 冒険を１つ保存し再開できる。新しく始める際は上書き前に確認し、既存の記録を大切に扱う。 | 必須 |

## S：工房から街へ

| 部品 | 仕組み | 未確定 |
| --- | --- | --- |
| S1 | 工房周辺の異なる２依頼の達成後、既存の旅先選択に街を追加し、水辺の村か街を明示的に選ぶ。どちらにも後から戻れる。 | 街の地名と風景 |
| S2 | 街で風景と祭りの準備を短く紹介し、ギルドか市場を選ぶ。ギルドでは明るく世話好きな受付兼荷物担当、市場では穏やかで面倒見のよい人物に出会う。名前・役割・全身と顔を示す。 | 人物の名前、姿、会話 |
| S3 | ギルドは２依頼を紹介し、市場でも整列依頼を直接受けられる。同じ依頼は入口にかかわらず進行と達成を共有する。 | 導入の具体的な文面 |
| S4 | 品札の隣接交換と荷物の先着順の操作を、`src/sorting.js` と `src/containers.js` を確認して再利用・調整する。各依頼で目標・操作・手がかり・必要な背景を示し、中央の達成表示から記録を見直せる。 | 祭りに必要な品物や荷物の設定。既存の荷物教材はスタックとの比較も必須にするため、今回の待ち行列の依頼では依存を取り除く調整が必要 |
| S5 | 街のいずれか１依頼の初回達成で祭りの準備を見られる。手伝った人物の会話が変わり、もう一つの依頼も受けられる。 | 祭りの名前と演出 |
| S6 | 登場人物が達成状況に基づく未達成の依頼を短く一度紹介し、後から相談すれば再度案内する。紹介は強制や習熟度の証明とせず、他の依頼も選べる。 | 具体的な候補順位とセリフ |
| S7 | 既存の１冒険の保存、設定、工房・村の進行を保持して街の進行を追加する。データ破損・保存不可の警告と元データの保護、最初から開始時の確認を維持する。 | 既存スキーマの安全な拡張方法 |
| S8 | CS2023 対応と根拠・限界を更新し、テスト・実画面・公開先を検証。複数の変更をまとめ、既存トップを維持して体験版を GitHub Pages に公開する。 | 公開時の remote・Pages 状態と未公開変更の安全な扱い |

## 今後の大まかな流れ

街を一つの区切りとして完成・公開し体験を確認する。その後は地域ごとに既存教材の活用、物語と操作の拡張、CS2023 との対応・正確性の検証を繰り返し、未対応項目を埋める。最後に主要な物語と教材を通して確認する。地域・依頼の順序や完成率は、今後の確認なしに確定しない。
