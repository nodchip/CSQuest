# OS-Memory の対応状況

出典: [CS2023 OS-Memory](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 210–211。原典を要約した作業用一覧。依頼34・40はページ置換と住所変換を示す固定モデルであり、実 OS の挙動やプログラム開発能力を直接評価しない。

## トピック

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | 物理メモリ、アドレス変換、管理ハードウェア | 依頼40で固定ページ表による変換と保護の例。実機ハードウェアは未対応 |
| 2 | KA Core | キャッシュを含むメモリ階層が OS の仕組みと方針に与える影響 | 依頼25でキャッシュの固定例。CPU ごとのキャッシュや OS 方針への影響は未対応 |
| 3 | KA Core | 論理・物理アドレスとアドレス空間の仮想化 | 依頼40で４頁と３枠、依頼385で２プロセスの同じ仮想頁が別または同じ物理枠に対応する固定例。一般の仕組みは未対応 |
| 4 | KA Core | ページング、置換、スラッシング、ページと枠の割当 | 依頼34・137の固定例と、依頼487で５種類・最大12参照の列を組み立て、３・４枠の FIFO・LRU・理想方式を比較。実際のスラッシングや一般の割当は未対応 |
| 5 | KA Core | メモリの確保・解放・格納手法の性能と柔軟性 | 依頼387で先頭適合・最小適合、外部断片化と隣接空きの結合の固定例。実時間や一般の割当は未対応 |
| 6 | KA Core | メモリキャッシュ、一貫性、脆弱性対策としてのフラッシュ | 依頼485で TLB の切替時消去と空間識別を操作。一般のキャッシュや脆弱性対策は未対応 |
| 7 | KA Core | サンドボックス、保護、分離と攻撃経路 | 依頼40で読み取り専用頁、385で別枠と共有枠、491で Dirty COW の概要と参照先の変化を扱う架空模型。一般の保護や実際の攻撃手順は未対応 |
| 8 | Non-core | 仮想メモリのハードウェアを利用した OS の効率化 | 依頼486で頁保護と書込み時の複製を操作する固定例。一般の仮想化や実装は未対応 |

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | メモリ階層と費用・性能のトレードオフを説明 | 依頼489で仮定した２階層の費用と読取り時間を比較。一般の階層と自由記述は未対応 |
| 2 | KA Core | キャッシュ・ページングにおける仮想メモリの原理を要約 | 依頼34・40：３枠のページ置換と固定ページ表の住所変換。一般の原理と自由記述は未対応 |
| 3 | KA Core | 記憶容量とプロセッサ速度のトレードオフを評価 | 依頼489で容量・費用と仮定した読取り時間を比較。プロセッサ速度の変化や実機は未対応 |
| 4 | KA Core | キャッシュの目的・利用と分離への影響を説明 | 依頼485で TLB の空間混同と切替時消去・印を比較。一般の分離や VM は未対応 |
| 5 | KA Core | ページ置換と枠割当を考慮した効率的なプログラムを開発 | 依頼488で同じ表の走査順を選び２枠の頁取寄せを比較する代替体験。実言語のプログラム開発能力は直接評価しない |
| 6 | Non-core | 効率的な仮想化へのハードウェア利用を説明 | 依頼486で頁保護を使うコピーオンライトの固定例。一般的な説明や自由記述は未対応 |

依頼34は同じ３枠に対する参照列 A B C A D A と A B C A D B を使う。前者の読み込みは FIFO ５回・LRU ４回、後者は FIFO ４回・LRU ５回。読み込みと置換を単純化し、書き戻し、並行する他の処理、実時間や実 OS の方針はモデル化しない。

依頼40は４住所ごとの仮想頁０〜３と、物理枠０〜２の固定表を使う。頁０→枠２、頁１→不在、頁２→枠０、頁３→枠１（読み取り専用）。全16仮想住所と読み書き両方について変換結果をテストする。フォールト後の読み込み、TLB や実 OS は扱わない。

依頼137は A B C を３回繰り返し、LRU の２枠では９回、３枠では最初の３回だけ頁を読み込む。必要な頁の数と枠数の関係を扱う固定例で、実時間、他のプロセス、書き戻しや実 OS のスラッシングは測定しない。

依頼387では空き長３・６・４の間に使用中の箱を置き、４個、次に６個を連続確保する。先頭適合は６個の空きから４個を確保して３・２・４となり、合計９個でも６個を確保できない。最小適合は４個の空きを使い６個を残す。前者は４個を解放し隣の空きと結合すると６個を確保できる。固定した領域・依頼であり、方式の一般的な優劣、管理情報や実時間は評価しない。[参考：OSTEP の空き領域管理](https://pages.cs.wisc.edu/~remzi/OSFEP/vm-freespace.pdf)

依頼485はＰの頁０→枠１、Ｑの頁０→枠２で、無区別、切替時消去、空間識別子付きの TLB を比較する。Ｐ・Ｑ・Ｐの読取りでミスはそれぞれ１・３・２回。無区別ではＱが誤って枠１を使う。各手順と保存を検査した。２枚の容量と固定頁表を仮定し、ASID 再利用、権限、頁表更新や複数 CPU は扱わない。[OSTEP の TLB](https://pages.cs.wisc.edu/~remzi/OSFEP/vm-tlbs.pdf)を参照。

依頼486は親子が値７の頁を共有し、子が９を書き込む固定例。コピーオンライトでは書込み保護によるフォールト後に子の頁を複製するため親は７を読み、書込み可能な共有頁では親も９を読む。１頁・１回の書込みの模型で、実装や障害時処理、共有状態による最適化は網羅しない。[OSTEP のコピーオンライト](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-complete.pdf)を参照。

依頼487は A〜E の頁を最大12回選び、空の３・４枠で FIFO・LRU・未来の参照を知る理想方式の取寄せを比較する。A B C D A B E A B C D E では FIFO の取寄せは９回・10回で、枠を増やすと増える例になる。理想方式は実際の未来予測ではない。FIFO・LRU は独立した待ち行列の模型と照合し、理想方式は短い列で全置換候補の最小値と比較した。１プロセス、空の初期状態、書戻しと時間を省略する。[OSTEP の頁置換方針](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-beyondphys-policy.pdf)を参照。

依頼488は１〜16の４行４列表を１行１頁に格納し、空の２枠と LRU で行順・列順・２×２区画順に走査する。同じ整数の合計136を得るが、頁の取寄せは４・16・４回。各途中状態を独立した LRU の計算と照合した。固定配置と単純な整数の合計の例であり、走査順の変更が常に正しいとは限らず、実行時間や実際のプログラム開発は評価しない。[Cornell の走査順と局所性の教材](https://www.cs.cornell.edu/courses/cs3410/2025sp/assignments/cacheblock/instructions.html)を参照。

依頼489は４頁の書庫の費用４、速い棚１枠の費用２、棚での読取り１刻、取寄せを含む読取り６刻と仮定する。空の棚で ABABAB と ABCABC を読み、１・２・４枠の LRU を比較し、予算内で最短時間、同時間なら最小費用の棚を選ぶ。予算８の２頁と３頁では各２枠・１枠、予算12の３頁では４枠を選ぶ。各９構成の取寄せ・費用・時間を検証した。これは仮想の数値で、プロセッサ速度・電力や実機性能は評価しない。[Cornell の記憶階層](https://www.cs.cornell.edu/courses/cs3410/2026sp/notes/caches.html)を参照。
