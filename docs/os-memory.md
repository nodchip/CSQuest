# OS-Memory の対応状況

出典: [CS2023 OS-Memory](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 210–211。原典を要約した作業用一覧。依頼34・40はページ置換と住所変換を示す固定モデルであり、実 OS の挙動やプログラム開発能力を直接評価しない。

## トピック

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | 物理メモリ、アドレス変換、管理ハードウェア | 依頼40で固定ページ表による変換と保護の例。実機ハードウェアは未対応 |
| 2 | KA Core | キャッシュを含むメモリ階層が OS の仕組みと方針に与える影響 | 依頼25でキャッシュの固定例。CPU ごとのキャッシュや OS 方針への影響は未対応 |
| 3 | KA Core | 論理・物理アドレスとアドレス空間の仮想化 | 依頼40で４頁と３枠、依頼385で２プロセスの同じ仮想頁が別または同じ物理枠に対応する固定例。一般の仕組みは未対応 |
| 4 | KA Core | ページング、置換、スラッシング、ページと枠の割当 | 依頼34：３枠で FIFO と LRU を比較。依頼40で仮想アドレス変換、依頼137で２・３枠と繰返し参照の固定例。実際のスラッシングや一般の割当は未対応 |
| 5 | KA Core | メモリの確保・解放・格納手法の性能と柔軟性 | 依頼387で先頭適合・最小適合、外部断片化と隣接空きの結合の固定例。実時間や一般の割当は未対応 |
| 6 | KA Core | メモリキャッシュ、一貫性、脆弱性対策としてのフラッシュ | 未着手 |
| 7 | KA Core | サンドボックス、保護、分離と攻撃経路 | 依頼40で読み取り専用頁、依頼385で別枠と共有枠の固定例。攻撃経路や一般の保護は未対応 |
| 8 | Non-core | 仮想メモリのハードウェアを利用した OS の効率化 | 未着手 |

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | メモリ階層と費用・性能のトレードオフを説明 | 未着手 |
| 2 | KA Core | キャッシュ・ページングにおける仮想メモリの原理を要約 | 依頼34・40：３枠のページ置換と固定ページ表の住所変換。一般の原理と自由記述は未対応 |
| 3 | KA Core | 記憶容量とプロセッサ速度のトレードオフを評価 | 未着手 |
| 4 | KA Core | キャッシュの目的・利用と分離への影響を説明 | 依頼25：手元の棚の固定例のみ。分離や VM は未対応 |
| 5 | KA Core | ページ置換と枠割当を考慮した効率的なプログラムを開発 | 未着手。依頼34は置換を操作する固定例であり、実言語の開発能力は評価しない |
| 6 | Non-core | 効率的な仮想化へのハードウェア利用を説明 | 未着手 |

依頼34は同じ３枠に対する参照列 A B C A D A と A B C A D B を使う。前者の読み込みは FIFO ５回・LRU ４回、後者は FIFO ４回・LRU ５回。読み込みと置換を単純化し、書き戻し、並行する他の処理、実時間や実 OS の方針はモデル化しない。

依頼40は４住所ごとの仮想頁０〜３と、物理枠０〜２の固定表を使う。頁０→枠２、頁１→不在、頁２→枠０、頁３→枠１（読み取り専用）。全16仮想住所と読み書き両方について変換結果をテストする。フォールト後の読み込み、TLB や実 OS は扱わない。

依頼137は A B C を３回繰り返し、LRU の２枠では９回、３枠では最初の３回だけ頁を読み込む。必要な頁の数と枠数の関係を扱う固定例で、実時間、他のプロセス、書き戻しや実 OS のスラッシングは測定しない。

依頼387では空き長３・６・４の間に使用中の箱を置き、４個、次に６個を連続確保する。先頭適合は６個の空きから４個を確保して３・２・４となり、合計９個でも６個を確保できない。最小適合は４個の空きを使い６個を残す。前者は４個を解放し隣の空きと結合すると６個を確保できる。固定した領域・依頼であり、方式の一般的な優劣、管理情報や実時間は評価しない。[参考：OSTEP の空き領域管理](https://pages.cs.wisc.edu/~remzi/OSFEP/vm-freespace.pdf)
