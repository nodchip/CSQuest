# ４地域の操作と保存の見取り図

基準：公開版 8879744。既存の冒険記録を維持しながら拡張するための実装前の整理。

## 遷移

1. 鍛冶街または駅で道具の発送を見届ける（既存 `forgeStationSeen`）。発送後の場面で四方からお礼と知らせが届き、４地点が同時に地図に現れる。
2. 旅先の地図で地点を選ぶ → 地点の説明を確認 → 移動、または閉じて現在地にとどまる。地図の取り消し元は既存の `travelFrom` による。
3. 各地域の場面には人物と４つの依頼、地域の祭り準備、旅立ちを表示する。いずれの依頼にも最初から取り組める。
4. 依頼は状況を２〜３件続けて進める。操作のたびに状態を保存し、誤りは理由を表示して訂正できる。戻ると同じ地域に戻り、再開すれば途中から。全状況を終えると達成ダイアログを表示し、結果を見た後に地域に戻る。
5. 各地域で異なる依頼２件が終わると、その土地の祭りの２つの準備がそろう。４地域すべてそろった時だけ祭りの知らせを出し、確認すると祭りへ進む。祭り後も全依頼を遊べる。

## 保存の境界

- 既存 `completed` は依頼 ID の集合で、同じ依頼の再挑戦を重複計上しない。新しい ID を検証許可リストに追加する。
- 各依頼の操作履歴は新しい辞書に分け、再生と検証で途中状態を復元する。操作履歴が正しいことと、完了した依頼が全状況を満たすことを整合させる。
- 新項目のない古い保存には空の初期値を与える。発送イベント達成済みの保存は新４地域に進める。
- `mapVisited` は既存の移行方針を維持する。新しい地点の訪問フラグと祭りの知らせの既読状態を保存する。
- 無効なデータを検出した際に元の保存を上書きしない既存の保護と、保存失敗時の警告を維持する。

## 成立条件

地域ごとの準備数は `min(2, その地域の異なる達成済み依頼数)`。祭りは４地域すべての準備数が２のときだけ可能。合計８件でも偏りがあれば不可。祭りの既読状態は、既読時に条件が成立している場合だけ妥当とする。

## 検証上の懸念

- 現在の絵地図は12地点用の位置とモバイル用の別座標を持つ。16地点では各幅・拡大率の実表示を確かめる必要があり、座標の追加だけでは重なりの解消を証明できない。
- 既存 `show` は画面遷移時に先頭へスクロールする。依頼中の更新と達成ダイアログでは不用意なスクロールを起こさないよう、既存の依頼のように局所再描画と `preventScroll` を使う。
- 公開サイトでの操作確認は独立したブラウザ環境を使う。
