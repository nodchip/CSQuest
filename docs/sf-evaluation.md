# SF-Evaluation の対応状況

出典: [CS2023, SF-Evaluation](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 295–296。原典を要約した作業用一覧。依頼66は理想化した固定例で、実システムの性能を測定しない。

| 2 | CS Core | ワークロード、代表的ベンチマーク、測定と分析 | 依頼572で架空の仕事の構成比と合計時間を比較。実測や代表的ベンチマークは未対応 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 構成要素が性能改善にどう寄与するか説明 | 依頼572で命令構成・CPI・クロックと時間の固定例。一般の説明は未対応 |
| 2 | CS Core | 指標が有用な状況を説明 | 依頼254で平均遅延と処理量を比較。一般の指標と自由な説明は未対応 |
| 3 | CS Core | ベンチマークの利用と限界を説明 | 依頼572で一つの仕事と異なる構成比の固定例を比較。実測・一般の説明は未対応 |
| 4 | CS Core | アムダールの法則と限界を説明 | 固定の２例と理想化の限界を提示。自由な説明は未対応 |
| 5 | CS Core | 簡単な計算・限界検討による概算 | 依頼66で８条件の所要時間を選択。一般の概算は未対応 |
| 6 | CS Core | ツールで性能を測定・分析 | 未着手 |
| 7–8 | KA Core | システムや階層の性能実験を設計・実施 | 未着手 |

依頼254は、時刻０に到着した４通の完了時刻を `[1, 2, 3, 4]` と `[3, 3, 3, 3]` で比較する固定模型。平均遅延はそれぞれ2.5刻と３刻、４通を終えるまでの処理量は４通／４刻と４通／３刻。継続負荷の定常性能や実測値ではない。

依頼572は各100命令の P（計算80・記録20）と Q（計算20・記録80）。A は2GHz・計算1/記録4サイクル、B は1.5GHz・計算2/記録1サイクルと仮定。P の時間は A=80・B=120ns、Q は A=170・B=80ns。P９件・Q１件では A=890・B=1160ns、P１件・Q９件では A=1610・B=840ns。式・４組と２種類の合計を検査。固定 CPI と逐次処理の模型であり、実測・並列性・キャッシュ変動・I/O・一般のベンチマーク設計は扱わない。参考：[CMU、性能方程式](https://www.cs.cmu.edu/afs/cs/academic/class/15740-s17/www/lectures/02-isa.pdf)。

依頼573は２棚の直接対応付けで番地を２で割った余りを使う読出し模型。ヒット１サイクル、ミスは確認１と取寄せ４の計５。A=0・B=1 を交互に４回読むと２ミス12サイクル、A=0・C=2 では４ミス20サイクル、C を番地３に移すと２ミス12サイクル。番地０〜３の長さ４の全256列を独立模型と照合。書込み・ブロック・多重アクセス・実機測定は未対応。参考：[Cornell、キャッシュと平均アクセス時間](https://www.cs.cornell.edu/courses/cs3410/2025sp/notes/caches.html)。

依頼572の追加試験は、準備１刻と計算８刻の架空模型。最適化する方式では結果を使わない計算が省かれて１刻となり、結果を記録する場合と最適化しない方式は９刻となる。４条件と途中記録を検証した。これは実コンパイラやベンチマークの実行ではなく、結果を使うことだけで定数畳込みや測定準備などの問題が解消するとは限らない。参考：[OpenJDK JMH の不要な計算の削除の例](https://github.com/openjdk/jmh/blob/master/jmh-samples/src/main/java/org/openjdk/jmh/samples/JMHSample_08_DeadCode.java)。

同じ依頼の別の模型では、測定の固定費２刻、１仕事１刻を仮定する。１回なら合計３刻・１回あたり３刻、10回をまとめると合計12刻・１回あたり1.2刻であり、固定費の寄与が減る。仕事の時間自体は同じという仮定で、反復による状態変化や他の誤差は扱わない。参考：[OpenJDK JMH のまとめて測る例](https://github.com/openjdk/jmh/blob/master/jmh-samples/src/main/java/org/openjdk/jmh/samples/JMHSample_26_BatchSize.java)。
