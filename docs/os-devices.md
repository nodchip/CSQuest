# OS-Devices：装置管理

出典: [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.211–212。ゲームの固定模型は実機の装置やドライバーの開発を直接評価しない。

| トピック | 区分 | 内容と現状 |
|---|---|---|
| 1 | KA Core | バッファリング戦略。依頼129で通信路の容量０・１の固定例。装置のバッファリング戦略は未対応 |
| 2 | KA Core | DMA、ポーリング、メモリマップド I/O、DMA 通信の例。依頼105でポーリングと通知、依頼132で直接転送と DMA の固定模型。メモリマップド I/O、プロトコルと実装は未対応 |
| 3 | KA Core | 磁気ディスク・SSD などの永続記憶装置の管理と歴史的背景。未対応 |
| 4–6 | Non-core | 装置インターフェースと抽象化層、ドライバーの目的・実装・試験、装置通信の障害耐性。未対応 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1 | KA Core | 装置制御の構造と OS の仕組み・方針を説明。依頼105・132で固定した通知と転送の模型。実機構と自由な説明は未対応 |
| 2–4 | KA Core | 装置制御層、物理装置と仮想装置の関係、入出力のバッファリングと戦略を説明。未対応 |
| 5 | KA Core | DMA の利点・欠点と適用場面を議論。依頼132で転送中の仕事と準備・完了確認の費用を比較。実機の条件や一般的な判断は未対応 |
| 6 | Non-core | ドライバー作成の複雑さと実践。未対応 |

依頼132は宝石４つ、別の仕事３つ、１操作１刻の架空模型。CPU が直接転送する場合は転送４刻と仕事３刻で最短７刻。DMA は準備１刻、転送４刻、完了確認１刻で最短６刻であり、転送中の４刻に他の仕事を重ねられる。競合や遅延は含まず、DMA が常に速いとは言えない。
