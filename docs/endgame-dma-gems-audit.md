# 宝石の転送と DMA：教材監査

[CS2023 OS-Devices 印字211–212頁](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=211) の DMA の利点・欠点を扱う固定模型。旧 `src/dma.js` の依頼132を再利用し、現行の鍛冶街へ接続する。現行の `endgame-io` はポーリングと割込みの待機を比較し、今回の DMA による転送とは別の固定例。

宝石４個の転送と別の仕事３つ。直接方式は転送４刻と仕事３刻で計７刻。DMA は準備１刻の次から４刻で４個を転送し、その間に仕事を進められる。準備→仕事３刻→待機１刻→完了確認１刻の例は計６刻。開始前や転送完了後の不要な待機は選べないが、別仕事を準備前にする等の有効な順序も選べ、その場合６刻とは限らない。転送完了前の完了確認は拒否する。

固定の１刻単位・転送数・作業数で、共通バスやメモリの競合、通知、エラー、実装置、DMA のメモリ整合性、実性能は未評価。DMA が常に速いとはしない。[OSTEP の I/O Devices](https://pages.cs.wisc.edu/~remzi/OSFEP/file-devices.pdf)、[Linux DMA API](https://docs.kernel.org/core-api/dma-api.html) を参照。

## 独立レビューと動作確認

実装担当と別の担当が固定手順の時間、重なり、一般化の限界と保存・開放・焦点を確認。ローカルで集いと４地域の達成状態を用意した記録から、幅 213・390・1200 px で誤操作、キーボード、途中保存・再開と達成を確認した。冒険開始からの通し到達は含まない。
