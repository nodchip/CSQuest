# 谷の二つの台帳：照合記録

[CS2023 印字122頁 DM-Distributed](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 2c は複製と弱い整合性を扱う。[DynamoDB の結果整合な読取り](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadConsistency.html)は直後に完了済み更新を反映しない場合があると説明する。旧依頼190 `src/replica-lag.js` を現行冒険に再利用し、新規の範囲達成を主張しない。

初期４・４、分断中に本館を３に更新すると分館は４のまま。途切れ中の配送は失敗し、復旧操作だけでは４、別操作で配送後３。復旧と配送を分けるのは本模型の前提で、実機では自動配送もある。一度の更新、通信停止・回復、配送を操作する固定例であり、一般の結果整合性・強い整合性・永続性、複数更新、故障・欠落や実装を証明しない。

## 独立レビューと動作確認

実装担当と別の担当が複製値と配送、模型固有の規則、保存・開放・焦点を確認。達成 ID の許可漏れと操作後の古い状態による焦点移動を修正し、独立に再確認。ローカルで集いと４地域の達成状態を用意した記録から、幅 213・390・1200 px で誤操作、キーボード、途中保存・再開と達成を確認した。冒険開始からの通し到達は含まない。
