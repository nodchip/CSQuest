# AR-Memory の対応状況

原典: [CS2023 AR-Memory](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.104–105。固定の模型による操作であり、実機の計測や自由な説明は直接評価しない。

依頼103は合計容量４頁・完全連想・LRU の読出し専用模型。棚の確認が１、ミスの追加時間が５で、読み方２種類とブロック１頁・２頁を比較する。８回の合計時間は順次で28・18、１頁おきで28・48。ミス率と追加時間からの平均はそれぞれ 3.5・2.25・3.5・6。ブロックの転送時間を大きさにかかわらず同一とし、実ハードウェアの実測を意味しない。各アクセスは独立した LRU の参照計算と照合した。

依頼104では共有値０を A・B が読み、A が１を書き、B が再読する。書込みは共有値と A の写しを更新する。通知しない場合、B は古い０を読み、無効化の場合は共有値の１を読み直す。操作は順に完了し、単一アドレスだけを扱う。具体的なコヒーレンスプロトコル、通信中の競合と異なるアドレス間のメモリ順序は未対応。

依頼106は偶数パリティのハミング (7,4) 符号を用いる。位置３・５・６・７がデータ、１・２・４がパリティ。データ 1011 は符号 0110011。位置６の１ビット誤り 0110001 は不一致の組 ２と４から位置６を反転して元に戻る。位置３・５の２ビット誤り 0100111 も同じ不一致を示し、１ビットと仮定して位置６を反転すると別の有効符号 0100101 になる。元に戻る保証はない。全16データと全１・２ビット誤りを検証した。２ビット誤りを検出することと、１ビット訂正と同時に２ビット誤りを区別することは異なる。依頼107で全体パリティを加えた拡張方式の固定例を操作する。参考: [University of New Brunswick の解説](https://www.ece.unb.ca/tervo/ee4253/hamming.shtml)。

依頼110は A=5、B=2、C=2、D=1 の出現回数で、最小の２つを順に結ぶハフマン符号を構築する。４種類の固定２ビット符号の本体20ビットに対し、得られる接頭辞符号の本体は18ビット。符号木を伝える費用やファイル形式の追加情報は含まない。全ての貪欲な同順位・左右順を列挙し、符号が接頭辞なしであることと、独立した全結合順の最小コストを検証した。参考: [MIT の解説](https://math.mit.edu/~djk/18.310/Lecture-Notes/huffman_algorithms_2007.html)。

依頼455は４番地の揮発性の作業机と、電源断後も残る巻物を別々に操作する。番地１を２から９に書き換え、巻物に保存しなければ再読込後は２、保存すれば９。再開時に保存先を机へコピーし、保存が完了していると仮定する。[Micron のメモリ入門](https://www.micron.com/content/dam/micron/educatorhub/intro-to-memory/micron-intro-to-memory-presentation.pdf)を参照。全４番地と選択可能な３値を検査した。実機の起動・初期化、保存中の障害、一般のメモリ構造は扱わない。

依頼574は A・B が同じ１枠を使う固定模型。A を０から１、２と続けて更新して B を読むと、ライトスルーは主記憶への書込み２回、ライトバックは未反映の A を置換する際の１回となる。書込み前に A を読込み、書込みはヒットすると仮定する。書込みバッファ、他のキャッシュ、時間や永続性は扱わない。参考: [Cornell University のキャッシュ解説](https://www.cs.cornell.edu/courses/cs3410/2024fa/notes/caches.html)。

依頼795は直接対応と２ウェイの棚を組単位で操作し、LRU と２種類の参照列を比較する固定例。[項目別台帳](coverage-ar-memory.md)を参照。

依頼796は２棚の完全連想 LRU で先読みの有無と２列を比較し、要求ミスと要求・先読みの取寄せ回数を区別する固定模型。実行時間、並行転送や実際の先読み方式は未評価。[項目別台帳](coverage-ar-memory.md)を参照。
