依頼799では１秒間、描画10・20回と、描画ごと６歩・固定0.1秒ごと６歩を比較する。前者は60・120歩、後者はいずれも60歩。追加例は描画間隔を0.10・0.10・0.35・0.10・0.10・0.25秒とする。未処理時間を保持し描画ごと更新最大１回なら６回・36歩で0.40秒が残り、最大３回なら10回・60歩で未処理は０。最大１回で残った全更新分を捨て、0.1秒未満を保持する方式では６回・36歩、未処理０、捨てた時間0.40秒となる。更新・描画自体の所要時間を含まない固定模型で、実時間の計測、連鎖的な遅延、補間、衝突、ゲームエンジンの実装は扱わない。追加例は既存の達成条件に含まれない。参考：[MDN: ゲームループ](https://developer.mozilla.org/en-US/docs/Games/Anatomy)、[Fiedler: 固定時間更新](https://gafferongames.com/post/fix_your_timestep/)。

依頼117の操作比較は、仮想のＡ・Ｂを押下・解放し、同時押しと、Ａの後にＢを押す設定を比較する。一度に１つしか押せないという固定条件で両方を試した記録を残し、どちらで発動できるか振り返る。実機・実際の能力・入力時間・当事者の経験やゲーム全体の適合は評価せず、字幕の既存達成条件にも含めない。参考：[Microsoft の入力の選択肢](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/107)。

依頼800では、２次元を３×２区画に分け、画面と面積を持って重なる区画を選ぶ。区画にまたがる宝箱は複数区画へ登録し、候補は重複を除いてから画面との正確な重なりを確認する。上の画面では候補 A・B・C のうち B・C、探索者の衝突範囲では候補 B・C・E・F のうち E・F が重なる。７個すべてと正確に比べる代わりに、各々３・４候補を確認する。ただし、区画の登録や検索・重複排除の費用は数えず、実行時間の短縮は保証しない。辺に触れるだけは含めない模型。地図内の整数座標を端とする全ての非空長方形について、実際に重なる宝箱が候補に含まれることを検査した。回転・遮蔽・影・３次元・実測は未評価。参考：[MDN: 空間構造を用いた候補の絞込み](https://developer.mozilla.org/en-US/docs/Games/Techniques/2D_collision_detection)。

依頼799の場面模型では、精霊と像が同じ画像資産を使い、精霊だけが移動する。壁の衝突を有効・無効にし、画像の色を変えて２回ずつ更新する。実際のエンジンの内部動作や資産の共有方法を再現せず、元の依頼の達成条件に含めない。参考：[Godot: ノードと場面](https://docs.godotengine.org/en/latest/getting_started/step_by_step/nodes_and_scenes.html)。

依頼799の試作比較では、１回２歩で位置２の壁へ向かい、１回と２回の更新をそれぞれ位置０から試す。衝突無効では１回後は位置２、２回後は位置４となり、２回の例で通過が見つかる。衝突有効なら両方とも位置２。実行前に通過の有無を予想し、結果と比べる。設定の修正後に同じ２試験を繰り返すが、他の速度や場面、実ゲームの品質や性能は保証しない。元の依頼の達成条件には含めない。

依頼117のゲームデザインの例では、３本の矢に対し盾か回避を選び、盾が毎回補充されるルールと２回だけ使えるルールを比較する。盾２回と回避１回で無傷にする挑戦もあり、３通りの順序で達成できる。遊び手自身が感じ方を選ぶが、感じ方を正誤判定したり他者へ一般化したりしない。MDA の仕組み・遊び中の動き・体験を区別する入口であり、枠組み全体や実利用者の調査は未評価。元の字幕課題の達成条件には含めない。参考：[Hunicke ほか：MDA](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/)。
