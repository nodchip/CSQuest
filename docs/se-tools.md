# SE-Tools の対応状況

出典: [CS2023, SE-Tools](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 241–242。原典を要約した作業用一覧。依頼59は項目単位の簡略例で、ツールを使えることを証明しない。

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 集中型と分散型の構成管理の違いを説明 | 依頼655で切断中の編集・版の記録、共有先の先行変更と統合を比較。一般の実装や自由な説明は未対応 |
| 2 | CS Core | リリース管理への版管理の利用を説明 | 依頼655で固定した目印と先端の版・試験結果を比較。実際のリリースや自由な説明は未対応 |
| 3 | CS Core | チームで構成項目を特定し版管理ツールを使う | 固定された記録の統合のみ。実ツールとチーム作業は未対応 |
| 4 | KA Core | 静的・動的試験ツールの開発環境への統合 | 未着手 |
| 5 | KA Core | 共有コードの状態を把握する CI | 依頼656で検査結果と対象版を対応づける固定例。複数の実行や実ツールは未対応 |
| 6 | KA Core | プロジェクト向けのツール選択を検討 | 未着手 |
| 7 | KA Core | 中規模製品の開発にツールを使う | 未着手 |

依頼59では３者の値を項目ごとに比べ、競合を見つけた後、提示された代表者の希望を選択する。実際の Git の行単位のマージや、統合結果の意味的な正しさの保証ではない。

依頼655は同じ項目を北・南に変更する２人の固定例。集中型の模型では切断中の編集は残るが共有先へ記録できず、分散型では手元に記録してから共有先の変更を取得・統合する。競合のどちらの解決案も扱い、履歴の再生を検査。別の固定例で、試験済み R1 を指す目印と未試験の先端 R2 を比較する。目印自体は移動・削除可能で品質を保証しない。実際のツール操作、任意の競合、実リリースや試験の正しさは評価しない。[Git: Version Control](https://git-scm.com/book/en/v2/Getting-Started-About-Version-Control)、[Git: Tagging](https://git-scm.com/book/en/v2/Git-Basics-Tagging)。

依頼656は、版を固定して取得・材料の準備・組立・試験を進める模型。古い成功記録を別の版に使えないこと、試験失敗と、検証を省いた古い材料の復元による組立失敗を確認する。成功は実施した試験の範囲に限られ、材料表だけでは実行環境など全入力を固定できない。実 CI の自動起動、並行実行や依存関係ツールの実動作は扱わない。[GitHub Docs: Dependency caching](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching)。

依頼657では、割り算直前のゼロ確認のみを調べる静的規則と、実際に選んだ人数を通す試験を比較する。別の助け手がゼロを断る門への警告は、この模型での誤検出。人数の上限を誤った門では、静的規則も３人の試験も欠陥を見つけず、５人の境界試験が仕様との不一致を示す。修復後の再検査も行う。任意のプログラム、実ツールの統合や警告の一般的な分類は評価しない。[OWASP: Static Application Security Testing](https://devguide.owasp.org/en/05-implementation/05-static-analysis/)。
