依頼795では各４棚の直接対応と２ウェイ・組内 LRU を、２つの８参照列で比較する。前者はヒット０対６、後者は５対４。２ウェイで組数が減ることで干渉する組合せも変わる固定例であり、全ての参照列・方針・実機で性能が決まることを示さない。独立した LRU 模型と４種類の巻物・長さ５の全1,024列×２方式を照合し、各方式の途中復元も検査した。参考：[Cornell: キャッシュ](https://www.cs.cornell.edu/courses/cs3410/2026sp/notes/caches.html)。

依頼796では２棚の完全連想 LRU と、ミス後に次の巻物を取り寄せる方式を比較する。要求列 0・1 の反復は要求ミス２→１、取寄せ合計２→２。要求列 0・2 の反復は要求ミス２→６、取寄せ合計２→12。先読みは要求に先立ち完了し、最後の要求の後も行い、既にある先読み対象は再取得せず使用順も変えない。４値・長さ５の全1,024列×２方式を独立模型と照合した。実際の待ち時間・帯域・重なりや一般の先読み性能は示さない。参考：[University of Michigan: sequential prefetching and cache pollution](https://www.cse.umich.edu/techreports/cse/99/CSE-TR-389-99.pdf)。

依頼1009は 107 の拡張ハミング符号を使い、巡回点検なし、２つの一時的な誤りの間の点検、両誤りの後の点検を比較する。高々２ビットの異なる一時的誤りを仮定し、１ビット訂正時は書戻し、２ビット検出時は通知・利用停止とする。[Intel の RAS 解説](https://www.intel.com/content/www/us/en/developer/articles/technical/pmem-RAS.html) は巡回による誤り訂正と訂正不能時の処理を説明する。恒久故障、３ビット以上、実装の通知・復旧、確率や点検費用は評価しない。`tests/memory-scrub.test.js` で符号と診断、各操作、途中記録を検査する。

依頼1011は依頼1008・1009・1010の限定模型を遠征内で再利用し、命令の実行、記憶の読取り、薬棚の審査を順に使う。`tests/guild-relay.test.js` で進行条件、失敗からの回復、途中記録を検査する。個々の題材の限界は上記の通り。
