# SE-Design: ソフトウェア設計

参照：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.243–244。依頼223は単一の倉庫で固定された入力を試す模型です。実際の API を設計・実装する能力や一般の正しさを評価するものではありません。

| 分類・トピック | 対応と不足 |
| --- | --- |
| CS Core 1 抽象の段階、関心の分離、情報隠蔽、結合度・凝集度 | 依頼224で画面・受付と倉庫の内部形式・公開操作の依存を比較し、依頼225で変更影響を比較。一般の結合度・凝集度の評価は未対応 |
| CS Core 2 設計パラダイム、標準アーキテクチャ、部品境界と依存関係 | 依頼151・152で処理の受け渡し、依頼224で３部品の依存の固定例。一般のアーキテクチャと部品設計は未対応 |
| CS Core 3 大規模と小規模のプログラミング | 未対応 |
| CS Core 4 正しさとは別のコード品質・コードスメル | 依頼680で現在の有限試験に合格する重複した数量確認と共有設計を比較し、一方だけ変更した際の食い違いや誤った共通化を調査。一般の品質分析や実コードの改善は未対応 |

| KA Core 6 データと時間の不変条件の識別・明文化 | 依頼223で在庫の非負と拒否時の状態保持を固定試験で確認。時間の不変条件や一般の明文化は未対応 |
| KA Core 7 構造・振る舞いのモデル | 依頼226で正常時と在庫不足時の部品間の伝言を順に並べる固定例。一般のモデル作成は未対応 |

| Non-core 11 設計品質の測定と分析 | 未対応 |
| Non-core 12 安全な設計とコーディング：最小権限、安全側の初期値、心理的受容性 | 依頼11で固定の役割別許可を比較。一般の設計原則は未対応 |
| Non-core 13 効率・信頼性、セキュリティ・使いやすさなどの設計上のトレードオフ | 依頼680で重複箇所・変更時の不一致と元の振る舞いの保持を固定例で比較。効率・セキュリティ等の一般的な比較は未対応 |

依頼680では店頭と配達の数量確認を別々に持つ設計と、数量確認だけを共有する設計を７注文で比較する。両方とも元の有限試験に合格するが、上限変更時に別々の店頭側だけを変更すると配達側が旧条件のまま残る。配達料を消す案と、拒否前に在庫を引く案はそれぞれ代金・在庫の期待を破る。現在の動作を保つ構造変更と、その後の仕様変更を区別する。試験は有限で、一般の振る舞いの同値性や変更費用を証明しない。参考：[Martin Fowler、Refactoring](https://refactoring.com/)、[Code Smell](https://martinfowler.com/bliki/CodeSmell.html)。
