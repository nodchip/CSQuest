# SE-Validation の対応状況

出典: [CS2023 SE-Validation](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 246–249。原典を要約した作業用一覧。依頼23の小さな固定例は、実際のソフトウェアの試験計画・実装や自由な説明能力を直接評価しない。

依頼251では元の門が１〜５人を通し、変更Ｂは１人を拒否、変更Ｃは６人を通す。０人と２人の試験は元の門の最終判定の真・偽をともに通るが、どちらの変更も検出できない。１人と６人を含む試験なら両変更を検出できる。複合条件の個々の評価、一般的な分岐網羅や他の変更の検出は評価しない。

依頼252では朝の在庫３個が正午前に０個になった場面を扱う。朝の数を正午まで示す旧仕様と旧実装は一致するが、取り出し直後の在庫を知りたいという固定の利用目的には合わない。村と合意した新仕様と実装を即時表示に変えると、この場面では両方に一致する。実利用者との検証や複数場面での製品全体の妥当性は評価しない。

依頼253は在庫３・依頼１の単体、統合、システム、受入の各固定試験を比較する。倉庫の計算の誤りは４試験、受付が異なる数を渡す誤りは統合以降の３試験で不一致となる。古い表示仕様と利用目的のずれは、仕様を期待値とするシステム試験では一致し、目的を期待値とする受入試験では不一致となる。これらは一例で、試験の種類だけで検出範囲が決まるわけではない。

依頼23は仕様「１〜５人を通す」に対し、最大３件の候補を選んで三つの固定された実装の結果を比較する。境界にある二つの不具合は発見できるが、一般的な網羅や欠陥がないことを証明するものではない。

依頼254では、同時に到着した４通について受付方式ごとの平均遅延と、全４通を終えるまでの処理量を比較する。実システムの性能測定は行わない。
