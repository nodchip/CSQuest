依頼67では村番号 V1・V2 が同じ村名を持つ。V1 の一行だけ名前を更新すると食い違いが残る。注文・村番号と村番号・村名を番号で結ぶと元の３行、注文・村名と村番号・村名を名前で結ぶと追加３行を含む６行になる。この一例の結果から任意のデータでの無損失性を主張しない。

依頼464は村１を参照する依頼１・２と、村２を参照する依頼３を使う。参照中の削除を拒否する方式では、依頼１・２を削除してから村１を削除する。連鎖する方式では、村１と依頼１・２が同時に削除され、どちらも村２と依頼３は残る。[PostgreSQL の外部キー](https://www.postgresql.org/docs/current/ddl-constraints.html)を参照。削除順と履歴復元を検査した。NULL、遅延制約、更新時の動作、実 SQL や業務判断は扱わない。

依頼466は３属性の規則 {A→B, B→C} と {AB→C, C→B} から閉包を操作する。前者の A は候補キー、後者の A はスーパーキーではなく AC は候補キー、ABC は最小でないスーパーキー。各規則集合・全８初期集合について、２行の全組による関数従属性の反例探索と閉包を照合した。[Cornell の属性閉包](https://www.cs.cornell.edu/courses/cs330/2004sp/slides/CIS330-lecture11-03-02-2004-Normalization.pdf)を参照。固定の属性と規則であり、一般の正準被覆・分解の証明は扱わない。

依頼466の追加実験では３属性の空でない左辺と、それに含まれない単一右辺の９規則を任意に選び、８種類の開始集合の閉包と候補キーを調べる。右辺が複数の規則は単一右辺の組として扱える。全512規則集合・８開始集合を２行の全組による反例探索と照合し、候補キーの最小性も検査した。空左辺、４属性以上、正準被覆の計算は扱わない。

依頼466の簡約実験では {AB→C, A→B, A→C, C→B} から左辺の余分な属性と冗長な規則を取り除く。各操作の可否を属性閉包で判定し、重複を統合する。操作で到達可能な全状態について８種類の開始集合の閉包が初期状態と一致することを検査した。一般の任意入力や分解アルゴリズムは未対応。[Emory University の最小被覆](https://www.cs.emory.edu/~cheung/Courses/377/Syllabus/9-NormalForms/FD-equi-3.html)を参照。

依頼466の分解実験では３属性と単一右辺の９規則の任意集合に対し、２つの真部分集合による分解を操作する。共通部分の閉包による無損失判定と、分解先への依存性の射影を用いた保存判定を行う。全512規則集合と有効な分解を、２行の同値パターン列挙および独立に構築した射影規則と照合した。空左辺の入力、４属性以上、３つ以上の分解、自由記述の論証は扱わない。[RPI の正規化講義](https://cs.rpi.edu/~sibel/csci4380/fall2020/course_notes/normalization.html)を参照。

依頼466の正規形実験は、３属性の値が原子的で 1NF を満たすと仮定する。９規則の任意集合から導かれる依存と候補キーを調べ、1NF・2NF・3NF・BCNF のうち最も厳しいものと違反例を表示する。全512規則集合について、２行の同値パターンに基づく独立判定と照合し、４段階の代表例も検査した。自由なスキーマ、原子性の判定、4NF・5NF、実際の設計判断は扱わない。[Juniata College の正規化講義](https://jcsites.juniata.edu/faculty/rhodes/dbms/normalization.htm)を参照。

依頼467は同一の薬師について薬草２種と届け先２か所を使う。独立の約束では４組すべてが必要であり、２台帳に分けて結び直しても同じ４行となる。一方、２つの対応だけが許される場合、分解後の結合は余分な２行を生む。全16行集合について射影と結合を別実装と照合した。固定例であり、任意の多値・結合従属性の導出や５NFは扱わない。[Stanford の多値従属性と４NF](https://i.stanford.edu/~ullman/fcdb/aut07/2006/lecture_notes/06-Normalization.html)を参照。
