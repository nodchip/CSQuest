# FPL の翻訳・構文解析・意味解析の対応

原典 CS2023 pp.139–141。依頼75は、固定された３つの算術式について、演算子を選んで左右の部分を抽象構文木として結び、規則に基づく構造と値を比較する。プレイヤーが文法や実コードを記述する演習ではない。

## FPL-Translation トピック

| 区分・番号 | 原典の対象 | 対応 |
|---|---|---|
| CS Core 1–4 | インタプリタ・コンパイラ・JIT、中間コード、それぞれの長短、クロスコンパイラ | 依頼311・312で解釈・事前翻訳・実行時翻訳の固定模型。中間コードや一般の比較は未対応 |
| CS Core 5 | BNF・拡張 BNF による文脈自由文法 | 依頼309で２規則の文法の導出を操作。一般の文法記述は未対応 |
| CS Core 6 | 簡単な文の構文木 | 固定した算術式の抽象構文木のみ。具体構文木は未対応 |
| CS Core 7–8 | ネイティブ・仮想機械での実行、翻訳の各段階 | 未対応 |
| KA Core 9 | オブジェクトや関数の実行時表現 | 依頼52・65はクロージャ・動的な振る舞いの固定例。実行時表現は未対応 |
| KA Core 10 | 安全なコンパイラ開発 | 未対応 |

例示学習成果: CS Core 1 は依頼311・312で解釈と事前・実行時翻訳の固定例。3、5 と一般的な比較は未対応。2 は構造構築と値を分けて表示する一例のみで、構文・解析と意味・評価の一般的区別は未評価。4 は固定した抽象構文木のみで、任意の式や具体構文木は未対応。6 は依頼75・310で算術式の結合と曖昧な文法の固定例。一般の曖昧性や条件文は未対応。KA Core 7 の到達可能性とガベージコレクションは未対応。

## FPL-Syntax トピックと成果

Non-core トピック 1 の正規文法と文脈自由文法の一般的な比較、2–3 は依頼313で最長一致と予約語を含む字句解析の固定例。一般の走査・解析は未対応。4 は固定例のトークンのみ。5 の解析方式・先読み表は未対応。6 は依頼309・310で導出と曖昧性の固定例。一般の言語理論や文法変換、7 の誤り回復、8 の生成器は未対応。例示学習成果 1–3 は未対応。4 は依頼75・310で算術式の優先順位・結合と曖昧な文法の固定例。一般的な構文定義の分析は未対応。

## FPL-Semantics トピックと成果

Non-core トピック 1 の抽象構文木は固定された演算子と数の木のみで、具体構文との比較全般は未対応。2 の表現の構築は固定例のみで、一般の走査・変換は未対応。3–8 のうち、依頼306で値渡し・参照渡しの固定例。一般のスコープ・束縛、静的意味解析、左辺値・右辺値、他の呼出し・引数渡し方式、属性文法は未対応。例示学習成果 1 は固定の木の組立てのみで、任意の小言語の木を描く能力を評価しない。2–3 は未対応。

依頼310は「式→数｜式−式」の規則と３個の数の２例を使い、同じ文字列の２種類の構文木と左結合を比較する。一般の曖昧性の判定や実際の言語の規則は未対応。参考：[MIT: Ambiguity in Grammar](https://ocw.mit.edu/courses/6-035-computer-language-engineering-spring-2010/c6ce16f57edc535c1d0e425095be68e9_MIT6_035S10_lec02.pdf)。

依頼311は巻物を読みながら動く模型と、事前に成果物を作る模型で、巻物変更後の古い成果物と再翻訳を比較する。中間表現、実際の性能と一般の翻訳器は未対応。参考：[MIT: Compilers and Interpreters](https://ocw.mit.edu/courses/1-124j-foundations-of-software-engineering-fall-2000/pages/recitations/recitation_6/)。

依頼312は２回と５回の固定例で、初めの２回を解釈し３回目に翻訳する架空の実行時コンパイル模型を操作する。費用は架空の値で、実際の JIT の動作や性能を保証しない。参考：[Oracle: Java Virtual Machine Technology Overview](https://docs.oracle.com/en/java/javase/26/vm/java-virtual-machine-technology-overview.html)。

依頼313は英小文字・数字・等号と空白の固定例で最長一致を使い、英字全体が if に一致する場合のみ予約語として分ける。構文解析や実言語の字句規則全体は未対応。参考：[Cornell: Lexer and Parser Generators](https://www.cs.cornell.edu/courses/cs3110/2019fa/manual-4.8/lexyacc.html)。
