# NC-Routing の対応状況

出典: [CS2023 NC-Routing](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 199。原典を要約した作業用一覧。依頼48は一つの宛先と固定ネットワークのモデルであり、実際のネットワーク全体を再現しない。

## トピック

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | 経路制御の方式と階層、ドメイン内外、集中・分散、送信元経路、仮想回線、品質 | 依頼48の固定経路、481の同期距離ベクトルと障害後の更新、482のリンクステートと最短経路。階層や品質は未対応 |
| 2 | KA Core | 転送表と照合方法 | 依頼48で次の塔を設定し、依頼61で８ビットの架空宛先と最長接頭辞を照合。実 IP 転送表の設定は未対応 |
| 3 | KA Core | IP と規模拡張、NAT、CIDR、BGP、IP の版 | 依頼61は可変長接頭辞、320は NAT とポート変換の固定例。依頼480で８ビットの経路集約と例外を操作。依頼483で AS 経路・方針・ループと撤回の固定例。一般の BGP と IP の版の比較は未対応 |

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | 経路制御の方式と階層を説明 | 依頼481・482で距離ベクトルとリンクステートの固定例を操作。一般の方式や自由記述は未対応 |
| 2 | KA Core | IP 網でのパケット転送を説明 | 依頼48の次の塔と回数制限、依頼61の最長接頭辞を操作。IP ヘッダー・実網の転送・自由記述は未対応 |
| 3 | KA Core | インターネットの規模拡張への対応を説明 | 依頼480で経路集約と例外の固定例。一般の規模拡張や自由記述は未対応 |

依頼48では S–A、S–B、A–B、A–G の費用が１、B–G が４。各塔の城 G への転送先を設定し、S・A・B の３地点からの手紙を１ホップずつ進める。巡回を含め最大５ホップで停止する簡略モデル。S→A、A→G、B→A の設定では費用はそれぞれ２・１・２。全18設定を独立した単純経路の列挙と照合し、各出発地点からの最小費用を検証する。転送表の更新で全試行をリセットする。

依頼61は８ビットの架空宛先に対し、長さ０・１・３・４の固定接頭辞の一致と最長の送り先を選ぶ。全256宛先を独立した整数範囲による判定と照合。実際の IP アドレス、経路学習、同じ長さの候補の優先順位は操作しない。

依頼480は８ビット宛先で 00 と 01 の送り先を比較し、共通の 0 への集約と長い 01 の例外を操作する。５札の全32選択と256宛先を整数範囲の独立判定と照合し、固定選択肢での最少枚数２・３も全列挙した。実 IP、BGP の広告・障害・経路方針は扱わない。[RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)を参照。

依頼481はＡ−Ｂ費用１、Ａ−城５、Ｂ−城１の同期距離ベクトルを操作する。初回交換でＡは２、Ｂは１。Ｂ−城の切断後、古い値を同時交換すると (Ａ,Ｂ) は (2,3)、(4,3)、(4,5)、(5,5)、(5,6) と変化し、途中は互いを次の塔に選ぶ。各段階の再計算と保存を検査した。分割水平線・非同期更新・実 RIP は扱わない。[RFC 2453](https://www.rfc-editor.org/rfc/rfc2453.html)を参照。

依頼482は４塔の隣接情報を受け取ったと仮定し、Ａからダイクストラ法で塔を確定する。Ａ−Ｂ=1、Ａ−Ｃ=4、Ｂ−Ｃ=2、Ｂ−城=6、Ｃ−城=1 で、城への最短費用は４。単純経路の全列挙と照合した。実際の OSPF の信頼できる配布、障害、区域、同値経路は扱わない。[RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html)を参照。

依頼483は自国 AS10 が AS20・AS30 の経路列を比較し、同じ優先度なら短い列、高い優先度なら長い列を選ぶ。自国を含む経路は除き、撤回された候補は選ばない４状況を検証した。BGP の経路属性・方針の一部を単純化した模型であり、全属性、到達性、広告処理、実運用や安全性は扱わない。[RFC 4271](https://www.rfc-editor.org/rfc/rfc4271.html)を参照。
