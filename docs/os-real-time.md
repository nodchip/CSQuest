# OS-Real-time：リアルタイム・組込みシステム

出典: [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.214–215。固定した２仕事の模型は、実際のリアルタイムシステムの安全性や設計能力を直接評価しない。

| トピック | 区分 | 内容と現状 |
|---|---|---|
| 1–2 | KA Core | 仕事のスケジューリング、期限とリアルタイムの問題。133で同時到着の２仕事、134で優先度継承、757で周期優先と期限優先の固定例。一般の到着・優先度・遅延は未評価 |
| 3 | KA Core | 低遅延、ソフトリアルタイム、ハードリアルタイム。133で期限超過、760で平均・期限超過と異なる要件を比較。一般の実例や実機は未評価 |
| 4–6 | Non-core | 758で頁の事前取寄せ・固定、395で遮蔽時の判断、752で装置の復旧、759で監視期間と再起動開始を比較。一般の記憶・ディスク要件、実際の復旧と実機の安全性は未評価 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1 | KA Core | リアルタイムシステムの特徴を説明。依頼133で結果が期限内に得られることの重要性を固定例で扱う。自由な説明は未対応 |
| 2–3 | KA Core | 遅延の要因と性質、リスクと対策を説明。固定例では切り替え費用や実装遅延を仮定せず、一般の説明は未対応 |
| 4 | Non-core | 実際のリアルタイム OS の機能と仕組みを説明。未対応 |

依頼133は時刻０に到着する仕事 A（１刻、期限２）と B（２刻、期限３）を１人が切り替え費用なしで実行。A-B-B と B-A-B はどちらも期限内。B-B-A は A が時刻３に完了し期限超過。期限ちょうどの完了は間に合う。この固定モデルは動的な到着、実行時間の変動、装置遅延や現実の安全性を扱わない。
