# 庭園の灯り絵と深度：範囲と未完了

[CS2023 印字 158 ページ（PDF 158 ページ目）GIT-Rendering 4c](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) は可視性と遮蔽、その解法として深度バッファ等を含む。[W3C WebGPU 仕様](https://www.w3.org/TR/webgpu/)は深度値の比較方法と深度書き込みの設定を規定する。

旧 `depth-buffer.js` は現行冒険からの到達を示さない。追加前の庭園には画素、画像寸法、色や行列の依頼があるが、深度判定の依頼はなかった。今回の固定模型は、不透明な灯り、小さい値が手前、最初は画素の色なし・深さ未記録、厳密に小さい深度だけを採用し深度書き込みを行う設定である。描画順による単純な上書きと比較し、同じ深度では先着が残る二つの順序、画素ごとに別々に比較する例を扱う。失敗時は色・深度とも保持する。

別の比較設定では等深度の結果が変わり得る。透明物の合成、投影・深度の精度、一般のシーン、描画 API・GPU・シェーダーの実装、レイトレーシングとの比較や自由な説明は検証していない。GIT-Rendering 4c およびその広い学習成果は部分対応である。

`garden-depth-painter` と `garden-depth-buffer` の２件を終えると `garden-depth-equal` が開く。庭園の依頼分類から選び、地図の全達成判定にも含まれる。

実装担当とは別の `review_candidate` が原典、上記 W3C 仕様と [Khronos の深度比較](https://registry.khronos.org/OpenGL-Refpages/gl4/html/glDepthFunc.xhtml)、固定例の色と深さ、等値・別画素の結果、説明、分類と保存をコード上で確認した。指定順に描いて結果を見る操作であり、一般的な描画結果の予測能力を直接評価したものではない。レビュー担当自身はブラウザを操作していない。

`tests/endgame-depth.test.js` は描画順、奥の不採用、等深度の先着、画素間の独立性、誤操作と途中履歴を確認する。`tests/late-region-quest-groups.test.js` は分類と開放を確認する。`scripts/endgame-depth.playwright.js` は集いと４地域などの達成を用意した検証用記録から、213・390・1200 px 幅で分類からの到達、キーボードによる依頼と回答、誤答の案内、途中復元、段階開放、３依頼の達成と達成後の再開を確認した。新規開始からこの依頼群までの通し操作、実際のスクリーンリーダー音声、利用者による面白さの評価は未確認。
