# OS-Files の対応

出典: CS2023 p.212。依頼77は Linux 系の単純化した通常ファイルを対象に、二つの名前が同じファイルを指す場合、片方の名前の削除、開いたまま最後の名前を削除した後の読取り、最後の参照を閉じる操作を扱う。根拠: Linux man-pages の [link(2)](https://man7.org/linux/man-pages/man2/link.2.html) と [unlink(2)](https://man7.org/linux/man-pages/man2/unlink.2.html)。特定ファイルシステムの全動作を再現するものではない。

## トピック

| 分類・番号 | 内容と状態 |
|---|---|
| KA Core 1 | ファイルのデータ、メタデータ、操作、アクセスモード。依頼77で名前と参照、384で読み取り用・書き込み用に開く操作と返り値の固定例。メタデータや一般のモードは未対応 |
| KA Core 2 | マウント。依頼291でマウント先と隠れる元の内容の固定例。一般の実装は未対応 |
| KA Core 3 | ファイルのアクセス制御。依頼384で読取可・書込不可の固定例。一般の権限モデルは未対応 |
| KA Core 4 | ファイル共有。複数名が同じ実体を指す限定例。複数利用者は未対応 |
| KA Core 5 | 依頼576で連続・連結・索引割当ての固定例。FAT の表や一般の方式は未対応 |
| KA Core 6 | 依頼77で名前と実体、576で分散した空き棚への割当ての固定例。一般のディレクトリと識別方式は未対応 |
| KA Core 7 | 依頼576で空き領域の分散と３頁目を読む棚の数を比較。解放・圧縮、実際の性能は未対応 |
| KA Core 8 | 空き領域の管理方式。未対応 |
| KA Core 9 | ディレクトリの実装と位置管理。名前と実体の関係の固定例のみ。実装は未対応 |

## 例示学習成果

KA Core 1–2 は依頼576で固定条件の割当て方式の比較を扱う。一般の設計選択・評価と 3 の実装知識に基づくソフトウェア構成は未対応。依頼77は操作の意味を体験する一例であり、実 OS の API を使う能力を評価しない。

依頼576は８棚中０・２・３・５・６が空きという固定例で、３頁の連続配置はできないが連結なら３棚、索引なら索引用１棚と頁用３棚を選べる。連結の開始位置と索引の位置のみ既知でキャッシュなしと仮定し、３頁目の読込みは前者が３棚、後者が２棚。空き配置・選択順と学習上の仮定を示し、速度の実測や FAT の実装は扱わない。参考: [UIC のファイルシステム実装](https://www.cs.uic.edu/~jbell/CourseNotes/OperatingSystems/12_FileSystemImplementation.html)。
