# AR-IO：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.105。[既存の調査](ar-io.md)と依頼を照合した。状態の意味は[追跡方法](coverage-status.md)を参照。親を重複計上せず、1 と 5 は子項目で追う。

## トピック

| 番号 | 区分 | 内容 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1a | CS Core | ハンドシェイクとバッファ | 部分 | 454 は１枠の有効・受取可能、OS の別の依頼は二重バッファの模型。一般の回路や容量は未評価。 |
| 1b | CS Core | プログラムによる入出力 | 部分 | 105 の固定時間のポーリング。実装全般は未評価。 |
| 1c | CS Core | 割込み駆動の入出力 | 部分 | 105 は１装置の通知・処理・復帰。複数装置と実機は未評価。 |
| 2 | CS Core | ベクタ、優先順位、割込み応答 | 部分 | 105 は１通知のみ。ベクタ、優先順位、応答の仕組みは未評価。 |
| 3 | CS Core | 入出力装置 | 未照合 | 105 等は架空の装置。原典例の機器と機能をどこまで扱うか要確認。 |
| 4 | CS Core | 外部記憶の物理構成と装置 | 部分 | 749 の磁気ディスクと SSD、750 の頁・消去ブロックの模型。実機全般は未評価。 |
| 5a | CS Core | バスのプロトコル | 部分 | 454 の有効・受取可能の受渡し。具体的なバス規格や電気的タイミングは未評価。 |
| 5b | CS Core | バス調停 | 部分 | 819 で固定優先と巡回優先の４刻を比較。実バスの転送中保持、受付制限、遅延や一般の公平性は未評価。 |
| 5c | CS Core | DMA | 部分 | 132 で転送と CPU の別作業の重なりを比較。バス競合と実装は未評価。 |
