# FPL-Systems：ヒープの再利用の教材評価

2026-11-06 に [CS2023 印字 p.139](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の CS Core トピック６c と依頼786を照合した。判定は「部分」。

依頼は棚100への宝石Ａの確保、合鍵の複製、返却、同じ棚または別の棚への宝石Ｂの確保を操作する。管理された鍵には番号と世代があり、同じ棚の再利用後も古い鍵を拒否し、新しい鍵を受け入れる。これは [CWE-416 の解放後使用](https://cwe.mitre.org/data/definitions/416.html)を理解するための模型で、[slotmap の世代付きキー](https://docs.rs/slotmap/latest/slotmap/)の方式も参照した。一般のポインタが世代を検査するという主張ではない。

`tests/arena-reuse.test.js` の３テストで両場面の状態、各段階の誤操作、鍵の照合と途中記録の再生を検査した。公開版の390px幅で両場面を操作し、振り返りと達成を確認した。

確保・解放・再利用の選択肢は固定であり、任意のメモリアロケータ、自由なプログラミング、実際の解放済みポインタの動作や有限の世代番号の周回への対策は評価しない。この例だけで手動メモリ管理全般の能力を証明しない。
