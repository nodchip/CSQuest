# OS-Concurrency：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.208。[既存の調査](os-concurrency.md)、依頼の実装・テストを照合した。状態は[追跡方法](coverage-status.md)に従う。有限の模型は実 OS や実コードの作成・分析能力を直接評価しない。

## トピック

| 番号 | 区分 | 要約 | 状態 | 対応例と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | スレッドの抽象と並行性 | 部分 | 179で同一プロセス内の２作業の共有を比較。実スレッドの状態や API は未評価。 |
| 2 | CS Core | 競合、クリティカル領域と割込み | 部分 | 15・16で更新喪失と排他を操作。実 OS と割込みの関係は未評価。 |
| 3 | CS Core | デッドロックと飢餓 | 部分 | 30・631で循環待ち、177で飢餓と優先度上昇を比較。一般の保証は未評価。 |
| 4 | CS Core | 複数プロセッサ、スピンロックと再入 | 部分 | 567で原子的な検査・設定、568で呼出しごとの作業状態を比較。実機のメモリ順序や一般の再入安全性は未評価。 |
| 5 | CS Core | 複数プロセスと複数スレッド | 部分 | 179・627で記録の共有と値の転送を比較。一般の資源管理や通信は未評価。 |
| 6 | KA Core | スレッドの生成・状態・構造 | 部分 | 628で生成・終了・合流を操作。一般の状態遷移や構造は未評価。 |
| 7 | KA Core | スレッド API | 部分 | 628で生成・join・detach に対応する模型を操作。実 API とエラー処理は未評価。 |
| 8 | KA Core | デッドロックと飢餓の条件・緩和 | 部分 | 30・631で４条件と取得順・一括取得、177で飢餓を比較。一般の緩和策・公平性は未評価。 |
| 9 | KA Core | セマフォ・ミューテックス・条件変数による安全な実装 | 部分 | 16・178・629で排他、セマフォ、待機後の再確認を操作。実装と一般の同期機構は未評価。 |
| 10 | KA Core | 共有メモリの競合 | 部分 | 15で読取りと書込みの順序を操作。一般の実行や実メモリモデルは未評価。 |
| 11 | Non-core | OS オブジェクトの原子的アクセス、鍵の粒度、ロックなしの構造 | 部分 | 567で原子的な操作、630で鍵の粒度、814で比較交換と再試行、815で ABA と更新番号を固定模型で比較。一般のロックなしリスト、実 OS のオブジェクトや性能は未評価。 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | OS の並行処理の利点・欠点 | 部分 | 53で待機中の別作業、15で更新喪失を操作。OS 全体での評価は未評価。 |
| 2 | CS Core | アーキテクチャ上の実行と競合の関係 | 部分 | 15で読取り・書込みの順序を比較。実命令やメモリ階層との関係は未評価。 |
| 3 | CS Core | 複数プロセッサの並行処理の問題 | 部分 | 104で単一値のキャッシュ無効化を操作。一般の問題は未評価。 |
| 4 | KA Core | OS の並行処理機構と各機構の利点 | 部分 | 16・178で排他と待機・通知を扱う。機構の体系的な比較は未評価。 |
| 5 | KA Core | OS の同期技法と原子操作 | 部分 | 16・178・567で鍵、セマフォ、原子的な検査・設定を扱う。OS の基本操作による実装は未評価。 |
| 6 | KA Core | コードから競合と解決策を分析 | 部分 | 固定模型の操作順序を比較。実コードの分析と記述は直接評価しない。 |
