# PDC-Coordination の対応状況

出典: [CS2023, Parallel and Distributed Computing, PDC-Coordination](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 222–223。原典を要約した作業用一覧。試作は共有更新の一例であり、この知識単位全体を扱わない。

| 2 | CS Core | バリア、キュー、再試行、通知などの制御 | 依頼90で二人が到着するまで集計を待つ固定例。一般のバリア、通知などは未対応 |
| 3 | CS Core | 原子性、ロックと排他、デッドロック回避、ロックの誤用や代替 | 試作：依頼15・16で更新喪失と単一の鍵、依頼30で２鍵の循環待ちと共通順序を操作。原子的操作の実装や一般の複数ロックは未対応 |
| 4 | KA Core | 進行特性、性能、所有権、ロックの変種、トランザクション、分散ロックなど | 依頼134で単一鍵の優先度継承の固定例。他は未対応 |

宝石の例は、各精霊の読み取りと書き込みがそれぞれ独立した順番で実行される簡略モデル。別の依頼では単一の鍵を使い、所有中は他方が待つ仕組みを試す。依頼30では２人と２鍵の固定モデルで循環待ちと共通順序を比較する。実際のメモリモデル、任意の複数ロックの正しさや性能は評価していない。

依頼502は２隊の固定された時系列で、成功またはゼロ除算を受けて中止する場合と続行する場合を比較する。中止は次の確認地点で受け取られ、後片付けを経て完了する模型。続行中の別隊が鍵を発見しても例外の記録は消えない。実際の並列性、例外の伝播や任意の取消し方式は評価しない。参考：[Python asyncio のタスクのキャンセル](https://docs.python.org/3/library/asyncio-task.html#task-cancellation)。

依頼503は基準時計と３刻遅れの時計を、往路・復路が２・２、１・３、３・１刻の３条件で比較する。基準側の応答は即時、時計の速さは同一と仮定する。往復時間はすべて４刻だが、往復均等の推定による調整は３、２、４刻となる。基準時計の精度、複数台の合意、実装や通信障害は扱わない。[RFC 5905](https://www.rfc-editor.org/rfc/rfc5905.html) と [RFC 8915](https://www.rfc-editor.org/rfc/rfc8915.html) を参照。

依頼503の追加比較では、塔の出発97・王城の返事101・塔への帰着101という同じ記録を固定する。行き１・２・３刻と帰り３・２・１刻の３つの内訳は、塔の遅れがそれぞれ３・２・１刻の場合にいずれも同じ記録を生む。往復記録だけで真の遅れを一意に決定できないことを示す模型であり、追加情報や複数測定を利用する実方式の精度を評価しない。
