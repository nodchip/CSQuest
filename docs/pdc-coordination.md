# PDC-Coordination の対応状況

出典: [CS2023, Parallel and Distributed Computing, PDC-Coordination](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 222–223。原典を要約した作業用一覧。試作は共有更新の一例であり、この知識単位全体を扱わない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | CS Core | 並行作業間の依存、競合の回避、進行保証 | 試作：２作業の実行順序、更新の喪失、単一の鍵による待機。依頼39で競合の順序と直列化を比較。一般の進行保証は未対応 |
| 2 | CS Core | バリア、キュー、再試行、通知などの制御 | 依頼90で二人が到着するまで集計を待つ固定例。一般のバリア、通知などは未対応 |
| 3 | CS Core | 原子性、ロックと排他、デッドロック回避、ロックの誤用や代替 | 試作：依頼15・16で更新喪失と単一の鍵、依頼30で２鍵の循環待ちと共通順序を操作。原子的操作の実装や一般の複数ロックは未対応 |
| 4 | KA Core | 進行特性、性能、所有権、ロックの変種、トランザクション、分散ロックなど | 未着手 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 与えられたプログラムの競合を回避・修復 | 簡略モデルの更新喪失と、鍵を使う別のモデルでの回避を操作。実際のプログラムの修復は未対応 |
| 2 | CS Core | 並行作業の完了後に正しく終了するようにする | 依頼90で２人の準備後に集計する固定例。実際のプログラムの終了制御は未対応 |
| 3 | KA Core | イベントを効率的に数える関数を書く | 未着手 |
| 4 | KA Core | 複数の形式で filter/map/reduce を書く | 未着手 |
| 5 | KA Core | 並列動作の完了後に次を実行するプログラムを書く | 未着手 |
| 6 | KA Core | 複数の探索を行い、解を得たら他を止めるプログラムを書く | 未着手 |
| 7 | KA Core | 一つの作業の数値例外で他を終了するプログラムを書く | 未着手 |
| 8 | KA Core | 複数主体で時刻を合意するプログラムと限界 | 未着手 |
| 9 | KA Core | リクエストごとにスレッド等を作って応答するサービスを書く | 未着手 |

宝石の例は、各精霊の読み取りと書き込みがそれぞれ独立した順番で実行される簡略モデル。別の依頼では単一の鍵を使い、所有中は他方が待つ仕組みを試す。依頼30では２人と２鍵の固定モデルで循環待ちと共通順序を比較する。実際のメモリモデル、任意の複数ロックの正しさや性能は評価していない。
