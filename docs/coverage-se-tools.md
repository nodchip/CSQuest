# SE-Tools：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.241–242。[既存調査](se-tools.md)と依頼・検査を照合。状態は[追跡方法](coverage-status.md)に従う。「未照合」は未実装の証拠ではなく、「部分」は項目全体の完成を意味しない。原典の細目を分けた場合、親と子は数値上で重複計上しない。実際の開発・協働・自由な説明やコード記述の能力は固定例だけでは直接評価しない。

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 代替と限界 |
|---|---|---|---|---|
| 1 | CS Core | 集中型と分散型の構成管理の違いを説明 | 部分 | 依頼655で切断中の編集・版の記録、共有先の先行変更と統合を比較。一般の実装や自由な説明は未対応 |
| 2 | CS Core | リリース管理への版管理の利用を説明 | 部分 | 依頼655で固定した目印と先端の版・試験結果を比較。実際のリリースや自由な説明は未対応 |
| 3 | CS Core | チームで構成項目を特定し版管理ツールを使う | 部分 | 固定された記録の統合のみ。実ツールとチーム作業は未対応 |
| 4 | KA Core | 静的・動的試験ツールの開発環境への統合 | 未照合 | 対応例を要照合。 |
| 5 | KA Core | 共有コードの状態を把握する CI | 部分 | 依頼656で検査結果と対象版を対応づける固定例。複数の実行や実ツールは未対応 |
| 6 | KA Core | プロジェクト向けのツール選択を検討 | 未照合 | 対応例を要照合。 |
| 7 | KA Core | 中規模製品の開発にツールを使う | 未照合 | 対応例を要照合。 |

依頼の前提・出典・検証と、一般化できない範囲は[既存調査](se-tools.md)を参照する。

依頼1014は版 A から本流 B と保守の修正 R を分岐し、２親の統合 M、v1.0 と v1.1 の目印、試験対象の R を追跡する。[Git の分岐と統合](https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging) と [タグ](https://git-scm.com/docs/git-tag) を参考とし、目印を動かさないのは模型の運用方針である。実際の Git では明示的にタグを変更できる。競合、リベース、実際の公開とチームでの運用は未評価。`tests/release-branches.test.js` で祖先関係、試験・目印、途中記録を検査する。

依頼1014の A・B・R・M の内容、M の２親、v1.0・v1.1 の参照先は、分離した一時 Git リポジトリでコミット・分岐・統合・タグを作り照合した。特定の４版に限り、一般の競合解決や配信は検証していない。
