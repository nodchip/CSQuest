# SE-Requirements の対応

原典: CS2023 p.242。依頼87は時刻表に関する４人の架空の発言を読む。機能、品質・制約、確認が必要な曖昧さや相反する希望を選び、別途、採用済みの閲覧要件から必要・禁止・未規定の振る舞いを分類する。個人予約の閲覧範囲は未解決として扱い、一方の関係者の希望を自動的な正解としない。

| 分類・番号 | 内容と状態 |
|---|---|
| KA Core 1 | 機能要件の記述方法と長短。依頼87で固定発言の機能分類と２つの利用者物語の下書きを行う。自由な文書作成や記述方法の比較は未対応 |
| KA Core 2 | 要件の整合性・妥当性・完全性・実現可能性。曖昧な速度と閲覧範囲の食い違いの固定例のみ |
| KA Core 3 | 関係者や調査方法による要件の収集。４人の架空発言を読む例のみ。依頼188で面接・現場観察・試用の目的と限界を比較。実際の聞き取りは未評価 |
| KA Core 4 | 非機能要件・品質特性。キーボード操作の固定例のみ |
| KA Core 5–6 | 倫理的なリスクの識別と管理、要件の伝達・形式化。未対応 |
| Non-core 7–9 | 要件確認の試作、変更影響、工数見積り。未対応 |

例示学習成果の KA Core 3・6 は、決められた１つの約束と固定例の分類に限る。依頼188で調査方法の固定比較、681で変更後の影響を扱うが、実際の収集・合意や一般の変更分析は未評価。ゲーム操作は実際の合意形成や自由な仕様書作成を評価しない。

依頼87では、練習用に与えた２つの事情から「立場・望み・理由」を選び、食い違う希望は未解決として扱う。理由は練習の仮定で実際の聞き取り結果ではない。実際の関係者との合意や自由な文書作成は評価しない。参考：[Agile Alliance の利用者物語](https://agilealliance.org/glossary/user-stories/)。
