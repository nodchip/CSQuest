# 塔の三通の窓：範囲と未完了

[CS2023 印字 199 ページ（PDF 199 ページ目）NC-Reliability](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の信頼性確保の入口。[RFC 3366](https://www.rfc-editor.org/rfc/rfc3366.html) はスライディングウィンドウを使う再送方式として Go-Back-N と Selective Repeat を挙げる。Go-Back-N の具体例は [Carnegie Mellon University の講義](https://www.cs.cmu.edu/~prs/15-441-F16/lectures/13-transport.pdf) と照合した。

既存の塔の依頼は配送・送信口・HTTP、天文台の依頼は返事消失と同じ番号での再送・重複排除を扱う。今回の固定模型は最大３通の未確認手紙、手紙２の消失、手紙３の順序外受信と破棄、１番までの累積確認、最も古い未確認の手紙からの時間切れ再送を扱う。送信の各操作はその手紙の受信側処理まで進め、生成済みの返事を後から選択して送信側に届ける。手紙２が消える場面で消失するのは手紙そのものであり、返事ではない。

順序外を保存しないのはこの固定模型の受信側規則であり、すべての窓方式や TCP を表すものではない。タイマーの実装、ACK 消失や破損、変化する窓・再順序付け、実ネットワーク、一般的なプロトコル設計と実装の能力は検証しない。関連項目は部分対応にとどまる。

`tower-window-clean` と `tower-window-gap` の２件を終えると `tower-window-retry` が開く。中継塔の依頼分類から選び、地図の全達成判定にも含まれる。

実装担当とは別の `review_candidate` が原典と上記資料、固定された送信・消失・順序外破棄・累積確認・再送の結果、説明、分類と保存をコード上で確認した。送信から受信処理までを一操作とするため、単一送信口の時刻や実ネットワークを検証したものではない。レビュー担当自身はブラウザを操作していない。

`tests/endgame-window.test.js` は３通送信時の未確認、順序外の破棄と返事１、時間切れ前の再送拒否、２・３の再送と返事３、途中履歴の再開を検証する。`tests/tower-gate-quest-groups.test.js` は分類と開放を確認する。`scripts/endgame-window.playwright.js` は集いと４地域などの達成を用意した検証用記録から、213・390・1200 px 幅で分類からの到達、キーボードによる依頼と回答、誤答の案内、途中復元、段階開放、３依頼の達成と達成後の再開を確認した。新規開始からこの依頼群までの通し操作、実際のスクリーンリーダー音声、利用者による面白さの評価は未確認。
