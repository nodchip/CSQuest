関連する `tests/behavioral-bags.test.js`、`tests/type-checking.test.js`、`tests/generic-pouch.test.js`、`tests/record-compatibility.test.js`、`tests/overload-dispatch.test.js`、`tests/type-unification.test.js`、`tests/type-application.test.js`、`tests/type-safety.test.js`、`tests/type-safety-proof.test.js`、`tests/curry-howard.test.js`、`tests/dependent-vectors.test.js`、`tests/type-rescue.test.js` は各模型を検査するもので、原典の範囲全体や学習効果の検証を意味しない。

依頼945は [Cornell の多相性の講義](https://www.cs.cornell.edu/courses/cs4110/2021fa/lectures/lecture24.pdf)を参考に、型変数による共通手順、宣言型による固定の多重定義、動物のサブタイプと実行時の手順を比較する模型。実言語の候補解決・変換・例外や自由な説明は未評価。

依頼946は [Oracle の型消去](https://docs.oracle.com/javase/tutorial/java/generics/erasure.html)と [Rust の単相化](https://doc.rust-lang.org/book/ch10-01-syntax.html)を参考に、同じ型検査の後に共有処理か型ごとの処理を概念的に用意する模型。実コンパイラーの最適化、ABI、コードサイズ、実測性能や言語全般は評価しない。

依頼1041は [Rust の型](https://doc.rust-lang.org/book/ch03-02-data-types.html)と [Python の TypeError](https://docs.python.org/3/library/exceptions.html#TypeError)を参考に、数字と文字列の加算を到達する場合・しない場合で比較する。`scripts/check_type_language_examples.py` で rustc 1.99.1 は両方をコンパイル時 E0277 とし、Python 3.13.15 は分岐を通る場合のみ TypeError、通らない場合は done を表示することを確認した。画面はこの結果の再現で実コンパイラーを起動しない。`tests/language-type-check.test.js` は４条件・選択肢・保存を検査する。実言語の全規則、外部静的解析、独自のコード作成や自由な説明は評価しない。

依頼1105は CS2023 が定義を示さない prescriptive / descriptive の解釈の一例として、[Pfenning の論理プログラミングにおける型の見方](https://www.cs.cmu.edu/~fp/papers/iclp90.pdf) と [多相型の二つの役割](https://scholar.lib.vt.edu/ejournals/JFLP/jflp-mirror/articles/2001/S01-01/JFLP-A01-01.pdf) を参考にする。３種類すべてをそのまま返す架空の操作に対して、許可する型を数・言葉に限定した門と、元の振る舞いを変えずに３型を調べる門を比較する。有限の観察は一般のプログラムの型や健全な近似の証明ではなく、型が規範と記述の役割を併せ持つ場合もある。`tests/polymorphism-views.test.js` は６条件・達成・復元を検査する。

依頼510では [Python の未実装を示す例外](https://docs.python.org/3/library/exceptions.html#NotImplementedError)を参考に、型検査に加えて未完成の札を開始前に拒否する架空の門と、呼び出したときに止まる門を比較する。`tests/unfinished-check.test.js` は８条件と旧記録の復元を検査する。未完成の検出はこの門の追加規則であり、静的型検査一般が未完成を必ず拒否するという意味ではない。

依頼510では [Python の型注釈](https://docs.python.org/3/library/typing.html)を参考に、数だけの袋を実行前に検査する方法、異種の品も入れる方法、追加時に確認する方法を比較する。`tests/collection-flex.test.js` は３方法・２品・２操作と旧記録の復元を検査する。静的型と実行時検査は併用でき、異種データを表す型もあり、この模型から実言語全体の安全性や開発効率は評価しない。

依頼595は [Cornell の組の型と取り出し](https://www.cs.cornell.edu/courses/cs4120/2022sp/notes/subtyping/)を参考に、４種類の品と３操作で型を予想し、積の構成・左右の取り出しの３規則を選ぶ。`tests/product-rules.test.js` は12条件と規則の選択32通り、旧記録の復元を検査する。自由記述・一般の言語やサブタイプは評価しない。

依頼767では [Cornell の型付き算術式](https://www.cs.cornell.edu/courses/cs4160/2020sp/sf/plf/terse/Types.html)を参考に、数・灯り・１を足す・分岐の規則を選び、６つの固定式に部分式から適用する。`tests/compositional-types.test.js` は規則の16通り、入れ子と不一致、旧記録の復元、および各規則の組合せと例について部分式からの導出を検査する。選択肢から規則を選ぶ代替体験であり、自由な定義や規則自体の安全性の証明は評価しない。
