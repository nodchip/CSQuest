# OS-Faults：障害耐性

出典: [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.214–215。データベースの固定した復旧模型は、実際の OS の障害耐性やデータ保全を保証しない。

| トピック | 区分 | 内容と現状 |
|---|---|---|
| 1–2 | KA Core | 信頼性・可用性と、ソフトウェア・ハードウェアによる障害耐性。依頼108で稼働時間、181で障害後に写しから戻す固定例、229で３装置のパリティ復元。一般的な OS や RAID 実装は未対応 |
| 3–5 | Non-core | 空間・時間の冗長性、障害耐性の実現、誤りの検出・訂正。依頼105〜107で通知や符号の固定例。一般の OS とメモリの仕組みは未対応 |
| 6–7 | Non-core | ファイルシステムの整合性検査・復旧、ジャーナルとログ構造。736で管理情報の確定記録と再適用、737・738で有効記録の移動と復旧点を操作。一般の整合性検査や実ファイルシステムの復旧は未評価 |
| 8–9 | Non-core | DB・安全重視システムでの利用、OS の検出・復旧・再起動機構。136で単一送金の復旧、752で装置の期限切れ後の状態確認と再試行を比較。OS のサービス再起動と実運用は未評価 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1–4 | KA Core | OS による信頼性・可用性、障害耐性の手法、障害後の継続、性能・柔軟性の兼ね合い。136・736・752で送金・ファイル・装置の固定復旧例。性能・柔軟性の評価、OS の一般的な仕組みと自由な説明は未評価 |
| 5 | Non-core | OS の障害耐性の課題と機構を詳細に説明。未対応 |

依頼136は変更前後の記録と確定印が安全に保存されると仮定し、未確定の部分反映を元に戻し、確定済みの未反映・部分反映を変更後の値へ直す。単一の送金で完全な書き込みを仮定し、実 DBMS の実装やファイルシステムの復旧を扱わない。[先行ログの説明](https://www.postgresql.org/docs/15/wal-intro.html)

依頼181は更新前・更新後・破損後の写しと復元時点の違いを操作する固定模型。写しが独立して残り、内容を識別できると仮定する。実際のバックアップ運用や復元の成功を保証するものではない。

原典の各トピック・成果と後続のファイル・装置復旧の記録は [項目別台帳](coverage-os-faults.md) を参照。
