# OS-Protection の対応状況

出典: [CS2023, Operating Systems, OS-Protection](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 209。原典の要約と作業中の対応であり、固定模型の達成は単位全体の習得を意味しない。

## トピック

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | OS のセキュリティ機構の概要 | 依頼54で保護された装置、180で媒体・起動・受付の固定模型。OS の機構全体は未対応 |
| 2 | CS Core | 攻撃と敵対的な振る舞い、スケジューリングなど | 依頼177で継続到着による飢餓、180で３経路の固定模型。実際の攻撃やスケジューリングへの妨害は未対応 |
| 3 | CS Core | 実際の OS の主な脆弱性の検討 | 未着手 |
| 4 | CS Core | バックアップなどの軽減策 | 依頼181で更新前後の写しから消失・破損後の台帳を復元する固定模型。実際の媒体やバックアップ手順は未対応 |
| 5 | KA Core | ポリシーと機構の分離 | 未着手 |
| 6 | KA Core | 保護リングなどのセキュリティ手法と装置 | 依頼54で利用者モードとカーネルモードの固定模型。実アーキテクチャの保護リングや履歴は未対応 |
| 7 | KA Core | 保護、アクセス制御と認証 | 依頼11で認証結果と役割別の権限、180で対象ごとの権限確認の固定模型。実際の認証や OS のアクセス制御は未対応 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | OS に保護とセキュリティ機構が必要な理由を理解する | 依頼54・180で保護された装置と３経路の固定模型。実 OS の全体的な脅威は未対応 |
| 2 | CS Core | OS の脆弱性を使う攻撃経路を列挙し説明する | 依頼180で媒体、起動部品、受付の３例。実 OS の脆弱性や自由記述による説明は未対応 |
| 3 | CS Core | OS の資源へのアクセスを制御する機構を理解する | 依頼11・54・180で権限と保護の固定例。実 OS の機構は未対応 |
| 4 | KA Core | OS の保護・セキュリティに影響する機能と限界を要約する | 依頼180で対策ごとの前提と限界を提示。体系的な要約や自由記述は未対応 |

依頼180は鍵を持たない媒体の持出し、信頼できる検証器による起動部品の署名検証、ログイン済み利用者の権限のない受付要求について、各対策が働くと仮定する模型。鍵の漏洩、検証器や実装の脆弱性、暗号化による改変検知は扱わない。
