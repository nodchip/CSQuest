# OS-Protection の対応状況

出典: [CS2023, Operating Systems, OS-Protection](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 209。原典の要約と作業中の対応であり、固定模型の達成は単位全体の習得を意味しない。

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | OS に保護とセキュリティ機構が必要な理由を理解する | 依頼54・180で保護された装置と３経路の固定模型。実 OS の全体的な脅威は未対応 |
| 2 | CS Core | OS の脆弱性を使う攻撃経路を列挙し説明する | 依頼180で媒体、起動部品、受付、依頼491で Dirty COW の概要と競合の架空模型。他の実 OS の脆弱性や自由記述による説明は未対応 |
| 3 | CS Core | OS の資源へのアクセスを制御する機構を理解する | 依頼11・54・180で権限と保護の固定例。実 OS の機構は未対応 |
| 4 | KA Core | OS の保護・セキュリティに影響する機能と限界を要約する | 依頼180で対策ごとの前提と限界を提示。体系的な要約や自由記述は未対応 |

依頼180は鍵を持たない媒体の持出し、信頼できる検証器による起動部品の署名検証、ログイン済み利用者の権限のない受付要求について、各対策が働くと仮定する模型。鍵の漏洩、検証器や実装の脆弱性、暗号化による改変検知は扱わない。

依頼490は２人・２対象・読取りのみのアクセスを対象とし、普段と緊急時の２方針を対象側の名簿と持ち主側の通行証でそれぞれ設定する。２方針について全16設定の４要求の判定を検証した。名簿の本人確認、通行証の偽造防止と提示、譲渡されないことを仮定し、実際の認証・譲渡・失効、複数の権限や OS 実装は扱わない。[OSTEP のアクセス制御](https://pages.cs.wisc.edu/~remzi/OSTEP/security-access.pdf)を参照。

依頼491は Dirty COW（CVE-2016-5195）の概要と提供元の修正を紹介する。操作部分は、写しの確認後に参照先が原本へ変化し、古い結果を信じる係が原本に書く架空の模型。比較する係は再確認と書込みを一続きで行い、変更を検出したら停止する。変更なしと変更ありの両順序、２方式、保存履歴を検証した。実際の Linux の処理・競合手順や修正を再現するものではなく、一般の競合対策の正しさは保証しない。[Red Hat の解説](https://access.redhat.com/security/vulnerabilities/DirtyCow)・[NVD](https://nvd.nist.gov/vuln/detail/CVE-2016-5195)を参照。
