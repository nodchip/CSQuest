# HCI-Accessibility：文字と背景のコントラスト

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.177–178、HCI-Accessibility 2a（アクセシビリティ標準）の固定例。旧 `src/image-contrast.js` は画像の階調の伸張で、文字の WCAG コントラスト判定ではない。現行 `endgame-accessibility.js` はキーボード・フォーカス・操作名の例であり、文字のコントラストは扱わない。

[W3C の WCAG 2.2 1.4.3 解説](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) を参照。非装飾の文字と白背景の固定例で、sRGB を線形化して相対輝度から比を計算。通常の12 pt文字は4.5:1以上、大きな18 pt文字は3:1以上として、丸めない値で判定する。`#777777` は約4.478089、`#767676` は約4.542225、`#aaaaaa` は約2.323123。色見本は補助であり、色・数値・結果を文字でも提示する。

基準には非活性 UI、純粋な装飾、ロゴなどの例外があり、実サイト・画像上の文字・不透明度・フォントや環境の違い、他の成功基準や実際の利用者の読みやすさは未評価。比だけで WCAG 適合やアクセシビリティ全体を保証しない。自由な評価・一般の設計や実際のユーザー調査も未評価。

実装担当とは別の `review_candidate` が原典・W3C WCAG 2.2、sRGB 変換・比・丸め前判定、各画面の前提、誤答・履歴、分類と開放、旧記録の既定値を確認した。例外と一条件だけでは WCAG 全体を判定できない説明を画面に明記するよう指摘し、修正後に再確認した。関連７テストも成功した。全体適合や実利用者を評価したものではなく、レビュー担当自身はブラウザを操作していない。

`scripts/endgame-text-contrast.playwright.js` は集いと４地域の達成状態を用意した検証用記録から、213・390・1200 px 幅で分類経由の到達、キーボード操作、誤答案内、途中保存・再開、段階開放と達成後の再開を確認した。新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者による面白さの評価は未確認。
