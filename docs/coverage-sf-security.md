# SF-Security：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.297。[追跡方法](coverage-status.md)に従い「部分」は記した限定例、「未照合」は対応や十分性が未確認であることを表す。いずれも項目の完成を意味しない。親と子の重複は集計時に検討する。原典はこの単位に Non-core を列挙していない。

## トピック

| 番号 | 区分 | 要約 | 状態 | 体験と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | システムの安全上の問題と例 | 部分 | 依頼180は媒体・起動・受付への３経路、492は送信元と回数制限の固定例。ウイルス・盗聴などを含む全般的な分類は未評価。 |
| 2 | CS Core | 安全上の問題への対策 | 部分 | 暗号と防御構成の固定例は子項目に記載。対策全般と運用は未評価。 |
| 2a | CS Core | 暗号による対策 | 部分 | 依頼180の媒体保護、58の XOR と鍵再利用、128の署名の模型。正しい鍵管理や実用的な暗号方式の実装は評価しない。 |
| 2b | CS Core | セキュリティアーキテクチャ | 部分 | 依頼180で３経路と対応する保護を比較。対策の正しい動作は仮定し、実システムの設計や安全性は評価しない。 |
| 3 | KA Core | 代表的な対策システム | 部分 | 侵入検知・通信制御・特徴照合の固定例は子項目に記載。対策システム全般と運用は未評価。 |
| 3a | KA Core | 侵入検知とファイアウォール | 部分 | 依頼279で応答の履歴を用いる通信制御、280でしきい値と誤判定を比較。実際の設定や運用は未評価。 |
| 3b | KA Core | ウイルス対策システム | 部分 | 依頼280で特徴表の照合・更新と隔離、見逃し・誤警報を固定例で比較。実際の製品、検体分析、隔離からの復旧や運用全般は未評価。 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 体験と残る範囲 |
|---|---|---|---|---|
| 1 | CS Core | 一般的な安全上の問題と例を説明 | 部分 | 依頼180・492で架空の経路や負荷を試す。実例の広い調査や自由な説明は評価しない。 |
| 2 | CS Core | 対策を説明 | 部分 | 依頼180で保護の選択と３経路の成否を比較。一般的な対策の説明や実運用を評価しない。 |
| 3 | KA Core | 代表的な対策システムを説明 | 部分 | 依頼279・280は通信制御、侵入検知と特徴照合・隔離の模型。各システムの一般的な説明や実際の運用は未評価。 |

対応する実装は `src/layered-protection.js`、`src/firewall-state.js`、`src/intrusion-threshold.js`・`src/signature-lab.js`、関連検証は各同名の `tests/*.test.js` を参照。依頼280の特徴照合は月・星の一致を仮定し、表更新で新しい毒札を検出するが無害な月の札も隔離する。実際の特徴抽出、振る舞い検知や製品の検出率は扱わない。[CISA のマルウェア検出・更新・隔離の説明](https://www.cisa.gov/sites/default/files/2023-01/Procurement_Language_Rev4_100809_S508C.pdf)を参照。DoS の模型は [SEC-Foundations](sec-foundations.md) を参照。自由記述、実際の設定・攻撃・防御能力はこれらの操作から直接評価しない。
