# GIT-Rendering の対応状況

出典: [CS2023 GIT-Rendering](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 157–158。原典を要約した作業用一覧。すべて KA Core。小さな図形操作の達成はグラフィックスのプログラムを作る能力全体を示さない。

## トピック

| 番号 | 要約 | 状況 |
|---:|---|---|
| 1 | 物体表現、アフィン・座標変換、シーングラフ | 依頼26：２次元三角形の固定された平行移動・90度回転と操作順。その他の表現とシーングラフは未対応 |
| 2 | カメラ、投影モデル、射影幾何 | 依頼64で奥行きの異なる点の平行・透視投影と投影面の距離を比較。一般のカメラモデルは未対応 |
| 3 | 放射測定と光のモデル、レンダリング方程式 | 依頼186で法線と光の向きの内積による拡散光、依頼507で点光源と不透明な壁による直接光の遮蔽の模型。放射測定やレンダリング方程式は未対応 |
| 4 | ラスタ化、描画 API、遮蔽、テクスチャ、レイトレーシング、標本化 | 依頼83で２値三角形の中心標本と４標本による平均、依頼506で２物体の深度比較と描画順の固定例。実 API、テクスチャやレイトレーシングは未対応 |

依頼26は、固定された２次元三角形の頂点に、右へ１の平行移動と原点周りの反時計回り90度回転を順に適用する。目標２例を比較し、変換順序で結果が変わることを扱う。任意の変換、行列の記述、３次元、投影、描画 API は評価しない。

依頼64では横位置８、奥行き４・８の２点を、平行投影および投影面までの距離１・２の透視投影で比べる。透視の横位置は距離×横位置÷奥行きで計算し、相似な三角形の関係をテストで検証。上から見た図は確認後に実際の投影線を表示する。高さ、クリッピング、任意のカメラや描画プログラムは未対応。

依頼506は不透明な宝石（深度２）と壁（深度５）を、２行３列の画素に重ねる。深度なしでは後に描いたものが中央を上書きし、深度ありでは各画素に記録した深度より小さい値のみを採用する。４通りの結果を検証。透過、同深度、投影、実際の描画 API や数値精度は扱わない。[MDN の深度比較](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/depthFunc)を参照。

依頼506の追加操作は、６つの画素それぞれについて、あらかじめ与えた物体との交差候補から最も深度が小さいものを選ぶ。深度比較による描画結果と全６画素が一致することを検証。これは視線の可視性のみで、レイと幾何の交差計算、影・反射・透明物体や実際のレンダリング性能は扱わない。[Cornell のレイトレーシング講義](https://www.cs.cornell.edu/courses/cs465/2003fa/lectures/notes-09raytracing.pdf)を参照。

依頼507は平面の x=0 の点光源と x=4 の３点、x=2 の５位置に置ける不透明な縦の壁を使う。光源と石の高さは 0・2・4 のいずれかで、壁の列を通る高さは両者の中間。３光源・３石・全32壁配置について直線の交差を検証した。点光源の直接光のみを扱い、透明、反射、明るさ、実際の画像生成や一般の幾何は未対応。[CMU の影のレイ](https://15462.courses.cs.cmu.edu/fall2016/article/15)を参照。
