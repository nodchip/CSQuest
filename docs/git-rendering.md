# GIT-Rendering の対応状況

出典: [CS2023 GIT-Rendering](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 157–158。原典を要約した作業用一覧。すべて KA Core。小さな図形操作の達成はグラフィックスのプログラムを作る能力全体を示さない。

## トピック

| 番号 | 要約 | 状況 |
|---:|---|---|
| 1 | 物体表現、アフィン・座標変換、シーングラフ | 依頼26で２次元三角形の変換順、637で台座・腕・旗・灯りの親子変換を操作。一般の表現とシーングラフは未対応 |
| 2 | カメラ、投影モデル、射影幾何 | 依頼64で奥行きの異なる点の平行・透視投影と投影面の距離を比較。一般のカメラモデルは未対応 |
| 3 | 放射測定と光のモデル、レンダリング方程式 | 依頼186で法線と光の向きの内積による拡散光、依頼507で点光源と不透明な壁による直接光の遮蔽の模型。放射測定やレンダリング方程式は未対応 |
| 4 | ラスタ化、描画 API、遮蔽、テクスチャ、レイトレーシング、標本化 | 依頼83で２値三角形の中心標本と４標本による平均、依頼506で２物体の深度比較と描画順の固定例。依頼638で４値のテクスチャの最近傍・線形標本化を比較。実 API や一般のレイトレーシングは未対応 |

依頼720は４つの長方形を２つの境界箱に分け、３本の水平な視線と箱・旗の交差を調べる。高さ２の視線は手前の箱に当たるが、箱内のどちらの旗にも当たらない。高さ3.5では奥の箱を飛ばし、手前の旗２枚だけを詳しく調べる。境界に触れる場合も交差として扱い、選択した複数高さで箱によって実際の交差が見逃されないことを検査。２次元の固定階層で、任意の向きや３次元の BVH 構築・実性能は扱わない。参考：[Physically Based Rendering: Bounding Volume Hierarchies](https://www.pbr-book.org/4ed/Primitives_and_Intersection_Acceleration/Bounding_Volume_Hierarchies)。

## 例示学習成果

| 番号 | 要約 | 状況と限界 |
|---:|---|---|
| 1 | 光の輸送の問題を説明・図示 | 依頼507で点光源から石への直接光の遮蔽を操作。反射や一般の光輸送は未対応 |
| 2 | 基本的な描画パイプラインを説明 | 依頼639で物体・カメラ変換、投影と切取り、画素候補、色、深度比較を順に操作。１方向・２旗・３画素の模型で、実 API や一般のパイプラインは未対応 |
| 3 | 前方・後方レンダリングを比較 | 依頼506で物体ごとの画素更新と、画素ごとの視線による最近接候補の固定比較。交差計算や一般の手法の比較は未対応 |
| 4 | ２次元図形を表示するプログラムを作成 | 未着手。依頼26はゲーム内の図形操作であり、記述能力は評価しない |
| 5 | ３次元モデルを表示するプログラムを作成 | 未着手 |
| 6 | 相似三角形から透視投影を計算 | 依頼64で高さ０の固定点２個を選択式で投影。一般の３次元点と自由な計算は未対応 |
| 7 | アフィン変換で２・３次元の点を計算 | 依頼26で２次元、640で３次元の固定回転・移動を操作。一般の計算と任意角度は未対応 |
| 8 | ２次元変換を３次元へ拡張する変更を示す | 依頼640で２次元の90°回転を z 軸回転へ拡張し、x・y 軸回転と移動を操作。同次座標の次元を説明。任意角度や一般の行列の構築は未対応 |
| 9 | テクスチャ、標本化、アンチエイリアスを定義・説明 | 依頼83で画素の中心と４標本の結果を比較。依頼638でテクスチャの位置と最近傍・線形標本化を比較。一般的なアンチエイリアスや多様なテクスチャは未対応 |
| 10 | 可視性に関するレイトレーシングとラスタ化を比較 | 依頼506で６画素のあらかじめ与えた交差候補から最近接を選び、深度比較の結果と照合。依頼641で２線分の投影と実際の視線交差を比較。一般の３次元幾何や性能比較は未対応 |
| 11 | ２次元図形の変換・クリッピングを行うプログラムを作成 | 未着手。依頼26は操作の一例のみ |
| 12 | 描画 API・頂点バッファ・シェーダーでリアルタイム描画を実装 | 未着手 |
| 13 | 描画手法を比較 | 依頼641で物体からの投影・深度比較と、画素からの視線交差を同じ４標本で比較。一般の描画方式や性能は未対応 |
| 14 | カメラとモデルの変換を比較 | 依頼636で２物体とカメラの横方向の平行移動を比較。回転、透視や一般の変換は未対応 |

依頼26は、固定された２次元三角形の頂点に、右へ１の平行移動と原点周りの反時計回り90度回転を順に適用する。目標２例を比較し、変換順序で結果が変わることを扱う。任意の変換、行列の記述、３次元、投影、描画 API は評価しない。

依頼64では横位置８、奥行き４・８の２点を、平行投影および投影面までの距離１・２の透視投影で比べる。透視の横位置は距離×横位置÷奥行きで計算し、相似な三角形の関係をテストで検証。上から見た図は確認後に実際の投影線を表示する。高さ、クリッピング、任意のカメラや描画プログラムは未対応。

依頼506は不透明な宝石（深度２）と壁（深度５）を、２行３列の画素に重ねる。深度なしでは後に描いたものが中央を上書きし、深度ありでは各画素に記録した深度より小さい値のみを採用する。４通りの結果を検証。透過、同深度、投影、実際の描画 API や数値精度は扱わない。[MDN の深度比較](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/depthFunc)を参照。

依頼506の追加操作は、６つの画素それぞれについて、あらかじめ与えた物体との交差候補から最も深度が小さいものを選ぶ。深度比較による描画結果と全６画素が一致することを検証。これは視線の可視性のみで、レイと幾何の交差計算、影・反射・透明物体や実際のレンダリング性能は扱わない。[Cornell のレイトレーシング講義](https://www.cs.cornell.edu/courses/cs465/2003fa/lectures/notes-09raytracing.pdf)を参照。

依頼507は平面の x=0 の点光源と x=4 の３点、x=2 の５位置に置ける不透明な縦の壁を使う。光源と石の高さは 0・2・4 のいずれかで、壁の列を通る高さは両者の中間。３光源・３石・全32壁配置について直線の交差を検証した。点光源の直接光のみを扱い、透明、反射、明るさ、実際の画像生成や一般の幾何は未対応。[CMU の影のレイ](https://15462.courses.cs.cmu.edu/fall2016/article/15)を参照。

依頼636は宝石・塔・カメラの初期横位置を４・７・０とし、各移動量 −２・０・２ を操作する。見える横位置は世界の位置からカメラ位置を引く。宝石だけ左へ２では２・７、両物体を左へ２とカメラだけ右へ２ではどちらも２・５となるが、世界座標は異なる。全27配置を検査。横方向の平行移動のみの模型で回転・透視・画面端の切取りや描画 API は扱わない。[MDN: Model View Projection](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_model_view_projection)。

依頼637は台座 (２,２)、台座の子である腕 (１または２,０)・旗 (０,１)、腕の子である灯り (０,１) を用いる。台座の０°・90°回転と右への移動０・２、腕の位置１・２を組み合わせ、世界での位置を比較する。初期配置で台座 (２,２)・腕 (３,２)・旗 (２,３)・灯り (３,３)、台座を90°回すとそれぞれ (２,２)・(２,３)・(１,２)・(１,３)。全８設定の性質を検査。平面の固定階層で３次元・拡大縮小・実 API は未対応。[Three.js: Matrix Transformations](https://threejs.org/manual/pages/matrix-transformations.html)。

依頼638は２×２のテクセルの明るさ０・80・160・240を使用し、それぞれの中心の範囲で最近傍と線形の標本を比較する。同距離の最近傍は模型の規則として左・上を選ぶ。３×３点の両手法を検証し、中央はそれぞれ０・120。５×５点の結果も可視化する。実 GPU の同距離の挙動や丸め、範囲外、ミップマップ、色空間変換、実際の API 実装は評価しない。[MDN: WebGL texture parameters](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/texParameter)。

依頼639では深度２の朱の旗と深度４の青の旗を描画順に通す。カメラからの横位置を奥行きで割り、画面範囲内の３画素の中心から候補を作る。旗を左に１、カメラを右に１動かすと、深度比較なしでは左から青・青・空、ありでは朱・青・空となる。全12設定を投影の逆算で照合し、５段階の選択と途中再開を検査。横方向と固定深度のみで、同次座標でのクリッピング、三角形、透過、実 API や自由なプログラム作成は扱わない。深度テストを色の後に示すのはこの模型の順序であり、実装では早期深度テストもありうる。[MDN: WebGL model view projection](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_model_view_projection)。

依頼640は右手系で点 A=(１,０,０) と B=(０,１,１) に x・y・z 軸の正回転90°と x 方向への移動１を操作する。平面の回転を z 軸回転へ広げ、他の軸と操作順序を比較する。長さ４以下の全341操作列を独立した４×４同次行列計算と照合。２点と固定角度による模型で、任意角度、拡大縮小、３次元モデル、行列やプログラムの記述能力は評価しない。[MDN: Matrix math for the web](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Matrix_math_for_the_web)。

依頼871は固定立方体の24頂点・36索引を WebGL バッファに送り、頂点・フラグメントシェーダーと `drawElements` で実際に描画する。一面と立方体、０・45度の回転、深度判定の有無を操作し、描画順序による上書きを比較する。WebGL 非対応時は成功を記録しない。ブラウザーで画素を読み取り、回転と深度の有無で画像が変わることを確認した。固定例であり自由なモデルやコード作成、透過、照明、一般の行列、実性能は評価しない。[MDN: Creating 3D objects using WebGL](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Creating_3D_objects_using_WebGL)。

依頼641はカメラと２本の線分を上から見た断面で、奥行き２・４の旗と４つの窓標本を使う。物体側から端点を投影して深度を比較する処理と、各視線の各奥行きでの横位置を計算して線分と交差判定する処理を、旗・カメラ各２配置で照合する。実際の交差候補を用いるが、１方向の線分・不透明・固定標本の模型であり、三角形、反射、影、透過や実行性能は扱わない。[Cornell: Ray tracing](https://www.cs.cornell.edu/courses/cs465/2003fa/lectures/notes-09raytracing.pdf)。
