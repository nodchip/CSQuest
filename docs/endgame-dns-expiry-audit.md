# NC-Applications：住所の控えと期限

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.199、NC-Applications 1 の名前と住所。旧依頼421 `src/dns-resolution.js` の期限２・４の固定例を現行の塔で再利用し、独立した教材範囲として重複計上しない。現行の名前帳は控えの使用と期限切れ後の更新を扱うが、住所の更新後にも有効な控えが残る例は扱っていない。

各問い合わせは独立し、時刻０に旧住所をキャッシュ済み、時刻１に権威側が新住所へ更新、更新通知なしと仮定。期限２では時刻１は旧、時刻３は新。期限４では時刻１・３は旧、期限ちょうどの時刻４は権威側を再確認して新。実際の DNS は複数段のキャッシュ、負の応答、運用上の設定や通信失敗などを含み、具体的な伝播時刻や更新速度をこの模型から保証しない。[RFC 1034](https://www.rfc-editor.org/rfc/rfc1034) は名前解決と有効期間を説明する。

固定の２住所・２期限・少数の独立した問い合わせであり、実際の DNS 通信、一般的な設定・障害処理・自由な説明やプログラムの作成を評価しない。NC-Applications 全体の完成を示さない。

実装担当とは別の `review_candidate` が原典・RFC 1034/2181、固定例の期限と権威側更新、各画面の前提、誤答・履歴、分類と開放、旧記録の既定値を確認した。TTL は最大保持期間で必ず保持される保証ではなく、この挙動は固定模型の前提である。関連９テストも成功した。実通信を検証したものではなく、レビュー担当自身はブラウザを操作していない。

`scripts/endgame-dns-expiry.playwright.js` は集いと４地域の達成状態を用意した検証用記録から、213・390・1200 px 幅で分類経由の到達、キーボード操作、誤答案内、途中保存・再開、段階開放と達成後の再開を確認した。新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者による面白さの評価は未確認。
