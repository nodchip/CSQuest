# SEP-Privacy の対応状況

出典: [CS2023 SEP-Privacy](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 278–279。原典を要約した作業用一覧。依頼27の判定は架空の手順に基づく教材であり、実際の法令適合や情報の匿名性を保証しない。

## トピック

| 番号 | 分類 | 要約 | 状況 |
|---:|---|---|---|
| 1 | CS Core | 取引データベース、監視、クラウド、AI 等における広範な収集のプライバシーへの影響 | 依頼27：架空の受取台帳の収集・共有範囲を検討。大規模監視等は未対応 |
| 2 | CS Core | 匿名性、仮名性、身元 | 依頼27：番号による記録の結び付きと再識別の可能性に触れる。概念の体系的比較は未対応 |
| 3 | CS Core | 暗号化や差分プライバシー等の技術的保護 | 未着手 |
| 4 | CS Core | 市民的自由、プライバシー権、文化差 | 未着手 |
| 5 | KA Core | プライバシーの哲学的・法的概念 | 未着手 |
| 6 | KA Core | 地域におけるプライバシー保護の法的基盤 | 未着手 |
| 7 | KA Core | 実務分野のプライバシー法制 | 未着手 |
| 8 | KA Core | 人を対象とする研究の基本と法を超える原則 | 未着手 |
| 9 | KA Core | 表現の自由とその制限 | 未着手 |
| 10 | KA Core | 利用者生成コンテンツ、モデレーション、責任 | 未着手 |

## 例示学習成果

| 番号 | 分類 | 要約 | 状況と限界 |
|---:|---|---|---|
| 1 | CS Core | 取引・蓄積データのプライバシー上の脅威への対策を評価 | 依頼27：架空の台帳で収集項目と閲覧範囲を選択。現実の脅威分析や包括的評価は未対応 |
| 2 | CS Core | 広範な監視システムにおけるデータ収集の役割を説明 | 未着手 |
| 3 | CS Core | 匿名性と仮名性の概念・目的を区別 | 依頼27：番号でも記録を結び付けられる可能性に触れる。概念の比較と自由な説明は未対応 |
| 4 | CS Core | 差分プライバシーやエンドツーエンド暗号化等の影響を説明 | 未着手 |
| 5 | CS Core | プライバシーや市民的自由に関する文化差を特定 | 未着手 |
| 6 | KA Core | 個人のプライバシーの法的保護の哲学的基礎を議論 | 未着手 |
| 7 | KA Core | 法令や法を超える原則の意図・価値・実装を批評 | 未着手 |
| 8 | KA Core | 適切な表現の自由を可能にする戦略を特定 | 未着手 |

依頼27の前提では、受取番号と薬草の種類で薬師が包みを作り、受付は番号と受取時間で照合して封をした包みを渡す。本人の名前や住所を使わず、掲示板にも個別注文を公開しない。受取番号は他の情報と結び付けられ得るため、匿名化を保証するものではない。他の手順、アクセス管理の実装、保存期間、本人の意思、法律や文化の違いは評価していない。
