# OS-SEP: OS と社会・倫理

出典：[CS2023 印字 p.215](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。すべて KA Core。架空の移行模型は、実際の機器の互換性、セキュリティ、設定を保証しない。

| トピック | 対応と不足 |
|---|---|
| 1 OS におけるオープンソース：カーネルの脆弱性、ゲスト・ホスト OS、収益化 | 依頼846で公開された修正の確認と架空のホスト・ゲストへの個別適用、857で無償更新・有償支援の固定例。実カーネルの修正や実契約は未評価 |
| 2 OS のサポート終了時の課題 | 依頼361で修正提供の終了、道具の互換性、控えと復元、移行の固定例。実際の支援期限、移行手順や費用は未対応 |
| 例示：独自仕様の OS・環境の利用とプライバシー、利用状況収集、個人データの自動走査、広告、クラウド連携 | 依頼361で架空の任意の利用状況送信の設定を比較。実 OS の送信内容、自動走査、広告やクラウド連携は未対応 |

| 例示学習成果 | 対応と不足 |
|---|---|
| 1 オープンソースカーネルのバグ発見・対処の長短 | 依頼846で調査の機会と、修正・適用が自動ではない点を比較。一般の比較や自由な説明は未評価 |
| 2 Linux の歴史とオープンソースとしての正負の影響 | 依頼857で GNU 計画、Linux 0.01 と GNU 条件への移行、および調査機会・対応の限界を扱う。歴史全体や一般的な影響分析は未評価 |
| 3 サポート終了後も OS に依存する際の問題を列挙 | 依頼361で修正提供の終了と道具の互換性の固定例。一般の課題の列挙は未評価 |
| 4 OS の課金モデルとバグ発見・対処の違い | 依頼846・857で公開された調査機会、無償更新と有償の問い合わせ応答契約を区別。実際の発見率や修正速度、契約全般は未評価 |

依頼361はサポート中の新しい環境でも古い閲覧道具が動かないという架空の条件を設定し、別の場所への控えと検査用の復元、対応済みの道具と利用者の希望する任意の送信設定を確認する。送信の停止はすべての通信やリスクの消失を意味しない。[英国 NCSC のサポート終了製品に関するガイダンス](https://www.ncsc.gov.uk/collection/device-security-guidance/managing-deployed-devices/obsolete-products) は、更新が提供されなくなることのリスクと、旧製品を使い続ける場合に無リスクの方法はないことを説明している。

依頼846は、同じ欠陥の影響を受ける公開ソースのカーネルをホストとゲストが別々に持ち、各配布元から修正済みの更新が公開されている架空の例である。それぞれ知らせを確認し、控えでの試験後に各環境へ適用する。[Linux カーネルの報告手順](https://www.kernel.org/doc/html/latest/process/security-bugs.html)は影響を受ける版、再現と修正の検証などを求める。公開されているだけで安全性や対応速度が保証されるわけではない。実際の報告やカーネルの調査・修正、再起動、互換性、未公開の問題の公開判断は扱わない。

依頼857の年代は [GNU の歴史](https://www.gnu.org/gnu/gnu-history.html)、[Linux 0.01 の記録](https://www.kernel.org/pub/linux/kernel/Historic/old-versions/RELNOTES-0.01)、[0.12 の記録](https://www.kernel.org/pub/linux/kernel/Historic/old-versions/RELNOTES-0.12)を参照する。1991年の 0.01 はソースを含む一方で有償再配布を禁じ、1992年にその禁止を外して GNU の条件へ移行した。後半の無償更新、有償支援、専用版と各利用者の条件は架空で、問い合わせ応答の期限と修正の完成期限を区別する。[OSI の定義](https://opensource.org/osd)はソースへのアクセスだけでなく再配布や派生物についての条件を含み、有償販売を排除しない。実製品の契約や法的判断、公開・非公開による一般的な安全性や対応時間は評価しない。
