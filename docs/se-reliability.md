# SE-Reliability: ソフトウェアの信頼性

出典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.250–251。依頼238は固定された２系統と５場面の模型であり、一般の信頼性設計、実測や自由記述を評価しません。

| トピック | 区分 | 対応と不足 |
|---|---|---|
| 1 故障確率・平均故障間隔と欠陥 | KA Core | 依頼108で稼働記録の固定例。確率モデルや故障間隔の分析は未対応 |
| 2 システムごとの信頼性要件 | KA Core | 未対応 |
| 3 欠陥の発生を減らし、試験やレビューで除去 | KA Core | 依頼23で有限の試験選択。ライフサイクル全般は未対応 |
| 4 ソフトウェアとシステムの信頼性・故障時の振る舞い | KA Core | 依頼238で複数設備の故障と受付への影響の固定例。一般の比較は未対応 |
| 5 欠陥の混入と除去のサイクル | KA Core | 未対応 |

| 例示学習成果 | 区分 | 対応と不足 |
|---|---|---|
| 1–3 信頼性要件の決定、高信頼性の難しさ、開発段階ごとの欠陥抑制 | KA Core | 依頼23は固定の試験選択のみ。他は未対応 |
| 4–5 複数の方法による信頼性推定と要件を達成する構成 | Non-core | 依頼238で定性的な固定の障害条件を満たす構成を選択。信頼性の数値推定は未対応 |
| 6–7 冗長化による障害許容と単一障害点の特定 | Non-core | 依頼238で共通配電盤の故障と別経路、両方を止める洪水を比較。一般の設計分析は未評価 |

依頼238では倉庫Ａ・Ｂのどちらかが動けば受付可能。共通配電盤が故障すると両方が止まる一方、別経路にはその共通盤がない。どちらの構成も、双方を止める洪水には耐えない。個々の故障確率、故障の独立性、実際の設備のリスクは所与でも算出済みでもない。
