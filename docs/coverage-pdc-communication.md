台帳は既存の例と不足を記録するもので、原典全体の網羅・教材の正確性・大学水準の深さを証明しない。各模型の前提と個別検証は[通信分野の記録](pdc-communication.md)を参照。

依頼993は [MIT の待ち行列の資料](https://web.mit.edu/dimitrib/www/Queueing_Data_Nets.pdf) を参照し、ポアソン到着・独立な指数処理時間・先着順・１受付・無限バッファを仮定する M/M/1 を扱う。処理率４、到着率１〜５を比較し、定常条件、処理中を含む系内平均、待ち行列だけの平均と Little の法則を区別する。有限時間の実測、有限バッファ、一般の到着・処理分布や複数受付には一般化しない。`tests/queue-model.test.js` は３つの定常値、２つの非定常条件、正答・保存・達成を検査する。

依頼994は固定の４通の到着と処理を６区間進め、各区間の系内通数の合計９通・刻を、完了済みの滞在時間７刻と観測終了時の未完了の経過時間２刻に分ける。有限区間で完了分だけを用いる場合の境界を示す例であり、定常状態の証明、M/M/1 の乱数実験や実環境の観測ではない。`tests/queue-observation.test.js` で６区間の通数、到着・完了・未完了、時間の保存関係と途中記録・達成を検査する。

依頼995では到着率３・サービス率４の１受付について、異なる二つの固定された種と観測時間10・1000の４条件を比較する。到着間隔と処理時間は別の xorshift32 疑似乱数列から逆変換で指数分布の標本を生成し、空の系から事象を追跡する。[Utah のシミュレーション講義](https://www.math.utah.edu/~ethier/5040-sim-lectures1-5.pdf) と [MIT の待ち行列資料](https://web.mit.edu/dimitrib/www/Queueing_Data_Nets.pdf) を参照。表示の丸め、初期過渡、未完了を明示し、有限の４観測を実機測定や精度保証と扱わない。`tests/queue-simulation.test.js` は固定履歴との照合、種の再現・履歴の先頭、到着の保存、観測面積と完了・未完了時間の一致、保存と達成を検査する。

依頼996は受信処理中の１通と受信待ち０・１通を区別し、固定された５通の発生と各刻の受付を追う。満員時には送信側の無制限の保留で先頭を再試行するか、受付に失敗した手紙を破棄するかを比較する。破棄はこの模型で選んだ判断であり、API の失敗が常に自動破棄を意味するわけではない。[Java BlockingQueue の仕様](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/util/concurrent/BlockingQueue.html) は待機する put と失敗を返す offer の違いを示す。実 API、ネットワーク障害、送信側の保留容量や一般の流量制御は評価しない。`tests/channel-pressure.test.js` で４条件の各刻に発生済み手紙が重複なく保存・処理・破棄されること、履歴、途中記録と達成を検査する。

依頼997では２通信路の読み取り可能通知、通知後に別の読み手が先に取った場合の非ブロッキング読取りと再試行、非同期操作の保留・別作業・完了通知を固定した３場面で比較する。[Linux select の説明](https://man7.org/linux/man-pages/man2/select.2.html) と [Microsoft の I/O Completion Ports](https://learn.microsoft.com/en-us/windows/win32/fileio/i-o-completion-ports) を参照。操作順と所要刻は模型の条件であり、実際の API に先行確認を必須とする主張ではない。即時完了、EOF、取消し、エラー、実 API・一般のスケジューリングは評価しない。`tests/io-notifications.test.js` は両読取り順、競合・再試行、完了前の取得拒否、履歴復元と達成を検査する。

依頼998は非公開の記録を送る固定用途で、受動的盗聴、鍵差替えを伴う改変、王城のなりすまし、役割のない者の閲覧を別々に比較する。暗号化・改変検出が理想どおり動き、身元確認では正しい鍵が事前に安全に登録されると仮定する。鍵の管理、実装、端末侵害や通信量の漏えいを評価せず、すべての攻撃に対する安全性を証明しない。[NIST の認証](https://csrc.nist.gov/glossary/term/authentication) と [認可](https://csrc.nist.gov/glossary/term/authorization) を参照。`tests/message-protection.test.js` で４つの守りの全16組合せと４場面、保存と達成を検査する。
