# DM-Modeling の対応状況

原典: [CS2023 DM-Modeling](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.116–117。自由記述や SQL の実装はゲーム内操作で直接評価しない。

| 番号 | 区分 | 内容と現状 |
|---|---|---|
| 1 | CS Core | データモデリング。依頼101で参加関係の保存方法を３通り比較し、依頼102で列の一意性を設定。一般の要件分析や設計は未対応 |
| 2 | CS Core | 関係データモデル。依頼13・67・101で行、結合、分解、キーと参照の固定例。体系的な関係代数は未対応 |
| 3 | KA Core | ER などの概念モデル。依頼101で冒険者・依頼・参加と関係の属性、上限と参加の任意性を選ぶ固定例。一般の ER 図の構築は未対応 |
| 4 | KA Core | 半構造化モデルとスキーマ。依頼189で項目名付きの札を表や日誌と比較し、必須・型・最小値に相当する条件を選び検査。実際の DTD・XML・JSON Schema の記述は未評価 |
| 5 | Non-core | スプレッドシートモデル。依頼1228で固定の乗算式の相対・絶対参照とコピーを操作。一般の関数や実ソフトは未対応 |
| 6 | Non-core | オブジェクト指向モデル・GraphQL。未対応 |
| 7 | Non-core | SQL の新機能。未対応 |
| 8 | Non-core | 時系列・実体化ビューは依頼1074、グラフの２辺の走査は192、地理空間は1170の固定例。一般のデータモデルや処理は未対応 |

| 例示学習成果 | 区分 | 内容と現状 |
|---|---|---|
| 1 | CS Core | 関係モデルの要素の説明。依頼13・67・101で表・行・参照の固定例。自由な説明は未対応 |
| 2 | CS Core | １対１・１対多・多対多の関係のモデル化。依頼101で多対多を比較し、依頼102で１対多と１対１の高々の制約を設定。一般のモデル構築と全員の参加を保証する制約は未対応 |
| 3 | KA Core | ER などの概念モデルの要素の説明。依頼101は固定した実体・関係・属性の選択例。ER 記法と自由な説明は未対応 |
| 4 | KA Core | 現実の環境の概念モデル化。依頼101は既に与えられた架空の要件から要素と参加条件を選ぶ固定例。一般の構築は未対応 |
| 5 | KA Core | 文書型・キー値型のデータモデル化。依頼189で既定の記録を両方式で検索・更新。要件からのモデル設計は未評価 |

依頼101は冒険者アオ・ミナ、依頼「森」「塔」を使い、アオ・森、アオ・塔、ミナ・森の３参加を求める。冒険者をキーにすると２件目が、依頼をキーにすると３件目が制約に抵触する。両列の組をキーにする参加表なら３件を保存でき、同じ組の重複と存在しない依頼「海」への参照は拒否する。３方式の５件について外部キー制約を有効にした SQLite の独立した一時データベースでも受理・拒否を照合した。名前は簡略化した識別子であり、実運用では安定した識別子等の設計が必要。

依頼102では１対多の所属と１対１の貸出について、２列の一意性を操作する。各例は登録がない人や相手を許すため「高々」の制約であり、全員が必ず登録されることは保証しない。全４設定と３例を、SQLite の一時表で一意制約を有効・無効にして照合した。外部キー、空値、完全参加制約や一般の ER 図はこの依頼では扱わない。
