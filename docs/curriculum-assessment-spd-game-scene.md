# SPD-Game の場面・試作教材の個別評価

[原典の範囲照合](curriculum-audit-spd-game.md)を踏まえ、2026-11-05 に [SPD-Game 台帳](coverage-spd-game.md) の 4a・4b を依頼799の画面、実装、テストと照合した。両項目とも **部分** とする。

- **4a ゲームエンジン**：共有画像の色、精霊の移動量と壁の設定を操作し、精霊と像の位置を比較する固定模型がある。エンジンの場面や対象を理解する入口になるが、実エンジンの構造や実行を再現せず、実際のエンジンの選択、操作、開発能力は検証しない。Godot の参考リンクはあるが、それだけで複数エンジンを扱ったことにはならない。
- **4b 発想・試作・反復・ビルド・試験・性能・移植・国際化・通信**：壁の衝突設定を切り替え、１回・２回更新の結果を予想して比較し、同じ試験を再実行できる。４条件の順序は自由で、変更後に再試験したことを強制するものではない。実ゲームのプレイテスト、性能測定、最適化、移植、国際化や通信などは評価しない。

模型では１更新２歩、位置２の壁とする。衝突無効の１回後は位置２、２回後は位置４であり、有効ではともに位置２になる。これらの値と、予想・履歴の復元を `tests/game-scene-testing.test.js` で検査した。色・歩数・衝突と更新回数の組合せ、既存記録の復元を `tests/game-scene-workshop.test.js` で検査した。画面、途中保存、元の依頼の達成時の保持は `src/app.js` と `src/game-loop-time.js` を確認し、公開版とローカル版での操作結果は [進捗記録](progress.md) に記録している。

両活動は元の依頼の達成条件には含まれず、クリアしたことがこれらの活動を完了した証拠にはならない。上記テストは固定例に限られ、エンジンやゲーム開発一般の正確性を保証しない。
