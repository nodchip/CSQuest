# PDC-Evaluation の対応状況

出典: [CS2023, PDC-Evaluation](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 224–225。原典を要約した作業用一覧。依頼66の固定モデルは実測や並列プログラムの作成ではない。

## トピック

| 番号 | 分類 | 要約 | 現状 |
|---:|---|---|---|
| 1 | CS Core | 時相論理による安全性・活性の要求 | 未着手 |
| 2 | CS Core | 順序、原子性、終了に関する誤りの検出と修正 | 依頼15・16・30で更新喪失、排他、循環待ちの固定例。一般の修正は未対応 |
| 3 | CS Core | スループット、応答、遅延、資源などの指標 | 依頼66で固定量の完了時間を比較。他の指標は未対応 |
| 4 | CS Core | 粒度、オーバーヘッド、通信など設計選択の性能への影響 | 分担費用を０とした例のみ。実際の費用の評価は未対応 |
| 5 | CS Core | アムダールの法則等による拡張性の限界 | 依頼66で分担できない準備が短縮を制限する例 |
| 6 | KA Core | 線形化可能性、仕様、形式手法、試験、計測等 | 未着手 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 本質的な性質を保って並列・分散化できるよう仕様を修正 | 未着手 |
| 2 | CS Core | 並行性における安全性と活性を説明 | 未着手 |
| 3 | CS Core | 各並列段階で成立する不変条件を指定 | 未着手 |
| 4 | CS Core | データ競合を検出する試験プログラムを書く | 更新喪失のゲーム操作のみ。プログラム作成は未対応 |
| 5 | CS Core | 並列化の性能・エネルギーへの影響を説明 | 固定量と理想的な分担の完了時間のみ。実測、エネルギー、自由な説明は未対応 |
| 6 | CS Core | 問題規模固定・変化の場合の拡張と効率を比較 | 固定量で２つの準備時間を比較。規模の変化や効率の一般的な分析は未対応 |
| 7 | KA Core | 多数の要求時のサービスを指定・計測 | 未着手 |
| 8 | KA Core | 逐次的なボトルネックを特定・修正 | 準備の限界を例示。修正は未対応 |
| 9 | KA Core | 実装のスループットを実測比較 | 未着手 |
| 10–11 | KA Core | 通信またはデータの遅延による性能問題を特定・修正 | 未着手。原典では10と11が同文 |
| 12 | KA Core | 資源管理のオーバーヘッドを特定・修正 | 未着手 |
| 13 | KA Core | 信頼性・可用性の問題を特定・修正 | 未着手 |

固定量８単位を１・２・４・８人に均等に分け、準備４または８時間を加算する。通信、同期、待ち、競合、エネルギーや問題規模の変化は再現しない。
