# DM-Distributed：分散データベースとクラウド

出典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p. 122。原典では全項目 Non-core。この知識単位に独立した例示学習成果は記載されていないため、トピック単位で追跡する。固定模型の達成は実装能力を直接評価しない。

| 番号 | 内容 | 対応状況 |
|---|---|---|
| 1a | 分散 DBMS のデータ保存 | 依頼190・191で複製と分割の固定模型。実際の保存方式は未対応 |
| 1b | 分散問い合わせ処理 | 依頼294で全行転送と半結合による絞込みの固定例。一般の問い合わせ最適化や実装は未対応 |
| 1c | 分散トランザクションモデル | 依頼293で２参加者の準備・決定・通知、拒否と調整役停止の固定模型。一般の故障や実システムは未対応 |
| 1d | 同種・異種の解決策 | 未対応 |
| 1e | クライアント・サーバー型の分散 DB | 未対応 |
| 2a | 並列 DBMS の共有メモリ・共有ディスク・共有なしの構成 | 未対応 |
| 2b | 速度向上・規模拡大と MapReduce 等 | 依頼130で固定の分担と集約、285で４値の累積和。一般の分散 DB の評価は未対応 |
| 2c | 複製と弱い整合性モデル | 依頼190・193で更新の遅れと読み書きの重なりの固定模型。他の整合性モデルは未対応 |

依頼293は２参加者の準備結果を保存し、全員の準備成功なら確定、一人でも拒否なら取消を記録して通知する。両者の準備後、調整役が決定前に停止した場合、準備済みの係が待つ例を含む。復旧時に回答が得られるという模型の前提があり、一般の通信障害・故障や同時可視性を保証しない。参考：[CMU の分散トランザクション講義](https://15445.courses.cs.cmu.edu/spring2024/notes/23-distributedoltp.pdf)。

依頼294は２拠点の内部結合で、重複注文を保持しつつ全行転送と番号による絞込みを比較する。行と番号を同じ費用とする固定模型で、実際のバイト数、遅延、計算費用や他の計画は扱わない。参考：[分散問い合わせ処理における半結合](https://drum.lib.umd.edu/items/0a4f0aa9-9567-446e-8005-f6d81e5552c9)。
