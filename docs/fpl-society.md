# FPL-SEP: プログラミング言語と社会

出典：[CS2023 印字 p.147](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。すべて Non-core。依頼350は架空の三人の固定例であり、多様な人々や支援技術を網羅した評価ではない。

| トピック | 対応と不足 |
|---|---|
| 1 英語中心のプログラミング言語の影響 | 依頼350で英語を読めない利用者向けの翻訳を比較。実言語の文法、教育や開発環境の障壁は未対応 |
| 2 障害のある人の包摂と支援技術 | 依頼350で絵の操作への読み上げ用の名前を比較。実際の支援技術を用いた評価は未対応 |
| 3a 構文のアクセシビリティ | 依頼350で操作の名前の有無を比較。構文の複雑さや入力手段の体系的評価は未対応 |
| 3b 文化の違い | 依頼350で数字だけの日付の曖昧さと月の明示を比較。通貨や小数、その他の文化差は未対応 |
| 3c ニューロダイバーシティ | 依頼350の解説で異なる認知の特性への配慮に言及。個別の設計・評価は未対応 |
| 4 プログラミング用語の語源 | 未対応 |
| 5 複数言語のアプリと UTF | 依頼93で UTF-8 の固定例、350で翻訳の選択肢を扱う。複数言語の実装や Unicode 全般は未対応 |

| 例示学習成果 | 対応と不足 |
|---|---|
| 1 包摂的で不快感を与えないプログラミング言語を意識して設計 | 依頼350で三つの設定を比較し利用者参加を選ぶ固定例。実際の言語設計や用語の吟味は未評価 |

日付が数字だけの場合の曖昧さと、月の名前などによる明確化は [W3C の日付形式ガイド](https://www.w3.org/International/questions/qa-date-format.en)を参照。言語の選択や操作の名前は架空の利用者の要求として提示し、すべての人に同一の方法が適するとは主張しない。
