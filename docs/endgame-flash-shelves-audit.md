# 水晶棚とフラッシュの更新・回収：教材監査

[CS2023 OS-Devices 印字211–212頁](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=211) の記憶装置管理を扱う固定模型。旧 `src/flash-translation.js` の依頼750を再利用し、現行鍛冶街へ接続する。現行の記録復旧や空き領域割当てとは異なり、頁単位の更新とブロック単位の消去を扱う。

２ブロック各３頁。初め０番にＡ１版、１番にＢ１版が有効、その他は消去済みの空き。更新は空き２番にＡ２版を書き、対応を切替えてＡ１版を無効化。有効頁を残したままブロックを消去するとその記録を失うため、この模型はデータ保護のため消去を拒否する。回収例はＡを３番、Ｂを４番へ移し、有効頁が残らない第０ブロックを消去。応用では更新後にＡ２・Ｂ１を移し消去し、利用者の更新１回・退避の書込み２回・消去１回となる。各依頼は同じ初期状態から指定順に操作する。

書込みと対応切替えは一操作で成功する仮定であり、電源断時の原子性や復旧を保証しない。固定頁数・空き・移動順のみ、寿命・摩耗分散・実時間・書込み増幅の一般値・実 SSD の配置や障害は未評価。[OSTEP: Flash-based SSDs](https://pages.cs.wisc.edu/~remzi/OSTEP/file-ssd.pdf) と [FAST 2011 SSD 研究](https://www.usenix.org/legacy/events/fast11/tech/full_papers/Chen.pdf) を参照。

## 独立レビューと動作確認

実装担当と別の担当が論理物理対応、更新、退避と消去、保存・開放・焦点を確認。消去拒否はデータ保護のための模型上の規則だと明確化し再確認。ローカルで集いと４地域の達成状態を用意した記録から、幅 213・390・1200 px で誤操作、キーボード、途中保存・再開と達成を確認した。冒険開始からの通し到達は含まない。
