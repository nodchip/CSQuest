# AR-Assembly の対応状況

出典: [CS2023, AR-Assembly](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 103–104。原典を要約した作業用一覧。依頼73は記号を用いた架空機械であり、実機の命令セットやプログラムを書く能力を示さない。

| 3 | CS Core | SIMD・MIMD と分類 | 依頼162で同じ命令を共有する機械と別々の命令を選ぶ機械を比較。実機の分類や制約は未対応 |
| 4 | CS Core | 共有メモリ型マルチプロセッサ・マルチコア | 依頼104・505で共有の記録と手元の写し、567で二人の共有札と原子的取得の固定模型。実機のコア構成・メモリ順序は未対応 |
| 5 | KA Core | ISA、命令形式、アドレッシング、機械語・アセンブリ | LOAD・分岐・加算・書戻し・停止の架空例。実 ISA と言語での作成は未対応 |
| 6 | KA Core | サブルーチン呼出しと復帰 | 依頼560で入れ子の呼出しと戻り先の上書き・スタック保存を比較。実 ISA と呼出し規約の全体は未対応 |
| 7 | KA Core | I/O と割込み | 依頼105でポーリングと完了通知の固定例。割込み処理の機械レベルの詳細は未対応 |
| 8 | KA Core | ヒープ、静的領域、スタック、コード | 依頼388で呼出し中の手元とヒープの寿命を比較。静的領域・コードや実装配置は未対応 |

架空機関は番地６を読み、０なら番地４へ分岐し、そうでなければ番地７の２を足して番地６へ書く。命令取出し時に次の番地へ進める規則を採用し、入力０と３で状態を確認。記憶・命令・レジスタのビット表現、パイプライン、割込みは再現しない。

依頼560は架空機械の０→４→７の入れ子呼出しと７→８→５→１の復帰を比較する。単一の戻り先を保存せず上書きした場合は５→５を繰り返し、スタック方式は５、１を順に取り出して停止する。両方式の履歴と誤予測、保存再生を検査した。実際の ISA、レジスタ規約、例外や任意の再帰は対象外。参考：[Cornell、呼出し規約と戻り先の保存](https://www.cs.cornell.edu/courses/cs3410/2026sp/notes/asm-call.html)。

依頼642は温室の温度16・24°Cと基準20°Cで炉を制御する架空の組込み装置。センサー入力、手順を保持する不揮発の記憶、RAM、CPU の制御と演算、出力を順に操作し、点灯中の電源再投入で模型の RAM と出力を初期化して手順が残ることを確認する。実機の回路、電源や出力の初期状態、センサー故障、応答時間、安全性や自由な議論を評価しない。[Espressif: Product Overview](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32/product-overview.html)、[Arm: Cortex-M based SoC](https://developer.arm.com/cfs-file/__key/communityserver-blogs-components-weblogfiles/00-00-00-21-42/Designing-a-SoC-with-Arm-Cortex_2D00_M-_2800_2.0_2900_.pdf)。
