# 項目別評価：DM-Security トピック９

2026-11-05 に [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 p.121 と依頼524・1225を照合した。原典のトピックはデータ完全性に関する典型的な危険因子と予防策である。

依頼524は直接届いた負数や過剰な数量を倉庫側で検証しないと、在庫が不正になる固定例を扱う。検証を追加すると、この４条件で不正な数量を拒否できる。依頼1225は、２人が同じ初期在庫を読んで書き戻すと更新が失われる例と、直列と同じ結果にする順序を比較する。部分的な処理、負の在庫、確定後の停止も固定の対策と比較する。[NIST の完全性の定義](https://csrc.nist.gov/glossary/term/integrity)と [MITRE の入力検証](https://cwe.mitre.org/data/definitions/20.html)を参照した。

関連４テストが成功。390px 幅の公開版524で、直接要求に対する誤予測・修正、再読込後の再選択と復元、倉庫側検証での拒否を確認した。1225の全８条件と達成については [既存の評価](curriculum-assessment-dm-data-core.md) に操作確認の記録がある。

これらは固定例による部分対応である。一般的な危険因子や予防策、認証・認可、実データベースの制約・同時実行、実システムの完全性は評価していない。
