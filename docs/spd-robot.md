# SPD-Robot の対応状況

出典: [CS2023 SPD-Robot](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 304–305。原典を要約した作業用一覧。すべて KA Core。固定シミュレーションの達成は、実機の開発や安全性を示さない。

## トピック

| 番号 | 要約 | 状況 |
|---:|---|---|
| 1 | ロボットの種類と機器 | 依頼691で車輪型・飛行型と２種類の観測器を架空の３通路で比較。実機の種類や仕様全般は未対応 |
| 2 | センサー、組込み計算、動作器 | 依頼28で前方観測と格子上の移動、690で観測係・移動係・動作指示、691で観測器と移動方法を選ぶ固定模型。実機や一般の観測処理は未対応 |
| 3 | ロボット用言語とライブラリ | 依頼690で Python と rclpy、C++ と rclcpp の組を選ぶ。実際の利用や一般の言語・ライブラリは未対応 |
| 4 | ROS 等のソフトウェア構成 | 依頼690でトピックの送信・購読と、３目的に応じたトピック・サービス・アクションの選択。ROS の実行や QoS の全設定は未対応 |
| 5 | プラットフォームの制約と設計 | 依頼28の移動・操作回数、71の力と充電、691の機体・観測器・地形と力の固定モデル。現実の制約や設計は未対応 |
| 6 | 物理・シミュレーションとの接続 | 依頼28・71の固定格子の簡略シミュレーションのみ。外部システムや実機との接続は未対応 |
| 7 | 順・逆運動学、動力学、経路計画、把持 | 依頼183・184の２関節の順・逆運動学、395の質量と制動距離、依頼28・71の経路、691の２接触での把持の固定模型。一般の運動学・動力学・経路計画や実際の把持は未対応 |
| 8 | 安全性と相互作用 | 依頼395で静止した人に対する停止距離とセンサー遮蔽時の固定比較。実環境や人との安全な相互作用は未対応 |

| 番号 | 要約 | 状況と限界 |
|---:|---|---|

| 2 | Arduino ロボットを組み立て、迷路を進むようプログラム | 未着手。実機や実言語は扱わない |
| 3 | ロボット用言語・技法と汎用開発を比較 | 未着手 |
| 4 | ロボットの設計と物理・模擬系の接続理由を説明 | 固定の格子シミュレーションの操作のみ。実際の接続と自由な説明は未対応 |
| 5 | ROS の構成要素と接続を設計 | 依頼690で観測係と移動係の話題・型を選ぶ固定模型。実際の ROS の構成・実装は未評価 |
| 6 | ロボットのプラットフォーム制約を議論 | 依頼28・71で移動・操作回数と充電の固定制限を体験。現実の制約と自由な議論は未対応 |

依頼28では４×３の固定格子上で、前方１マスを正確に観測し、90度回転または一歩移動する。移動は最大６回、操作は最大30回。観測誤差、連続空間、慣性、制動、人との接触や実機の安全はモデル化していない。

依頼71では５×３の既知の地図上で、通路への移動に力１、川への移動に力２を使い、各通路で一度だけ充電できる。独立した状態探索で、２通路とも充電なしでは到達できず、充電ありで到達できることを確認。電池の物理特性、観測誤差や移動の失敗は未対応。

依頼690は観測係の送信と移動係の購読を名前・型で照合し、固定容量１・２の受信待ちを比較する。２刻以上前の観測では進行指示を出さず、新しい近接観測では停止する独自のゲーム規則を用いる。受信待ちは古い順に読む理想化で、通信の遅延・損失、ROS 2 の QoS の相互互換性、実装差や実機の安全は扱わない。ゲームの鮮度判定は ROS の自動保証ではない。参考：[ROS 2 のトピック](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/About-Topics.rst)、[QoS の履歴と深さ](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/topics/About-Quality-of-Service-Settings.rst)。

依頼690の追加試験は、継続的な観測、素早い状態問い合わせ、途中報告と中止を要する長い移動に、それぞれトピック・サービス・アクションを選ぶ設計上の目安を扱う。Python の rclpy と C++ の rclcpp も選択する。これは [ROS 2 の通信方式の指針](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/Topics-Services-Actions.rst) と [クライアントライブラリの説明](https://github.com/ros2/ros_core_documentation/blob/master/source/developer_overview.rst) に基づく固定例であり、言語と通信方法が一対一に限定されること、実機の安全、ROS の実行や実装能力を意味しない。

依頼691は４歩の直線上で、車輪型・飛行型と光を使う観測器・距離を測る観測器を選び、暗い通路・切れた床・低い門を試す。暗所では光を使う観測器が不明を返し、車輪型は床切れ、飛行型は低い門を通れないという架空の規則。車輪型は１歩１、飛行型は１歩２の力を使い、初期の力は８。全12条件の到達・残量を検査した。機体・センサーの実際の仕様や外乱、安全性を評価しない。参考：[NASA JPL、複数センサーと地形に応じた移動](https://www-robotics.jpl.nasa.gov/what-we-do/research-tasks/multi-sensor-terrain-classification-and-terrain-adaptive-navigation-for-rovers-in-very-rough-terrain/)。

依頼183・184は平面の２関節で、前者は角度から先端を求め、後者は先端に合う角度を探す。184の長さ１・１の腕は (1,1) と (1,0) の各目標に２姿勢で届く。表示座標は小数第３位まで、判定には距離の許容誤差を用いる。角度選択肢と目標が限られ、一般の逆運動学の解法や実機は扱わない。参考：[Modern Robotics、逆運動学](https://modernrobotics.northwestern.edu/nu-gm-book-resource/inverse-kinematics-of-open-chains/)。

依頼395の追加模型では、速さ２または１、反応時間１、制動力２、質量２または１を仮定する。減速度は力÷質量、停止距離は反応中の距離に速さの２乗÷減速度の２倍を足す。速さ２では質量２の停止距離４、質量１は３。人までの距離３と一致する後者は余裕なしとし、手前で止まる場合と区別する。接触した場合の衝突後を計算せず、摩擦、滑り、人の動き、制動力の変動や関節の動力学は扱わない。参考：[Modern Robotics、質量と力](https://modernrobotics.northwestern.edu/nu-gm-book-resource/8-1-3-understanding-the-mass-matrix/)。

依頼691の把持模型は、両側に同じ法線力 N をかけ、各接触の静止摩擦上限を μN とする。重さ２に対し、係数1/4の荷物は片側 N=２で滑り、４で限界、６で余裕があり、破損限界６を超える８で壊れるという設定。係数1/2では４または６が余裕のある正答。摩擦力の上限は [Modern Robotics の摩擦モデル](https://modernrobotics.northwestern.edu/nu-gm-book-resource/12-2-1-friction/)を参照し、破損限界は架空の条件。形状、回転、動き、力のばらつきや実機の安全性は扱わない。
