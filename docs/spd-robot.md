# SPD-Robot の対応状況

出典: [CS2023 SPD-Robot](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 304–305。原典を要約した作業用一覧。すべて KA Core。固定シミュレーションの達成は、実機の開発や安全性を示さない。

## 例示学習成果

| 番号 | 要約 | 状況と限界 |
|---:|---|---|
| 1 | 所与のロボットプラットフォームでアプリを設計・実装 | 未着手。依頼28はゲーム内操作のみ |
| 2 | Arduino ロボットを組み立て、迷路を進むようプログラム | 未着手。実機や実言語は扱わない |
| 3 | ロボット用言語・技法と汎用開発を比較 | 未着手 |
| 4 | ロボットの設計と物理・模擬系の接続理由を説明 | 固定の格子シミュレーションの操作のみ。実際の接続と自由な説明は未対応 |
| 5 | ROS の構成要素と接続を設計 | 依頼690で観測係と移動係の話題・型を選ぶ固定模型。実際の ROS の構成・実装は未評価 |
| 6 | ロボットのプラットフォーム制約を議論 | 依頼28・71で移動・操作回数と充電の固定制限を体験。現実の制約と自由な議論は未対応 |

依頼28では４×３の固定格子上で、前方１マスを正確に観測し、90度回転または一歩移動する。移動は最大６回、操作は最大30回。観測誤差、連続空間、慣性、制動、人との接触や実機の安全はモデル化していない。

依頼71では５×３の既知の地図上で、通路への移動に力１、川への移動に力２を使い、各通路で一度だけ充電できる。独立した状態探索で、２通路とも充電なしでは到達できず、充電ありで到達できることを確認。電池の物理特性、観測誤差や移動の失敗は未対応。

依頼690は観測係の送信と移動係の購読を名前・型で照合し、固定容量１・２の受信待ちを比較する。２刻以上前の観測では進行指示を出さず、新しい近接観測では停止する独自のゲーム規則を用いる。受信待ちは古い順に読む理想化で、通信の遅延・損失、ROS 2 の QoS の相互互換性、実装差や実機の安全は扱わない。ゲームの鮮度判定は ROS の自動保証ではない。参考：[ROS 2 のトピック](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/About-Topics.rst)、[QoS の履歴と深さ](https://github.com/ros2/ros2_documentation/blob/rolling/source/ROS-Framework/interfaces/topics/About-Quality-of-Service-Settings.rst)。
