# AI-Search：見積もりを使う道探し（部分対応）

[CS2023 原典](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.68–69、AI-Search 2c・3d・3e の入口。現行の山では道の数と所要時間による探索を扱う。旧依頼42・43は一様費用・貪欲・A* と見積もりを既に扱うため、今回の固定例を新しい範囲として二重計上しない。

有向路 S→A＝１、S→B＝２、A→G＝２、B→G＝５。S 展開後から開始し、残りの見積もり h(A)=２、h(B)=０、h(G)=０。Ａ・Ｂ・Ｇの見積もりはこの例の真の残り費用２・５・０を超えず、Ａ→ＧとＢ→Ｇでは整合条件を満たす。Ｓの見積もりは扱わない。一様費用は g 最小で A・B・G、A* は g+h 最小で B・A・G と選び、ともに費用３。見積もりだけの貪欲は B・G で費用７を返す。A* は B 経由の G＝７を一度見つけた後、A 経由の G＝３へ改善する。ゴールを候補に入れた時点ではなく選んだ時点で終了する。

参考：[Berkeley CS188: A* Search](https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html)。固定４地点・正の費用・同点なしの例であり、一般のグラフ、過大評価や再展開、実装・一般の最適性証明・自由な説明は評価しない。

実装担当とは別の `review_candidate` が原典・A* 原論文、固定例の候補選択・経路費用、見積もりの前提、画面・誤答・保存・分類と開放を確認した。Ｓの見積もりが未定義のまま全体の整合性を述べていた監査の記述を指摘し、既定の辺に限定した修正後に再確認した。関連テストも成功した。一般の証明・実装を検証したものではなく、レビュー担当自身はブラウザを操作していない。

山の地域ナビ初期化を二重に呼んだため入口ボタンが重複し、最初のブラウザ確認は失敗した。呼出しを１回に修正後、入口の一意性、旧６依頼と新３依頼の分類、元ボタンの非表示を独立レビューした。`scripts/endgame-astar-guide.playwright.js` は集いと４地域等の達成を用意した記録から、213・390・1200 px 幅で入口・旧分類の一部、新３依頼の操作、キーボード、誤答案内、途中保存・再開、段階開放と達成後の再開を確認した。旧６件すべてのブラウザ操作、新規開始からこの依頼への通し操作、実際のスクリーンリーダー音声や利用者の評価は未確認。
