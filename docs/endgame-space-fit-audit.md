# 続き箱の確保：教材監査

- [CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字210〜211頁の OS-Memory トピック５（確保・解放・配置）と４（断片化）に関連する固定例。現行の駅ではページ置換を扱い、旧依頼387 `src/free-space.js` の連続領域確保を今回接続した。
- [OSTEP: Free-Space Management](https://pages.cs.wisc.edu/~remzi/OSFEP/vm-freespace.pdf) は先頭適合・最小適合と分割・隣接領域の結合を説明する。この模型では番号順に先頭を選び、最小適合で同じ長さなら番号の小さい方を選ぶ。
- 初期の空きは０〜２、４〜９、11〜14の３区間。４箱を先頭適合で４〜７に置くと空き合計９箱、最大連続４箱になり６箱の要求が失敗する。４箱を返すと４〜９がつながり６箱を確保できる。最小適合は４箱を11〜14へ置き、４〜９の６箱を確保できる。
- 箱は連続領域の簡略模型であり、一般の方式の優劣・実行時間・メタデータ・他の要求列・実 OS の割当器や実プログラム作成は評価しない。旧教材・本教材の存在を原典全体の完成とはしない。

2026-11-11、実装担当と別の `signed_review` が原典と [Operating Systems: Three Easy Pieces](https://pages.cs.wisc.edu/~remzi/OSFEP/vm-freespace.pdf) に照らし、確保・解放・空きの結合と固定値、画面・保存・開放を独立レビューした。空きなし時の開始番号と、候補がある時の「入る場所がない」の不正履歴を拒否する修正を再確認した。親担当が準備済み記録から幅 213・390・1200 px の駅の分類に到達し、誤答、キーボード、途中保存・再開、開放条件、達成後の保存をブラウザ確認した。新規開始からの通し操作、スクリーンリーダー音声、利用者による面白さは未確認。
