# SEC-Foundations：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.257–258。[既存の基礎](sec-foundations.md)、[安全性の分析・設計](sec-engineering.md)と依頼の実装・テストを照合。状態は[追跡方法](coverage-status.md)に従う。固定模型は実システムの安全性や実務能力を証明しない。

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | 攻撃可能性を評価 | 部分 | 328・329で固定された攻撃経路と修正前後を試す。一般の脅威分析や実システムは未評価。 |
| 2 | CS Core | 特定した脅威への保護を設計・開発 | 部分 | 328で提示された対策を選び、329で設定変更を操作。独自設計や実装は未評価。 |
| 3 | KA Core | プライバシー被害の回避を説明 | 部分 | 194〜196で収集・閲覧・集計推論の固定例を扱う。自由な説明や被害全般は未評価。 |
| 4 | KA Core | 安全性とプライバシー原則を組み込んだシステムを開発 | 部分 | 194〜196・328で提示済みの選択肢を操作。実システムの設計・開発は評価しない。 |
| 5 | KA Core | アクセス制御モデルの機能と性能を比較 | 部分 | 490で２方式の読取り方針を比較。実測性能や全モデルは未評価。 |

| 8 | KA Core | ソフトウェアに影響するハードウェアの脆弱性 | 部分 | 494で投機実行後の痕跡と測定の模型を比較。実機や自由な説明は未評価。 |

`tests/threat-planning.test.js`、`tests/threat-assumptions.test.js`、`tests/security-triad.test.js`、`tests/privacy.test.js` 等は各固定模型の一部を検査する。各前提と参考資料は[基礎](sec-foundations.md)・[安全性の分析](sec-engineering.md)を参照。未照合は未実装の証拠ではない。

依頼918は３観測器の固定報告に対し、A のみ・A と B の両方・３台中２台以上の判断を比較する。１台の誤警告や報告欠落を許容する例と、２台が同時に誤って危険な開門を許す例を扱う。報告元の確認と測定値の正しさを区別する。`tests/sensor-voting.test.js` は５場面・３方式の15条件、誤答と保存を検査。実機、観測器や判断器の独立性・故障率・安全性は未評価。参考：[NASA: Common Cause Failures](https://ntrs.nasa.gov/citations/20240013667)。

依頼917は水門への開門命令について、命令の認証・使用済み番号・観測された物理条件の確認を選び、偽造・再送・危険な状態と観測の食い違いを比較する。認証は番号を含む命令を保護するという仮定であり、観測器の正しさは保証しない。`tests/control-gate-security.test.js` は５場面と８設定の40条件、誤答と保存を検査。実機、鍵・センサー・通信断・期限や総合的な安全性は未評価。参考：[NIST: Guide to Operational Technology Security](https://csrc.nist.gov/pubs/sp/800/82/r3/final)。

依頼916は架空の本人３件と第三者１件について、普段の鍵のみ・公開情報による復旧・予備鍵と確認窓口の３方式を比較する。本人の受付は順に１・３・３件、第三者の受付は０・１・０件。窓口を利用でき、本人の追加証拠の検証に成功し第三者は失敗するという明示的な仮定の下での結果であり、実際の認証や不正防止を保証しない。`tests/recovery-usability.test.js` で12条件と集計、誤答時の進行、保存を検査。実利用者の参加、窓口の障壁、証拠検証の誤りや詐称は未評価。参考：[NIST: Customer Experience Considerations](https://pages.nist.gov/800-63-4/sp800-63b/customer/)。
