# SEC-Foundations：項目別の対応状況

原典：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp.257–258。[既存の基礎](sec-foundations.md)、[安全性の分析・設計](sec-engineering.md)と依頼の実装・テストを照合。状態は[追跡方法](coverage-status.md)に従う。固定模型は実システムの安全性や実務能力を証明しない。

## トピック

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | 機密性・完全性・可用性、リスク、システム・攻撃者・利用者の視点 | 部分 | 493で３性質、328で資産・攻撃経路・架空の影響点と対策を比較。リスクや各視点の体系的検討は未評価。 |
| 2 | CS Core | 認証・認可とアクセス制御 | 部分 | 11・490で本人確認結果と権限、329で設定修正前後を比較。実際の本人確認や権限設定は未評価。 |
| 3 | CS Core | 脆弱性・脅威・攻撃面・攻撃経路 | 部分 | 328で受付・通信・保管の３経路と、鍵や設定の前提が崩れる場合を操作し、329で公開設定と鍵の漏出を扱う。一般の脆弱性分析や多様な攻撃面は未評価。 |
| 4 | CS Core | DoS と DDoS | 部分 | 492で単一・複数・共有送信元と回数制限の固定例。実通信と一般の防御は未評価。 |
| 5 | CS Core | 最小権限・安全な既定値・多層防御など | 部分 | 11で役割と場所の許可、328で３経路の対策を比較。公開設計・ゼロトラスト等の原則全体と実装は未評価。 |
| 6 | CS Core | 安全性・プライバシー・性能などの兼ね合い | 部分 | 328で対策枠と架空の影響点を比較。実際の性能・プライバシー・費用を含む評価は未対応。 |
| 7 | CS Core | AI が防御・攻撃に与える影響 | 部分 | 495で学習札の細工と入力変更、496で多数決の固定例を操作。実際の攻防や AI を使った攻撃能力の一般評価は未対応。 |
| 8 | KA Core | 裁量・強制・役割・属性に基づくアクセス制御 | 部分 | 490で２方式による読取り方針の表現を比較。全モデルと実装は未評価。 |
| 9 | KA Core | セキュリティ制御 | 部分 | 328で受付・通信・写しへの対策を選択。各制御の一般的な分類と実装は未評価。 |
| 10 | KA Core | 信頼と信頼性 | 部分 | 328で各対策の前提を明示し、329で鍵漏出後の対応を比較。一般的な信頼・信頼性の評価は未対応。 |
| 11 | KA Core | Web・クラウド・モバイルへの応用 | 部分 | 329で公開された写しと鍵の漏出を試す。実サービスや各プラットフォーム全般は未評価。 |
| 12 | KA Core | 組込み・サイバーフィジカルシステムの保護 | 未照合 | 関連依頼と具体的な保護の対応は未確認。 |
| 13 | KA Core | 使いやすい安全性と人間中心設計 | 未照合 | 関連依頼と安全性の使いやすさの対応は未確認。 |
| 14 | KA Core | AI の安全性・信頼・検証・予期しない影響 | 部分 | 495で学習札の細工と入力変更を比較。独立検証、実システムや他の影響は未評価。 |
| 15 | KA Core | AI 構築・運用上のリスク | 部分 | 495で不正な学習札と運用時の入力変更を比較。偏り・知財など一般のリスクは未評価。 |

## 例示学習成果

| 番号 | 区分 | 要約 | 状態 | 対応例と限界 |
|---|---|---|---|---|
| 1 | CS Core | 攻撃可能性を評価 | 部分 | 328・329で固定された攻撃経路と修正前後を試す。一般の脅威分析や実システムは未評価。 |
| 2 | CS Core | 特定した脅威への保護を設計・開発 | 部分 | 328で提示された対策を選び、329で設定変更を操作。独自設計や実装は未評価。 |
| 3 | KA Core | プライバシー被害の回避を説明 | 部分 | 194〜196で収集・閲覧・集計推論の固定例を扱う。自由な説明や被害全般は未評価。 |
| 4 | KA Core | 安全性とプライバシー原則を組み込んだシステムを開発 | 部分 | 194〜196・328で提示済みの選択肢を操作。実システムの設計・開発は評価しない。 |
| 5 | KA Core | アクセス制御モデルの機能と性能を比較 | 部分 | 490で２方式の読取り方針を比較。実測性能や全モデルは未評価。 |
| 6 | KA Core | 機械学習を使った安全性低下の例 | 部分 | 495で分類に頼る見張りの見逃しを操作。実システムや一般の攻撃は未評価。 |
| 7 | KA Core | 機械学習を使った防御改善の例 | 部分 | 496で学習済みと仮定した見張りの多数決を比較。実データや実際の改善は未評価。 |
| 8 | KA Core | ソフトウェアに影響するハードウェアの脆弱性 | 部分 | 494で投機実行後の痕跡と測定の模型を比較。実機や自由な説明は未評価。 |

`tests/threat-planning.test.js`、`tests/threat-assumptions.test.js`、`tests/security-triad.test.js`、`tests/privacy.test.js` 等は各固定模型の一部を検査する。各前提と参考資料は[基礎](sec-foundations.md)・[安全性の分析](sec-engineering.md)を参照。未照合は未実装の証拠ではない。
