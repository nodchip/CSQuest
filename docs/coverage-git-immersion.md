## 例示学習成果

| 番号 | 要約 | 状態 | 代替と限界 |
|---|---|---|---|
| 1 | 立体画像を作成 | 部分 | 216 で点の左右投影を選ぶ。実画像の作成・表示は未評価。 |
| 2 | AR・VR アプリを設計・作成 | 未照合 | 218 の固定模型は実アプリの設計・作成を評価しない。 |
| 3 | 利用者追跡の各方式の長短 | 部分 | 1176で遮蔽物による可視性の違いを比較。一般の方式・精度や実機の長短は未評価。 |

| 5 | ネットワーク環境の同期・データ一貫性の設計課題を分析 | 部分 | 1178で順不同の状態配達と番号による巻戻り防止を比較。欠落、一般の競合処理や実通信は未評価。 |

216〜218 は少数の位置と距離を用いた模型であり、実際の両眼視・追跡装置・遮蔽や、快適性の測定ではない。各例の参考資料と前提は[既存の調査](git-immersion.md)を参照。

依頼1176は [Microsoft の追跡方式の説明](https://learn.microsoft.com/en-us/previous-versions/mixed-reality/enthusiast-guide/before-you-buy-faqs)を参考に、装着カメラから部屋の印と外部カメラから装着側の印の見通しを比較する。`tests/tracking-occlusion.test.js` は４条件の遮蔽、保存と達成を検査する。目印の可視性は実際の位置・姿勢の推定成功を意味せず、他のカメラ・慣性センサー・視野や照明を扱わない。

依頼1177は [Microsoft の固定視点の360度映像](https://learn.microsoft.com/en-us/windows/mixed-reality/design/coordinate-systems)を参考に、889の二つの旗を投影して幾何模型と固定視点パノラマを比較する。`tests/panorama-parallax.test.js` は再利用した座標、６条件と保存・達成を検査。回転や実映像は扱わず、複数画像・奥行きによる新視点生成を否定しない。1176の方式名はカメラの向きと混同しないようインサイドアウト・アウトサイドインと表記する。

依頼1178は [Snapshot Interpolation の状態番号と順不同の説明](https://gafferongames.com/post/snapshot_interpolation/)を参考に、固定順序で処理された二つの位置と、２台への状態通知を操作する。`tests/shared-vr-snapshots.test.js` は24種類の到着順序、仮表示、古い通知の無視、保存・達成を検査。単一の権威と完全状態を仮定し、欠落・再接続・競合解決・補間・実通信は扱わない。
