# OS-Memory：住所変換とアドレス空間の評価

評価日：2026-11-05。[CS2023 印字 pp.210–211](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) の KA Core トピック１と３を、依頼40・385の実装と照合した。[OSTEP のページング解説](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf)を、頁番号・オフセット、プロセスごとの対応の確認に用いた。

| 項目 | 判定 | 確認できる範囲と残り |
|---|---|---|
| １：物理メモリ、アドレス変換と管理ハードウェア | 部分 | 依頼40は４仮想頁・３物理枠の固定表で頁番号、オフセット、物理住所、不在と読取り専用の違いを扱う。不在頁への復帰は候補の枠を選ぶ模型で、取寄せ成功と書戻し不要を仮定する。MMU の実装、実機上の変換や管理ハードウェアの詳細は扱わない。 |
| ３：論理・物理アドレスとアドレス空間の仮想化 | 部分 | 依頼40の固定表に加え、依頼385では同じ仮想頁番号でも２プロセスが別枠または明示的な共有枠に対応する例を順番に操作する。一般的なアドレス空間や任意の対応表の構築、同時実行と共有の同期は扱わない。 |

`tests/address.test.js` と `tests/process-pages.test.js` の７テストは固定模型の変換、保護、不在頁の復帰、共有と途中記録を検査し、実 OS の振る舞いや学習者の一般的な理解を保証しない。公開版（コミット `f9bbed74`）を390px幅で操作し、依頼385の両場面の達成と依頼40で頁０の枠を選んだ復帰結果を確認した。２項目とも完了にはしていない。
