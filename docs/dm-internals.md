# DM-Internals の対応状況

出典: [CS2023 DM-Internals](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 119–120。原典を要約した作業用一覧。依頼35・38・39はトランザクションの原子性・永続性・分離の固定例であり、実際の DBMS の実装や運用を評価しない。

## トピック

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | DB のバッファ管理 | 依頼89で役割と、固定頁の退去拒否・変更頁の書戻しと入替えを操作。一般の置換方式や実 DBMS は未評価 |
| 2 | KA Core | トランザクション管理：分離水準、ACID、直列化可能性、分散トランザクション | 依頼35で原子性と永続性、依頼38で未確定値の読み取り、依頼39で競合直列化可能性の固定例。整合性、分離水準全般、その他の直列化可能性は未対応。依頼293に分散取引の固定例 |
| 3 | KA Core | 並行性制御：二相ロック、デッドロック対策、クォーラムによる整合性モデル | 依頼16・30は一般的な排他とデッドロックの固定例。依頼39で１取引の二相ロック、193でクォーラムの固定例。複数取引の二相ロックと一般の対策は未評価 |
| 4 | KA Core | 復旧マネージャーとバッファマネージャーの関係 | 依頼136で確定印と前後値による復旧の固定模型。実際のバッファ管理との関係は未対応 |
| 5 | Non-core | 楽観的並行性制御とタイムスタンプ方式 | 依頼451で版による条件付き更新と競合の固定例。一般の DBMS の楽観的並行性制御とタイムスタンプ順序方式は未対応 |
| 6 | Non-core | 先行ログと ARIES による復旧 | 依頼136で先行ログと未確定・確定済みの復旧の固定模型。ARIES や並行処理は未対応 |

## 例示学習成果

| 番号 | 分類 | 内容と現状 |
|---:|---|---|
| 1 | KA Core | DBMS によるバッファプール管理を説明 | 依頼89で役割と固定・書戻し・入替えを操作。一般の管理と自由な説明は未評価 |
| 2 | KA Core | 正しいトランザクション管理の四つの性質を説明 | 依頼35は原子性と永続性、依頼38は分離性の一例のみ。整合性、分離性全般、および自由記述による説明は未対応 |
| 3 | KA Core | 直列化可能性の原理を概説 | 依頼39で２作業の競合直列化可能性を比較。一般の判定と自由記述は未対応 |

依頼35では、A=10・B=2 から３枚を移す。中断後の保存済み台帳を予測してから結果を確かめる。別々に保存した更新の途中で中断すると A=7・B=2 が残る。まとめて確定するモデルでは、確定前の中断で A=10・B=2 に戻り、再試行して確定した後の中断では A=7・B=5 が残る。選択肢による固定例であり、実際の復旧機構や同時実行は扱わず、結果がこのように復旧することを仮定している。

依頼38は、確定値10の更新を未確定の7として保持中に、一方では7を読み、他方では以前に確定した10を読む固定モデル。いずれも更新は後で取り消される。未確定値を読める試行はダーティリードを示す。確定済みの値を読む方式では直前の確定値を返すと仮定し、待機する実装や反復不能読み取り、ファントム、直列化可能性は扱わない。

依頼39では、２人がそれぞれ読み取りと書き込みを行う全６順序を選び、同じ台帳と別々の台帳で競合の向きを比べる。競合する操作の順序を保つ直列順序があるかを考える例で、一般的なスケジュールや他の直列化可能性を網羅しない。

依頼136は A=10→7、B=2→5 の前後値がデータより先に永続化されると仮定する。未確定で A のみ反映された場合は前の値、確定済みで未反映または一部反映の場合は後の値を選ぶ。単一の送金・完全なログと書き込みの模型であり、特定の DBMS のアルゴリズムや ARIES を実装していない。[PostgreSQL の先行ログ](https://www.postgresql.org/docs/15/wal-intro.html)

項目別の再照合は [coverage-dm-internals.md](coverage-dm-internals.md) を参照。

依頼39の追加場面は１取引で鍵 X・Y の取得後、最初の解放からは新しい鍵を取得できないことを操作する。基本の二相ロックでは確定まで全ての鍵を保持するとは限らない。複数取引や障害復旧は扱わない。参考：[CMU の二相ロック講義](https://15445.courses.cs.cmu.edu/spring2024/notes/17-twophaselocking.pdf)。

依頼89の２枠の模型では、固定数１の頁を外せず、固定されていない変更済み頁を書き戻してから外し、新しい頁を読み込む。固定は他の利用者を排除するロックとは異なる。書込み失敗やログ、一般の置換方針は扱わない。参考：[CMU のバッファプール講義](https://15445.courses.cs.cmu.edu/spring2024/notes/06-bufferpool.pdf)。
