# SPD-Common: 専用プラットフォームの共通事項

出典：[CS2023 印字 pp.302–303](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf)。以下は CS Core。固定模型の操作は、実際のプラットフォームでプログラムを作成する能力を示さない。

| トピック | 対応と不足 |
|---|---|
| 1 概要 | 依頼1325で Web・モバイル・ゲーム・ロボット・組込み・対話型の例と視点の重なりを比較。実開発環境や全般の理解は未評価 |
| 1a 入力・センサー・操作・触覚装置 | 依頼219–222で光センサーの固定模型、351で画面上の入力。実機や触覚装置は未対応 |
| 1b 計算・保存・メモリ・通信の資源制約 | 依頼356で通信回数、架空の消費量と遅れの比較。計算・保存・メモリを含む体系的比較は未対応 |
| 1c 安全性・可用性・耐障害性などの要件 | 依頼353で復旧目標と訓練の固定例。専用プラットフォーム全般の要件は未対応 |
| 1d 出力・アクチュエーター・触覚装置 | 依頼219でセンサー値から角度指示を出す固定模型。実機と触覚装置は未対応 |
| 2 プラットフォーム固有 API と従来のアプリ構築 | 依頼354は通信と再送の固定模型。実 API を使ったプログラミングの比較は未対応 |
| 3 プラットフォーム向け言語の概要 | 1289で Web の HTML・CSS・JavaScript の役割を固定例で比較。他のプラットフォームは未評価 |
| 4 プラットフォームの制約・要件下でのプログラミング | 依頼356で架空の制約を満たす設定を選択。実際のプログラミングと安全性の検討は未対応 |
| 5 固有言語の学習・習熟の方法 | 未対応 |

| 例示学習成果 | 対応と不足 |
|---|---|
| 1 モバイルプログラミングの制約を列挙 | 依頼354・356で通信断と送信・待ち時間の固定例。他の制約の列挙は未対応 |
| 2 スクリプト言語の特徴を列挙 | 未対応 |
| 3 Web の３層モデルを説明 | 依頼803で画面・処理・データの役割と２つの固定申込みを操作。一般の構成や自由な説明は未評価 |
| 4 Web の状態維持を説明 | 依頼354で端末に残る送信待ちとサーバーの受理状態の固定例。一般の Web の状態維持は未対応 |

依頼356では各刻に１件、計８件を観測する。観測１件は力１、送信１回は力３と定め、１・２・４件ずつの送信を比較する。８件すべてを送るとそれぞれ送信８・４・２回、力32・20・14、最大待ち０・１・３刻。実端末の電力や遅延を表す値ではない。通信をまとめることと電力消費の関係は [Android Developers](https://developer.android.com/develop/connectivity/minimize-effect-regular-updates) を参考にした。

依頼803の３層と２分岐は固定模型であり、実サービスの構築や一般の説明能力を直接評価しない。[項目別台帳](coverage-spd-common.md)を参照。
