依頼793 は [W3C WAI の参加に関する案内](https://www.w3.org/WAI/planning/involving-users/)に基づく固定事例。利用者を早期から招き、同じ障害がある人でも経験は異なること、標準と利用者による評価を組み合わせることを扱う。実際の当事者参加、実機検証や規格適合を証明しない。

依頼793の試作品は、ポインターだけで動く応募操作と操作名の欠落を、それぞれ架空の鍵盤利用者・読み上げ利用者の観察で示す。修正後に両者を再評価する。[鍵盤操作](https://www.w3.org/WAI/WCAG22/Understanding/keyboard)と[名前・役割・値](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value)を参照。模型は実際の支援技術の挙動や WCAG 全体を再現せず、名前が適切であることと名前が存在することも同一ではない。旧版で既に記録されたクリアは維持するため、試作品の追加後に再挑戦していない過去のクリアは今回の新しい操作の達成を意味しない。

依頼1016で実 HTML の小さな受付板に対し、キーボード、操作名、状態通知の障壁を確認して修正する。詳細と支援技術・規格適合上の限界は [SEP-DEIA の対応表](coverage-sep-deia.md) を参照。

依頼1114は [内閣府の改正障害者差別解消法の説明](https://www.cao.go.jp/press/new_wave/20240520.html) と [合理的配慮の案内](https://www8.cao.go.jp/shougai/suishin/pdf/gouriteki_hairyo2/leaflet3.pdf) を参考に、2024年４月からの事業者の合理的配慮と、本人の意思・過重な負担・対話の考え方を紹介する。鍵盤操作と文字情報の希望は架空の２例で、代替手段を一律に否定せず本人の希望と照合する。個別の過重な負担や適法性、実際の当事者参加は評価しない。`tests/accessibility-dialogue.test.js` は２場面・選択肢・順序・復元を検査する。
