# FPL-Parallel: 並列・分散計算

参照：[CS2023](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) pp.135–136。以下の番号は原典のトピック番号です。依頼は固定された模型であり、実際の言語処理系やプログラムの正しさを保証しません。

| 区分・番号 | トピック | 対応と不足 |
| --- | --- | --- |
| CS 1 | 安全性・活性、競合、依存条件、故障モデル、停止 | 依頼15・30・90・131で更新の競合と待ちを体験。一般の安全性・活性証明、故障モデルは未対応 |
| CS 2 | アクター、手続き・リアクティブ、同期・非同期、データ並列のモデル | 依頼92・129・130でイベント、通信路、分割集約の固定例。各モデルの一般的な比較やアクターは未対応 |
| CS 3 | 可換性・独立性、原子性、一致 | 依頼156で操作順と可換性、16・90で排他と待ち合わせの例。一般の独立性や分散合意は未対応 |
| CS 4 | async/await、promise、スレッドの実行制御 | 依頼157で未確定・成功・失敗の結果と待機中の別作業を操作。実言語の例外伝播、実行順序、スレッド制御は未対応 |
| CS 5 | mutex、メッセージ、共有メモリ、cobegin/coend、モニタ、チャネル、スレッド、ガード | 依頼15・16・90・129・131で共有値、排他、待ち合わせと通信路の固定例。その他の構文や一般的な実装は未対応 |
| KA 6 | future | 依頼157で将来の結果を待つ固定例。言語ごとの API と詳細な意味論は未対応 |
| KA 7 | forall、ループ展開、map/reduce など言語によるデータ並列 | 依頼130で分割と集約の固定例。実言語の機能やループ展開は未対応 |
| KA 8 | メモリ整合性モデルと言語意味論・コード生成 | 依頼104は写しの無効化の模型。言語のメモリモデルとコード生成は未対応 |
| KA 9 | REST API | 依頼62で Web API の再送を体験。REST によるアプリケーション統合の一般的な扱いは未対応 |
| KA 10 | クラウド、HPC、量子、ユビキタス計算 | 個別の関連例はあるが、これらの技術と並行・分散の関連は未対応 |
| KA 11 | メッセージ通信のオーバーヘッド | 未対応 |
| KA 12 | 並行性を効率よく使う粒度 | 依頼130は２人への分割例、163は専用機械の固定費用と仕事量の比較。粒度と並行性能の一般的比較は未対応 |
| KA 13 | 他のパラダイムとの並行性 | 未対応 |

| 区分・成果 | 例示学習成果の要旨 | 対応と不足 |
| --- | --- | --- |
| CS 1 | データ競合時の逐次一貫性と言語上の対策を説明 | 依頼15は更新喪失の模型。実言語のメモリモデルや説明能力の評価は未対応 |
| CS 2 | 複数のモデルで正しい並行プログラムを実装 | 依頼15・16・129・130・157の操作は代替体験。実言語での実装能力は評価しない |
| CS 3 | メッセージ交換モデルで通信プロトコルを分析 | 依頼10・129・131で固定の再送・通信路・待ちを分析。一般のプロトコル分析は未対応 |
| CS 4 | モニタ等の同期を使う | 依頼16・90で排他と待ち合わせを体験。モニタの実装は未対応 |
| CS 5 | 変数の読み書きによるデータ依存のモデル化 | 依頼15・90・156で限定した読み書きや順序を操作。一般の依存分析は未対応 |
| CS 6 | 選択・繰り返しによる制御依存のモデル化 | 依頼２・３で分岐と繰り返しを操作。一般の制御依存分析は未対応 |
| KA 7 | REST API によるアプリケーション統合と自動化を説明 | 依頼62で再送の一例。一般的な統合や説明能力は未対応 |
| KA 8 | 並列・分散計算の利点、制約、課題を説明 | 個々の固定例はあるが、一般的な比較と説明能力の評価は未対応 |

依頼157の promise と await の対応は [ECMAScript 言語仕様](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise-objects)を参照しています。模型は成功・失敗後の仕事の再開を簡略化し、実際のジョブの順序は表現していません。
