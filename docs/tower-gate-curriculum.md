# 空の中継塔と霧の関所：教材の範囲と出典

## 出典

- [CS2023 最終報告書：Networking and Communication と Security](https://csed.acm.org/wp-content/uploads/2025/11/CS2023-Report.htm)。NC の転送・アドレス指定、NC-Reliability の順序・重複・再送、SEC-Foundations の認証・認可・最小権限・完全性に照らした。
- [NIST SP 800-63B-4: Authentication and Authenticator Management](https://pages.nist.gov/800-63-4/sp800-63b.html)。認証が提示された識別情報への信頼を確立する機能であること、利用者が安全な確認手段を使える必要性を確認した。
- [NIST SP 1800-26: Data Integrity](https://www.nccoe.nist.gov/publication/1800-26/VolA/1800-26A.html)。完全性が許可されない変更の防止・検知に関わることを確認した。

## 依頼別の範囲と限界

| 依頼 | 遊びで触れること | 扱わない・評価しないこと |
|---|---|---|
| 行き先で中継する | 二つの行き先と固定表による次の中継先の選択。NC の転送の入口。 | 実アドレス・最長一致・経路探索・動的更新・実通信。 |
| 知らせの欠片をつなぐ | 三つの欠片の到着順と番号順の違い。NC-Reliability の順序の入口。 | 実パケットの構造・損失・重複・ウィンドウ・汎用再組立て。 |
| 返事を待ち、送り直す | 最初の返事が失われる固定例で、待機・タイムアウト・再送・番号による重複抑止。NC-Reliability の一例。 | 実タイマー、複数の同時送信、任意の損失や順序、TCP 全体。 |
| 送り主を確かめる | 届いた知らせが示す連絡先と、以前から信頼する名簿の連絡先を区別して確認する固定例。SEC-Foundations の認証・信頼の入口。 | 名簿の真正性の確立、実際の認証プロトコル、多要素認証やすべてのなりすまし対策。 |
| 帳面の権限を整える | 三人の役割に対し、閲覧・編集・権限なしを必要に応じて選ぶ。SEC-Foundations の認可と最小権限の入口。 | 実システムの ACL、認証、管理者権限、権限委譲や監査。 |
| 記録の違いを調べる | 信頼できる控えと届いた三つの項目を比較して変更を発見・修正する。SEC-Foundations の完全性の入口。 | 控えの真正性の証明、暗号学的ハッシュや署名、一般の改ざん検知・発信者の証明。 |

いずれも小さな固定例の操作であり、当該分野の大学水準の習熟、全学習成果の達成、実ネットワークや実セキュリティ機構の検証を意味しない。送り主の確認には、名簿と連絡経路が信頼できるという前提がある。控えとの比較にも、控えが守られているという前提がある。
