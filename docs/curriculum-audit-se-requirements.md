# 分母照合：SE-Requirements

[CS2023 印字 pp.242–243](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf#page=242) と[候補台帳](coverage-se-requirements.md)を 2026-11-10 に照合した。範囲照合は教材の完成・正確性・操作・保存や独立レビューの証明ではない。

KA Core のトピック 1a〜1c は機能要件の記述・構造化、設計・実装の支援、方法の長所・短所。親 1 のユースケースや利用者物語などによる機能要件の記述という文脈を保持する。2 は要件の整合性・妥当性・完全性・実現可能性、3a・3b は要件源と収集方法、4〜6 は非機能要件、倫理を含むリスク、要件仕様の伝達・形式化。Non-core 7・8 は収集・確認のための試作と要件変更の影響、9a〜9c は見積り方法、実績比較、見積りの困難さと経験。親 1・3・9 は子の範囲と文脈を保持して追跡し、親子を重複計上しない。トピック 14 行。

KA Core 成果 1〜6 は収集方法の比較、機能要件を記述する方法の違い、必要・許可・禁止の判別、要件収集、新要件による変更箇所、機能と非機能の識別。Non-core 7〜10 は試作、工数見積りと実績比較、依存・リスクを考えた作業順、単純なシステムの要件仕様の記述。成果 10 行をトピックと別に追跡する。

旧台帳の番号付き依頼は現行冒険への到達を示さない。現行冒険には案内所の聞取り・利用者物語・合意を扱う部分評価があるが、実関係者との合意、自由な仕様記述や一般の要件分析の達成を意味しない。現行の到達・正確性・操作・保存・独立レビューと残る範囲は各行で別途確認する。

2026-11-10、照合担当とは別の `review_candidate` が原典の番号・区分・親子関係と候補台帳を確認した。これは原典範囲のレビューであり、教材の正確性、現行の冒険からの到達やブラウザ操作を確認したものではない。整合性検査の範囲ハッシュは候補 ID と台帳要約を対象とし、監査文書や学習内容の正しさを保証しない。
