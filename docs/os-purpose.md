# OS-Purpose の対応状況

出典: [CS2023, Operating Systems, OS-Purpose](https://ieeecs-media.computer.org/media/education/reports/CS2023.pdf) 印字 pp. 206–207。以下は原典の要約であり、関連する依頼がある場合も、単位全体の習得を示すものではない。

## トピック

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 汎用ハードウェアと用途別ソフトウェアを仲介する OS | 依頼54でアプリから保護された装置への要求を操作する固定模型。一般的なハードウェアとアプリケーションの関係は未対応 |
| 2 | CS Core | プロセス・利用者・装置との窓口やデータの永続化などの共通機能 | 依頼53で仕事の状態、105で装置完了の通知、77でファイル名と開いた参照を扱う固定例。利用者との窓口や永続化の仕組みを含む全体像は未対応 |
| 3 | CS Core | 組込み、各種サーバ、起動と起動時の安全性などの拡張・専門機能 | 依頼133で仕事の期限を扱う固定例。各用途の OS の機能や起動の仕組みは未対応 |
| 4 | CS Core | 効率・堅牢性・柔軟性・移植性・安全性などの設計上のトレードオフ | 依頼105でポーリングと通知、176で急ぎの仕事の完了と切り替え費用を比較する固定模型。OS の設計要因の体系的な比較は未対応 |
| 5 | CS Core | セキュリティ、ネットワーク、マルチメディア、並列・分散処理から受ける影響 | 関連する個別の依頼はあるが、それらが OS の設計へ与える影響は未対応 |
| 6 | CS Core | あらゆる層での保護の必要性と、OS の保護を迂回する攻撃経路 | 依頼54で装置への直接操作を防ぐ模型。媒体の持出し、起動・ファームウェア、API 境界、仮想化、ハードウェア脆弱性と対策の費用は未対応 |
| 7 | CS Core | シェルとシステムプログラミングを通じた OS 機能の利用 | 依頼151〜153で処理の受渡し、終了状態、環境変数の固定模型。実際のシェルや OS の API を使う練習は未対応 |

## 学習成果

| 番号 | 分類 | 要約 | 現状と限界 |
|---:|---|---|---|
| 1 | CS Core | 現代の OS の目的と機能を理解する | 個別の機能の固定例はあるが、目的と機能を関連付けて評価する体験は未対応 |
| 2 | CS Core | リアルタイム、モバイル、サーバなどの用途で設計上の問題を評価する | 依頼133は期限、176は仕事の完了時刻と切り替え費用を比較する固定例。実際の用途間の OS 設計の比較は未対応 |
| 3 | CS Core | 利便性、効率、進化可能性に関わる OS の機能を理解する | 依頼105で待機方法、176で仕事の切り替え費用と完了時刻の固定例を比較。３つの観点と現代 OS の機能の関係は未対応 |
| 4 | CS Core | OS の進化と安定性の利点と緊張関係を理解する | 未着手 |

これらの模型は実際の OS の設計、実装、運用や自由記述による説明を評価しない。各番号は原典の項目に対応し、下位の例もまとめて残課題を記した。
